Static documentation site split into two parallel trees mirroring the runtime model: `collections/` holds one note per root document persisted to a real MongoDB collection (e.g. `AttachmentMetadata.md` → `attachments`, `ImageMetadata.md` → `images`, `PdfHistory.md` → `pdfhistory`, plus product/barcode variants for import vs process paths), while `types/` holds general-purpose embedded/request/response/projection structs grouped by domain sub-module (`product-*`, `productbarcode-*`, `bom-*`, `option-*`, `optionpattern-*`, `ordertype-*`, `promotion-*`, `unit-*`, `color-*`). Each note is a Markdown file with a YAML front matter block declaring `source:` (the Go file path that is the single source of truth) and `tags:` (`datamodel`, `mongodb`, `mongo-root`, `general-type`) so a generator can filter root documents vs shared types. `Home.md` acts as the index, enumerating all collections with their backing struct + code evidence, cross-linking related types via `[[Type]]` wiki links, and embedding a Mermaid graph of the core entity relationships. There is no executable code in this module — it is consumed-only documentation produced by an external doc generator that reads the `source:` tags under `backend/internal`.
