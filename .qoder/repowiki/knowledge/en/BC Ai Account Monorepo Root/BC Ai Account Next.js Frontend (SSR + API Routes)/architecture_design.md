- **Framework**: Next.js 16 App Router (`src/app/**`) with React Server Components for layout/pages and client components for interactive screens; Tailwind CSS v4 via PostCSS.
- **Server boundary**: `src/app/api/**` implements Route Handlers that validate input, call the Go backend at `${serverMainApiBase()}/...`, and return JSON. A global rewrite in `next.config.ts` proxies `/backend/*` to the on-prem backend while explicitly blocking unauthenticated identity-trusting routes (`/backend/login`, `/googlelogin`, `/goapi/get|exec|getdoc`, `/reportm/*`, `/goapi/api/setup/*`, `/goapi/api/mcp/*`) as defense-in-depth.
- **Auth flow**: Login/register endpoints live under `src/app/api/auth/{login,register-username,profile,...}`; Google OAuth is handled via `/api/auth/google/{verify,status,session}`, LINE OA via `/api/auth/line/{code,link/status,status}`. Tokens are returned from login and stored client-side; authenticated image access goes through `/api/auth/profile` and an `AuthenticatedImage` component.
- **Workspace shell**: `src/app/workspace/page.tsx` is the main SSR entry that preloads the backend language via `getInitialBackendLanguage()` and renders `<WorkspaceScreen>`; other top-level pages (`currency`, `holding`, `line-oa`, `manual/[screen]`, `system-settings`, `menu`, `product_barcode_shelf`, `price_history`) follow the same page/screen split.
- **Shared libraries** (`src/lib/**`): pure TS modules for auth bridging (`auth-bridge.ts`), backend URL validation (`backend-url.ts`), i18n (`i18n.ts` + `locales/*.json` with Thai as source of truth), date/time formatting, menu data/icons/usage, setup config, Thai branch/address helpers, toast, theme/font data, and workspace models/API.
- **UI layer**: `src/components/ui/` provides shadcn-style primitives (button, card, table, select, numeric-input, etc.); feature-specific components sit alongside pages (e.g. `src/app/menu/tab-product-*.tsx`, `src/components/product-barcode/`).
- **Testing**: Unit tests use Vitest (`vitest.config.ts`, environment=node, pattern `src/**/*.test.ts`); E2E regression suite uses Playwright (`playwright.config.ts`, `e2e/*.spec.ts`) against a separately started dev server.
- **Build & runtime**: Dockerfile present for containerization; `.env.local` holds local overrides; `components.json` drives shadcn CLI.
