Existing underscore/mixed-case identifiers are legacy only; do not copy them into new work. Remove or rename them through explicit reset/migration/backfill/rebuild steps with rollback notes. External provider contracts that require underscores, such as LINE/RAGFlow/Shopee payload fields, must stay isolated in adapter boundaries and must not leak into internal MongoDB/PostgreSQL/ClickHouse contracts. MongoDB stores the primary key as `_id` and cannot remap it, so `bson:"id"` makes the field never unmarshal (always zero value), silently breaking any `doc.ID == NilObjectID` "not found" checks. The `json` tag may still expose it as `id` for no-underscore API contracts; only the `bson` tag is exempt. (Regression history: commit `2cdd52c4` renamed 161 `bson:"_id"`→`bson:"id"` and broke holding access — reverted.)

- **No Base64 Images Iron Rule**: ภาพทุกชนิด (logo, product, barcode, attachment, banner, illustration, user avatar, document scan) ต้องเก็บเป็น **ไฟล์จริงใน S3-compatible storage (MinIO/R2)** แล้วอ้างอิงด้วย URL/path เท่านั้น — ❌ ห้าม embed ภาพเป็น base64 data URI (`data:image/png;base64,...`) ใน MongoDB document, PostgreSQL row, API response, JSON config, frontend state, หรือ source code เด็ดขาด. เหตุผล: base64 ทำให้ DB/API payload บวม ~33%, ทำให้ query/index ช้า, backup ใหญ่, ไม่ cache ได้, และผิด Data Store Roles (ไฟล์ต้องอยู่ใน S3). ข้อยกเว้น: inline icon ขนาดเล็ก (< 2KB) ใน CSS/HTML เช่น favicon หรือ data placeholder, และกรณี slip OCR/scan preview ชั่วคราวที่ backend แปลงเป็นไฟล์ทันที — ต้องมี comment อธิบายเหตุผล. การดึงภาพออกมาแสดงต้องใช้ authenticated S3 proxy URL (`/goapi/s3/file/{key}`) หรือ public CDN URL เท่านั้น.
- **Shared Widget First Rule**: เมื่อ UX pattern เดียวกันปรากฏใน 2 หน้าจอขึ้นไป (เช่น list cards, skeleton loading, modal dialog, empty state + CTA, summary chips, search+add bar, motion stagger, header controls, toast/notice) ให้ **สร้างหรือใช้ shared widget/component/global CSS class** ใน `frontend/src/components/` หรือ `frontend/src/app/` ก่อนเขียน page-specific UI. ยกตัวอย่างที่มีอยู่: `<AppHeaderControls>`, `<NamesEditor>`, `RadioOptionGroup`, `useConfirmDialog`, `.header-controls`, `.holding-modal-panel`, `.holding-skeleton-card`. ห้าม copy-paste UI block ทั้งก้อนระหว่างจอ (เช่น skeleton HTML, modal wrapper, empty state markup) — ดึงเป็น component หรือ CSS class กลางแล้ว reuse. เมื่อสร้าง widget ใหม่ ต้องตั้งชื่อ generic (ไม่ใช่ชื่อจอ) และวางไว้ใน shared location.
- **Premium UX/UI Standard**: ทุกหน้าจอ frontend ต้องเป็น **เรียบหรู ดูแพง ใช้งานง่าย เข้าใจง่าย สวยงาม** และ **เหมาะสำหรับจอทุกขนาด**. เกณฑ์บังคับ: (1) **Tablet/Desktop-first responsive (เน้นจอใหญ่ก่อน, มือถือลำดับสุดท้าย)** — ออกแบบและทดสอบตามลำดับ priority ต่อไปนี้: **iPad/tablet (`md:768px`+)** ก่อนเป็นอันดับ 1 → **notebook (`lg:1024px`+, `xl:1280px`+)** อันดับ 2 → **desktop (`2xl:1536px`+)** อันดับ 3 → **มือถือ (`<768px`, สมาร์ทโฟน 375-414px)** อันดับสุดท้ายทำเป็น adaptive fallback ให้ใช้ได้ไม่พังเท่านั้น. ผู้ใช้หลักของ BC Account คือธุรกิจ SME ไทยที่ใช้ iPad/notebook เป็นอุปกรณ์หลัก ไม่ใช่มือถือ. ห้าม element ล้น/ตัด/ซ้อนกันทุกขนาดจอ แต่อย่าใช้เวลาส่วนใหญ่ไปกับ mobile-specific micro-layout ที่ซ่อน/ย้าย element รบกวน layout หลักบน iPad/notebook. (2) **Premium feel** — ใช้ design tokens (`--text-*`, `--radius-*`, `--shadow-*`, `--ease-out`), glassmorphism, subtle motion (fade/lift/stagger), hover micro-interactions, ห้าม UI ดิบ/แห้ง/เหมือน template ฟรี. (3) **Accessibility** — focus-visible ring, aria-label, semantic HTML, contrast WCAG AA, `prefers-reduced-motion`. (4) **Consistency** — ปุ่ม/icon/card/spacing ต้องเท่ากันทุกจอผ่าน shared component และ CSS class. (5) **Thai-first tone** — ภาษาไทยเป็นหลัก ใช้คำธรรมดาที่ SME เข้าใจ. ห้าม generic AI template (stock card grid + serif heading + accent bar). ตัวอย่างมาตรฐาน: login screen redesign + holding screen redesign (commit `754fb4bf`).
