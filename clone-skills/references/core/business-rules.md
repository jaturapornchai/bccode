# Business Rules — Checklist & Common Mistakes

## Mandatory Steps Before Implementing a New Feature

### Step 1: Understand Requirements
Answer these questions before writing code:
- Which document type? (PO/SO/PI/SI/SA/TR)
- Any state transitions to manage?
- Approval needed? Who is the approver?
- Which tables affected? Does stock change?
- Notifications needed? (LINE OA)
- Permission checks required?

### Step 2: Check Existing APIs
- Use MCP tools to verify if endpoint already exists:
  - General: `GET /goapi/mcp/tools` (business data tools)
  - Dev: `GET /goapi/mcp/dev/tools` (all tools incl. database, API catalog)
- If missing -> write `prompts/api_requests/{feature}.md` first. Never create APIs yourself.

### Step 3: Find Similar Features in Codebase
- Flutter: Find similar blocs in `bcaiaccount/lib/bloc/`, study patterns
- Go: Find similar handlers in `backend/handlers/`, study patterns

## Validation Rules

### Frontend (before API call)
- Document date must not be in the future (> 1 day)
- At least 1 line item required
- All items: qty > 0, price >= 0
- Grand total must match sum of line items (client-side calculation + verification)
- Check state before showing buttons/actions

```dart
// State-based button visibility
bool canEdit = doc.docstatus == 'draft' || doc.docstatus == 'rejected';
bool canSubmit = doc.docstatus == 'draft';
bool canApprove = doc.docstatus == 'pending' && currentUser.isApprover;
bool canCancel = !['completed', 'cancelled'].contains(doc.docstatus);
```

### Backend (every handler must validate)
- `shopid` must not be empty
- State transition must be valid (see document-flows.md)
- User authorized for this shop?
- Document exists?
- Numeric precision: prices use 2 decimals, quantities use 3

## Common Mistakes

### Mistake 1: Invalid state transition
```go
// Wrong — skips pending
if doc.Status == "draft" { doc.Status = "approved" }

// Correct
if doc.Status != "pending" {
    return c.JSON(400, map[string]interface{}{
        "message": "Document must be in pending status to approve",
    })
}
```

### Mistake 2: Missing transaction when updating multiple tables
```go
// Wrong — if stock update succeeds but doc update fails = data out of sync
UpdateStock(db, doc.Items)
UpdateDocument(db, doc)

// Correct
tx, _ := db.Begin()
defer func() { if r := recover(); r != nil { tx.Rollback() } }()
UpdateStock(tx, doc.Items)
UpdateDocument(tx, doc)
tx.Commit()
```

### Mistake 3: Showing buttons without permission check
```dart
// Wrong
ElevatedButton(onPressed: onApprove, child: Text('Approve'))

// Correct
if (currentUser.hasPermission('po_approve'))
  ElevatedButton(onPressed: onApprove, child: Text('Approve'))
```

### Mistake 4: Missing shopid
```dart
// Wrong
await dio.post('/goapi/api/po/list', data: {'limit': 20});

// Correct
await dio.post('/goapi/api/po/list', data: {
  'shopid': shopId,
  'limit': 20,
});
```

### Mistake 5: Creating Dart model without verifying API response
Correct approach: Use MCP tool `get_table_sample` or `execute_query` to inspect real data before creating model.

### Mistake 6: Frontend generating docno
Correct: DocNo generated by backend only — frontend should not send docno on insert.

## Pre-Commit Checklist

### Business Logic
- [ ] Multi-tenant: shopid everywhere?
- [ ] State transitions valid per document-flows.md?
- [ ] Permission checks on all critical operations?
- [ ] Validation on both client-side and server-side?
- [ ] Notifications on correct triggers?
- [ ] Audit log for important state changes?

### Cross-System
- [ ] Frontend calling correct API endpoint path?
- [ ] Request/Response field names match?
- [ ] All backend error messages handled by frontend?

### Testing
- [ ] Happy path passes
- [ ] Validation errors display correctly
- [ ] All state transitions tested
- [ ] Edge cases: empty data, zero quantity
