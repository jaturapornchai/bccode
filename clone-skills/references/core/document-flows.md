# Document Flows — State Machine for All Modules

## Document Types

| Code | Name | Module |
|------|------|--------|
| `PO` | Purchase Order | Purchasing |
| `PI` | Purchase Invoice | Purchasing |
| `SO` | Sales Order | Sales |
| `SI` | Sales Invoice | Sales |
| `PR` | Purchase Requisition | Purchasing |
| `RFQ` | Request for Quotation | Purchasing |
| `SA` | Stock Adjustment | Inventory |
| `TR` | Transfer | Inventory |

## Core State Machine

```
                    [Edit and resubmit]
                         ^
draft --submit--> pending --approve--> approved --complete--> completed
                    |
                    +--reject--> rejected

[Can cancel in any state except completed]
draft/pending/approved --cancel--> cancelled
```

## Rules per State

| State | Editable? | Deletable? | Can submit? | Printable? |
|-------|-----------|------------|-------------|------------|
| `draft` | Yes | Yes | Yes | Yes |
| `pending` | No | No | No | Yes |
| `rejected` | Yes | No | Yes (resubmit) | Yes |
| `approved` | No | No | No | Yes |
| `completed` | No | No | No | Yes |
| `cancelled` | No | No | No | Yes |

## Approval Workflow

### Pre-approval conditions
- Document must be in `pending` state
- Approving user must have `approver` role for that document type
- Grand total must be > 0
- At least 1 line item required

### On approval success
- Set `docstatus` -> `approved`
- Send LINE OA notification to document creator
- Record audit log (who approved, when)

### On rejection
- Set `docstatus` -> `rejected`
- Record `reject_reason`
- Send LINE OA notification to creator

## Flow by Module

### Purchase Flow (Procurement)
```
PR (draft) -> PR (approved) -> RFQ (get quotes from 3+ vendors) -> RFQ (approved)
                             \-> PO (create directly, skip RFQ)       |
                                                                PO (create from RFQ)
PO (draft) -> PO (approved) -> PI (create referencing PO) -> PI (approved)
```
- **PR**: Department submits request -> manager approves -> purchasing proceeds (transflag=21)
- **RFQ**: Get quotes from 3+ vendors -> compare -> select vendor (transflag=22)
- PR can skip RFQ and create PO directly
- PO can reference either PR or RFQ
- PI must reference an approved PO
- Stock increases when PI is `completed`

#### PR-specific fields
- `requestercode`, `requestername` — requester
- `departmentcode`, `departmentnames` — requesting department
- `purpose` — purpose/reason
- `budgetcode`, `budgetamount` — budget
- `urgency` — 1=Normal, 2=Urgent, 3=Critical
- `requesteddeliverydate` — required delivery date
- `conversionstatus` — none/converted_to_rfq/converted_to_po

#### RFQ-specific fields
- `refprdocno`, `refprguidfixed` — PR reference
- `vendorentries` — vendor list (VendorEntry[]) each with items + prices
- `selectedvendor` — selected vendor
- `selectionreason` — selection reason
- `submissiondeadline` — quotation submission deadline
- `minvendors` — minimum vendor count

### Sales Flow
```
SO (draft) -> SO (approved) -> SI (create from SO) -> SI (approved) -> SI (completed)
```
- Stock decreases when SI is `completed`
- If SI cancelled -> stock restored

### Stock Adjustment
```
SA (draft) -> SA (approved) -> SA (completed)
```
- Stock changes immediately on `completed`
- Adjustment reason required

### Transfer
```
TR (draft) -> TR (approved) -> TR (completed)
```
- Stock moves from source to destination warehouse on `completed`
- Both warehouses must be in the same shop

## Document Number Format

- DocNo generated by backend automatically
- Format: `{PREFIX}{YY}{MM}{RUNNING_NUMBER}` e.g. `PO2501001`
- Frontend must never generate docno

## Key Database Fields (table: doc)

```sql
docno        VARCHAR  -- Document number (unique per shop per doctype)
doctype      VARCHAR  -- PO/PI/SO/SI/SA/TR
docstatus    VARCHAR  -- draft/pending/approved/completed/cancelled/rejected
docdatetime  TIMESTAMPTZ -- Document date
shopid       VARCHAR  -- Multi-tenant key
createdby    VARCHAR  -- Creator
approvedby   VARCHAR  -- Approver
approvedat   TIMESTAMPTZ
totalamount  NUMERIC  -- Total before VAT
vatamount    NUMERIC  -- VAT
grandtotal   NUMERIC  -- Total after VAT
```
