## 2026-06-23 — Fix "กลุ่มสินค้า ย้ายไปมา หายหมด" (product-group tree vanishes after reparent)
- Symptom (ลุงจืด): dragging/reparenting product groups made ALL groups disappear from the tree.
- Root cause (verified via live API + UI): a reparent can create a CYCLE in parentguid (A→C→B→A). Confirmed empirically — backend has no cycle guard (#6, PUT accepts it, data NOT lost) and the FE move-guard checked `targetGroup.parentguidall` (a string that goes STALE on descendants after a move, so the cycle slips through). frontend/src/app/system-settings/product-group-tree-view.tsx treeRoots builder put every node with a present parent into childGroups and only parent-less nodes into `roots`; in a cycle EVERY node has a present parent → `roots = []` → tree renders empty = "หายหมด" (groups are fine in DB, just unrenderable).
- Fix (FE, minimal, 2 parts):
  1. Cycle-tolerant builder: walk parentguid upward with a visited-set (`chainReachesRoot`); a node whose chain loops never reaches a root → surface it as a root (flat) instead of dropping it, and never link cyclic nodes into childGroups (no render-recursion loop). Tree can no longer vanish regardless of cycle source.
  2. Cycle prevention: new `isWithinSubtreeOf(nodeGuid, ancestorGuid)` walks the LIVE override-aware parentguid graph (not the stale parentguidall string). moveGroupAsChild blocks when target is inside the dragged subtree; reorderGroup blocks when the new parent is the dragged node or inside its subtree.
- Verified: tsc EXIT 0; production next build EXIT 0; live Claude Preview (fresh build → .202) with a deliberately seeded cycle (A→C→B→A) → /productgroup renders all 3 cyclic groups flat as roots (5 rows incl. 2 pre-existing) with แก้ไข/ลบ — NOT empty. Pre-fix the same data rendered 0 rows. Cyclic test data cleaned up (break-cycle then delete; note the #2 child-guard blocks deleting cyclic nodes until parent is cleared).
