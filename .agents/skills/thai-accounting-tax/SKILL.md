# งานบัญชี/ภาษีไทย — ห้ามเดา ต้องมีอ้างอิงทางการ

ลุงจืดสั่ง 2026-09-23: **"หลักการบัญชี ห้ามเดา ต้องมีอ้างอิง ค้นหาจาก internet"** และ **"งานด้านบัญชี พยายามสร้าง skill หรือ kms เก็บไว้ จะได้ไม่สับสน"**

- **ความรู้ (ข้อเท็จจริง + อ้างอิง)** อยู่ที่ `docs/kms/21-thai-tax-form-references.md` (ทะเบียนอ้างอิง: ช่องไหนของแบบ ระบบเติม/คำนวณ เพราะคำชี้แจงข้อไหน)
- **skill นี้** = ขั้นตอนทำงาน + กับดักที่เจอแล้ว; ขัดกับ `AGENTS.md` ให้ `AGENTS.md` ชนะแล้วแก้ skill

## 1. ใช้เมื่อ

งานที่ตัวเลข/ช่อง/สูตร/เงื่อนไขมาจากกฎหมาย ประกาศ หรือมาตรฐานวิชาชีพ เช่น เติมหรือคำนวณช่องในแบบยื่นภาษี, อัตราภาษี, เงินเพิ่ม/เบี้ยปรับ, เครดิตภาษี, เงื่อนไขใบกำกับภาษี, การจัดประเภทบรรทัดงบการเงิน, วิธีลงบัญชีตาม TFRS — **ไม่ใช้** กับงาน UI ล้วน (ใช้ `ui-scale-polish`) หรือ workflow ตามต้นแบบ Champ ที่ไม่เกี่ยวกับกฎหมาย (Champ เป็นต้นแบบ workflow ไม่ใช่แหล่งกฎหมาย)

## 2. ขั้นตอน (ทำตามลำดับ ห้ามข้าม)

1. **เปิดทะเบียนก่อน** `docs/kms/21-thai-tax-form-references.md` — ถ้ามีแถวของเรื่องนั้นแล้ว ใช้ตามนั้น (เรื่องที่เปลี่ยนบ่อย เช่น อัตรา/กำหนดเวลา ให้ตรวจว่าฉบับที่อ้างยังเป็นฉบับล่าสุด)
2. **ไม่มีในทะเบียน → ค้นแหล่งทางการ** (WebSearch):
   - ภาษี: `<หัวข้อ> site:rd.go.th` — คู่มือวิธีกรอกแบบอยู่ใต้ `rd.go.th/fileadmin/tax_pdf/...` (เช่น `cit/2566/251066Ins50.pdf`)
   - มาตรฐานบัญชี (TFRS / TFRS for NPAEs): `tfac.or.th`
   - งบการเงิน/นำส่งงบ: `dbd.go.th`
   - กฎหมาย/ประกาศ: `krisdika.go.th`, `ratchakitcha.soc.go.th`
   - บทความสำนักงานบัญชี/บล็อก = เบาะแสให้ไปหาเอกสารทางการ **ไม่ใช่หลักฐาน**; บทสรุปจาก search/AI ก็ไม่ใช่หลักฐาน
3. **อ่านเอกสารทางการเอง** — WebFetch กับ PDF ภาษาไทยของกรมสรรพากรสรุปไม่ได้ แต่จะบันทึกไฟล์ไว้ใน `tool-results/webfetch-*.pdf` → ถอดข้อความด้วย pypdfium2:
   ```bash
   cd "<โฟลเดอร์ tool-results ที่ WebFetch แจ้ง>" && PYTHONIOENCODING=utf-8 py -c "
   import pypdfium2 as pdfium, re
   pdf = pdfium.PdfDocument('webfetch-XXXX.pdf')
   t = re.sub(r'\s+', ' ', ' '.join(pdf[i].get_textpage().get_text_range() for i in range(len(pdf))))
   i = t.find('<ข้อความที่ต้องการ>'); print(t[i:i+700])"
   ```
   (ภาษาไทยจาก PDF มีช่องว่างแทรกระหว่างสระ เช่น "จำ นวน" — ค้นด้วยคำสั้นหรือ regex `\s*`)
4. **บันทึกลงทะเบียนใน commit เดียวกับโค้ด**: แบบ/ข้อ, key ของช่อง, ถ้อยคำสั้นที่ใช้ตัดสิน (ในเครื่องหมายคำพูด), รหัสแหล่ง (URL + ฉบับ/ปี) ใน §1, ข้อมูลในระบบที่ใช้, โค้ด `path:line`, test
5. **เขียนโค้ด** (backend-first — `AGENTS.md`):
   - คอมเมนต์อ้าง § ของทะเบียน (เช่น `docs/kms/21-thai-tax-form-references.md §4`)
   - เงินเป็น decimal/สตริงเสมอ (`shopspring/decimal`, ห้าม float/JS number) — Rule 20
   - ช่องที่ระบบเติมต้องแก้ได้เสมอ (ฐานภาษี/เครดิต) ระบบคำนวณเฉพาะบรรทัดรวมตามสูตรบนแบบ
   - ทุกช่องที่เติมจากข้อมูลในระบบต้องมีหมายเหตุบอกที่มา (`TaxFormNote` + `{count}`/`{amount}`) ให้ผู้ใช้ตรวจกับเอกสารจริงได้
   - ข้อความใหม่ = แถวใน `backend/assets/language/languages.tsv` ครบ 13 คอลัมน์ (th + en จริง, ภาษาอื่นใส่ en)
6. **ข้อมูลในระบบไม่พอจะเติมโดยไม่เดา → ไม่เติม** + ใส่ในทะเบียน §5 + เสนอลุงจืดเป็นตัวเลือก — **ห้ามจับคู่บัญชีกับบรรทัดแบบจากชื่อหรือรหัสบัญชีเอง** (ผังบัญชีตาม `mydocs/datamodels/gl/chartofaccount.sql` ไม่มีข้อมูลนี้)
7. **ตรวจ**: unit test ของสูตร (กรณีบวก/ลบ/ศูนย์/ยังไม่กรอก), integration test บน PostgreSQL จริง (`BC_TAXFORM_TEST_POSTGRES_DSN`, `tools/verify.sh postgres` ส่งให้เอง), UAT ด้วยปุ่ม Demo + ตรวจ PostgreSQL ทีละขั้น (กฎ UAT ใน `AGENTS.md`)

## 3. กับดักที่เจอแล้ว (อย่าพลาดซ้ำ)

- **แบบใน `mydocs/sample` ไม่มีหน้าคำชี้แจง** — สูตรบนแบบใช้ได้ แต่เงื่อนไข (ช่วงเวลา, ใครใช้วิธีไหน) ต้องมาจากคู่มือวิธีกรอกแบบของกรมสรรพากร
- **ช่วงเวลาของเครดิตต่างกันตามแบบ**: ภ.ง.ด.50 ภาษีถูกหักทั้งรอบบัญชี แต่ ภ.ง.ด.51 เฉพาะ 6 เดือนแรกของรอบบัญชี — กรองตาม **วันที่จ่ายในหลักฐาน** ไม่ใช่วันลงบัญชี
- **ภ.ง.ด.51 วิธีที่ 2 (กำไรจริง 6 เดือน) ไม่ใช่ของ SME** — ใช้เฉพาะบริษัทจดทะเบียน/ธนาคาร/สถาบันการเงินและกิจการที่ต้องสอบทานงบ; SME ใช้ประมาณการ
- **"ภาษีที่ชำระแล้วตาม ภ.ง.ด.51"** ใน ภ.ง.ด.50 = ยอด "ชำระเพิ่มเติม" รายการที่ 2 ข้อ 6 เท่านั้น (ชำระไว้เกินไม่นับ)
- **ห้ามคำนวณอัตราภาษีหรือเงินเพิ่มเอง** จนกว่าจะตรวจแหล่งทางการและบันทึกในทะเบียน — ตอนนี้ผู้ใช้กรอก
- **จอรายงาน "ภาษีถูกหัก" (แก้ 2026-09-23)**: เดิมหาบัญชีจากคำว่า "ภาษีถูกหัก" ติดกัน จึงหาบัญชีมาตรฐาน "ภาษีเงินได้ถูกหัก ณ ที่จ่าย" ไม่เจอและรายงานว่างบน prod — ตอนนี้ใบที่บันทึกรายการภาษีหัก (`details.withholdings`) เข้ารายงานเสมอ (`recordedWithholdingRows` ใน `tax_report.go`; ยอดบัญชีที่เกินยอดบันทึก = `withholdingRemainders`) และการหาจากชื่อรับทั้ง "ภาษีถูกหัก" และ "ถูกหัก ณ ที่จ่าย" (แถวที่ได้จากชื่อบัญชีติดป้าย inferred); **เครดิตภาษีใน ภ.ง.ด.50/51 ยังนับเฉพาะรายการที่บันทึก** (`generalledger.WithheldFromCompanyTotal`) ไม่นับแถว inferred
- **ภ.ง.ด.50 รายการที่ 2–9 แยกบรรทัด = ผู้ใช้กรอกเอง** (มติลุงจืด 2026-09-23) — ห้ามสร้างผังจับคู่บัญชี→บรรทัดในโค้ด; Champ ก็ไม่มี (รายละเอียดทะเบียน §5)
- **ห้ามใช้รหัสบัญชีเป็นเงื่อนไข** (ลุงจืด 2026-09-24) — ผังบัญชีแต่ละบริษัทต่างกัน; `startsWith("115")` = ภาษีซื้อ ทำให้ 1153 ภาษีเงินได้ถูกหัก ถูกเสนอให้ "ปรับเป็น VAT 7%" ผิด ๆ — แยกประเภทจากชื่อบัญชี + `accounttype` + รายละเอียดที่ผู้ใช้บันทึก (`details.vats`/`details.withholdings`) เท่านั้น; บัญชีรายได้/ค่าใช้จ่ายที่ชื่อมี "ภาษีมูลค่าเพิ่ม" ไม่ใช่บรรทัดภาษี (bug `docs/kms/bugs/2026-09-24-gl-journal-entry-uat-findings.md`)
- **ห้ามใช้รหัสประเภท/รหัส master ที่ผู้ใช้ตั้งเองเป็นเงื่อนไขกฎหมาย** (2026-09-25) — เพดานค่าเสื่อมรถยนต์นั่ง 1 ล้านเคยเช็ค `PASSENGER_CAR` แต่ฟอร์มบันทึก `VEHICLE_PASSENGER` จึงไม่เคยทำงาน; กฎหมายมีข้อยกเว้นรายคัน (รถกิจการให้เช่า/รถต้นแบบวิจัย) → ใช้ flag ที่ตัวรายการให้ผู้ใช้ติ๊ก (`passengercartaxcap`) — ทะเบียน §13, `docs/kms/bugs/2026-09-25-passenger-car-tax-cap-never-applied.md`. **เพดานทุน 1 ล้านอย่างเดียวไม่พอ** ต้องคงเพดานอัตรา (ม.4(5) ร้อยละ 20 ต่อปี ตามวันที่ถือ) ด้วย — สูตรสเกลตามทุนเคยทำให้รถอายุ 3 ปีหักได้ 333,333 แทน 200,000
- **ค่าเสื่อมทางภาษีที่ถูกเพดานกันไว้ ต้องยกไปหักปีถัดไป — อย่าหยุดตามงวดบัญชี** (2026-09-25) — คิดทีละปีจากค่าเสื่อมทางบัญชีของปีนั้นทำให้รถอายุ 3 ปี (ทุน 1.5 ล้าน) หักทางภาษีรวมแค่ 666,202.11 แล้ว 0 เมื่องวดบัญชีหมด; ที่ถูก (กค 0702/570 "หัก…ต่อไปจนหมด", กค 0811/09658, ป.3/2527 ข้อ 2+8) = ไล่ยอดสะสม: ปีนี้ = min(min(บัญชีสะสม × 1M/ทุน, ฐานสูงสุด) − ที่หักไปแล้ว, เพดานปีนี้) หลังขาย 0 → `passengerCarTaxByYear` ต้องอ่านงวดบัญชี**ทุกปี** ไม่ใช่แค่ปีที่ขอรายงาน; ผลต่างปีที่บัญชีหมดติดลบได้ (ทะเบียน §13)
- **ใบที่กลับรายการแล้วกับรายงานภาษี** — VAT อ่านเฉพาะ `status = 'posted'` (ต้นฉบับกลายเป็น `reversed` แต่ `gl_lines`/`details` ยังอยู่คู่กับใบกลับรายการ, `subledger_vat.go`); **WHT ต่างออกไป** (2026-09-24): แบบ ภ.ง.ด. ยื่นตาม "เดือนที่จ่ายเงินได้" (ประกาศ กค. / ป.111/2545) — กลับรายการเดือนเดียวกันหรือก่อน = ไม่แสดงทั้งคู่; กลับรายการ **เดือนหลัง** = ต้นฉบับยังอยู่ในเดือนที่จ่าย + `reversedmonth` + หมายเหตุ (ยื่นแล้วแก้ด้วยการขอคืนตาม ม.27 ตรี / แบบ ค.10 หรือยื่นเพิ่มเติมกรณีนำส่งเกินใน e-Filing) ห้ามสร้างแถวติดลบในเดือนที่กลับ (`whtReversalMonthSQL` ใน `tax_report.go`, `docs/kms/21` §9)
- **ลบข้อมูลทดสอบที่ผ่านรายการแล้วตรง ๆ ไม่ได้** — `gl_subledger_audit` มี trigger append-only; เก็บกวาด UAT ด้วยการกลับรายการพร้อมเหตุผล ห้ามปิด trigger
- **คู่มือต่างปีถ้อยคำต่างกัน** — ระบุฉบับ/ปีที่ใช้เสมอ
- **ไม่มีระบบเงินเดือน**: ภ.ง.ด.1/1ก และ สปส. ห้ามทำ (`AGENTS.md`) แต่ ภ.ง.ด.2 อยู่ในขอบเขต
- **ห้ามอ้างชื่อซอฟต์แวร์บัญชีเจ้าอื่น** ในโค้ด/เอกสาร (`AGENTS.md`)
- **งวดของภาษีหัก ณ ที่จ่ายที่บันทึกไว้ = เดือนของ `payment_date` ไม่ใช่วันที่ใบ** (2026-09-24) — ประกาศ กค. ข้อ 2 / คู่มือ ภ.ง.ด.3/53 ข้อ 2.4 นับจาก "เดือนที่จ่ายเงินได้"; `payment_date` ว่างเท่านั้นจึงใช้วันที่ใบ; แถวที่ประมาณจากบัญชี (inferred) ใช้วันที่ใบ — `docs/kms/21` §9, `tax_report.go` `recordedWithholdingRows`
- **ใบกลับรายการ ใบยอดยกมา และใบปิดบัญชี (`kind` = `reversal`/`opening`/`closing`) มีสถานะ posted** — กรองแค่ `status = 'posted'` ไม่พอ ต้องตัด kind เหล่านี้ทุก query รายงานภาษีหัก (`whtNonTaxJournalKinds` ใน `tax_report.go`); UAT S24 2026-09-24 ใบยกมาเคยกลายเป็นแถวอัตรา 100% ใน ม.ค.
- **ใบที่บันทึกรายการภาษีหักทิศทางนั้นแล้ว ห้ามมีแถว inferred ซ้ำกับยอดที่บันทึก** แม้แบบที่บันทึกต่างจากแบบของบัญชี หรือวันที่จ่ายคนละเดือน — ไม่งั้นนับซ้ำ; แต่ **ห้ามทิ้งส่วนที่ไม่ได้บันทึก**: ยอดบัญชีภาษีหักของใบที่เกินยอดบันทึกรวม เป็นแถว inferred ฐานไม่ทราบ (`withholdingRemainders` — แยกตามแบบเมื่อส่วนขาดรายแบบรวมได้พอดี, ไม่งั้นแบบว่าง) เพื่อให้ยอดรวมตรงบัญชี (review C2 2026-09-24: ใบจ่ายสองรายบันทึกรายเดียว ส่วนที่เหลือเคยหาย)
- **ใบโอนยอดระหว่างบัญชีภาษีหัก (Dr ภ.ง.ด.3 / Cr ภ.ง.ด.53) ไม่ใช่การหักภาษี** — ฝั่งตรงข้ามไม่มีบรรทัดที่ไม่ใช่บัญชีภาษี = ไม่สร้างแถว inferred (UAT S25/S26 เคยนับซ้ำ); "บัญชีภาษี" ต้องรวมบัญชีที่ค้นพบจากชื่อแบบ "ภ.ง.ด.<แบบ>" ของทั้งสองทิศทาง (`whtScope.taxAccounts`) ไม่ใช่แค่ชื่อที่มี "หัก ณ ที่จ่าย" — "ภ.ง.ด.53 ค้างจ่าย" เคยถูกนับเป็นฐานจนได้แถวอัตรา 100% (review C1); ห้ามแก้ด้วยการหักลบเดบิตบัญชีภาษีหัก เพราะใบนำส่งเดือนก่อน + หักใหม่ในใบเดียวจะหาย; ใบที่ปนโอนยอดกับค่าใช้จ่ายอื่นยังประมาณผิดได้ → ให้ผู้ใช้บันทึก `details.withholdings`
- **ฐานภาษีของแถว inferred ตัดบัญชีภาษีด้วย "ชื่อ" + `accounttype`** — "หัก ณ ที่จ่าย"/"ถูกหัก" ตัดทุกประเภท; "ภาษีซื้อ"/"ภาษีขาย"/"ภาษีมูลค่าเพิ่ม" ตัดเฉพาะบัญชี asset/liability (บัญชีรายได้ "…มีภาษีมูลค่าเพิ่ม 7%" คือฐาน — UAT S14 เคยได้ฐาน 0 สุทธิติดลบ); ไม่ใช่รหัส; ใบที่มีบัญชีภาษีหักหลายบัญชี = ฐาน 0 อัตราว่าง (แบ่งฐานไม่ได้โดยไม่เดา) และหลายบรรทัดบัญชีเดียวกันรวมเป็นแถวเดียว
- **ฐานไม่ทราบ = ยอดสุทธิว่าง ไม่ใช่ติดลบ** — `net_amount` ว่างเมื่อฐาน 0 หรือฐาน < ภาษี; frontend ต้องคงค่าว่าง (`toMoneyOrBlank` ใน `frontend/src/lib/thai-tax.ts`) ห้าม `toMoney` แปลงเป็น "0.00"
- **เรียงรายการภาษีหักตามวันที่จ่าย ไม่ใช่วันที่ใบ** — ทั้งตารางและใบแนบ ภ.ง.ด.53 (UAT S10/S12)
- **`Amount` ว่างถูก marshal เป็น "0"** — ค่าที่ต้องมีจริง (เช่น `vat_rate`) ต้องตรวจ **ก่อน** JSON round trip (`requireVatRates` ใน `cloneJournalDetails`) ไม่งั้นค่าที่ไม่ส่งมากลายเป็น 0% เงียบ ๆ (UAT V13)
- **ข้อความผิดพลาดของ GL ต้องเป็น `userError`/`fieldError` code + field** (แปลผ่าน `gl_err_<code>` ใน `languages.tsv`) ไม่ใช่ `fmt.Errorf` ไทย — test `TestGLUserErrorCodesHaveEnglishRows` สแกนซอร์สหาแถวภาษาอังกฤษที่ขาด
- **ผู้รับเงินที่ไม่มีทั้งเลขผู้เสียภาษีและชื่อ** ห้ามรวมกันบนใบแนบ — แยกตามรหัสคู่ค้า ไม่มีก็แยกตามใบ (`payeeKey` ใน `tax_form_fill.go`)
- **งวดที่ใช้สิทธิภาษีซื้อแยกตามประเภทเอกสาร** (2026-09-24): ใบกำกับภาษีและ **ใบเพิ่มหนี้** (ม.77/1(22) นับใบเพิ่มหนี้/ใบลดหนี้เป็น "ใบกำกับภาษี") = เดือนที่ออกถึงอีก 6 เดือน; **ใบลดหนี้ไม่มีเพดาน 6 เดือน** — ม.82/10 วรรคท้าย + ป.80/2542 ข้อ 5: ต้องลดภาษีซื้อ "ในเดือนภาษีที่ได้รับใบลดหนี้" (บังคับ ไม่ใช่สิทธิที่เลื่อนได้) ตรวจแค่งวดต้องไม่ก่อนเดือนของใบลดหนี้ (`vat_credit_note_period_before_note`) — ห้ามใช้กรอบ 6 เดือนกับใบลดหนี้ทั้ง backend และจอ (`vatClaimTiming`)
- **งวดที่ใช้สิทธิภาษีซื้อ (ใบกำกับ/ใบเพิ่มหนี้) = เดือนที่ออกเอกสาร ถึงอีก 6 เดือนถัดไป** (2026-09-24) — ประกาศ VAT ฉบับที่ 4 ข้อ 2 (แก้โดยฉบับที่ 76) "ต้องไม่เกินหกเดือนนับแต่เดือนถัดจากเดือนที่ออกใบกำกับภาษี"; "สามปี" ใน ม.82/3 วรรคสองเป็นกรอบนอก **ไม่ใช่** กรอบใช้สิทธิในงวดปกติ — `checkPurchaseClaimWindow` ตรวจเฉพาะ `tax_type` 1 + `claim_status` 1 ทั้งตอนบันทึกและกระทบยอด; ปีของงวด (`tax_period_year`) เป็น **ค.ศ.** ห้ามเทียบกับ พ.ศ.; เกิน 6 เดือน = ยื่น ภ.พ.30 เพิ่มเติมของเดือนที่ออกใบกำกับ (ทะเบียน `docs/kms/21` §10)
- **เลขที่ใบกำกับภาษีซ้ำกันได้ถ้าคนละผู้ออก** — ม.86/4 (2)+(4): เลขที่ไม่ซ้ำเฉพาะในผู้ออกรายเดียว (สาขาต่างกัน = คนละผู้ออก); ห้ามเตือน/บล็อกด้วยเลขที่อย่างเดียว — key ต้องเป็น ประเภทภาษี + ผู้ออก (เลขผู้เสียภาษี+สาขา → รหัสคู่ค้า → ชื่อ) + เลขที่ normalize + วันที่ (`vatInvoiceKeySQL` ใน `subledger_vat.go`)
- **ใบกำกับภาษีเดียวกันในหลายใบสำคัญ = เตือน ไม่บล็อก** — `duplicatedocnos`/`duplicatecount` ในทะเบียน + หมายเหตุ `tax_form_note_duplicate_invoice` ใน ภ.พ.30; นับเฉพาะใบที่ยังมีผล (ร่าง/ผ่านรายการ, ไม่ถูกลบ, ไม่ใช่ใบกลับรายการ, ต้นฉบับที่กลับแล้วไม่นับ); ห้ามเขียนว่ากฎหมายบอก "ใช้ได้ครั้งเดียว" — ที่มาจริงคือสำเนาเป็นภาษีซื้อต้องห้าม (ประกาศฯ ฉบับที่ 42 (7)); ใบกำกับฉบับใหม่แทนฉบับเดิมมี **เลขใหม่ วันที่เดิม** (ป.86/2542 ข้อ 25) จึงจับด้วย key นี้ไม่ได้
- **ข้อความผิดพลาดของรายการ VAT ต้องชี้ field ที่ผิดทีละสาเหตุ** (`vat_invoice_no_invalid` → `tax_invoice_no` ฯลฯ) — `vat_invalid` รวมทุกสาเหตุแบบเดิมทำให้ผู้ใช้ไม่รู้ว่าต้องแก้ช่องไหน (`TestSubledgerVatReportsFieldOfEachError`)
- **ประเภทสมุดรายวันมาจาก `booktype` ไม่ใช่รหัสสมุด** (2026-09-24, สเปก `mydocs/datamodels/gl/journalbook.sql`: 1 ทั่วไป (JV), 2 จ่าย (PV), 3 รับ (RV), 4 ขาย (SV), 5 ซื้อ (UV), 6 ยอดยกมา) — สมุดเป็น master ที่ผู้ใช้เพิ่ม/ลบ/ตั้งรหัสไทยเองได้ (ต้นแบบ Champ `BCGLBook`); ภาษีขาย/ซื้อเริ่มต้นดูจาก `booktype` 4/5, ปิดบัญชี/สินทรัพย์ถาวรใช้ประเภท 1, ยกยอดใช้ 6 (ไม่มีใช้ 1); ระบบเดิมใช้ SV/UV **สลับความหมาย** → สมุดเก่าที่ไม่มีประเภทห้ามเดาจากรหัส ให้ผู้ใช้กำหนดที่หน้า "กำหนดสมุดรายวัน" (ADR `docs/kms/decisions/2026-09-24-user-defined-journal-books.md`, `backend/internal/generalledger/journal_books.go`)
- **ภาษีหัก ณ ที่จ่ายเก็บ snapshot ผู้จ่าย/ผู้รับเงิน ณ วันบันทึก** (2026-09-24, ฟิลด์ตาม `mydocs/datamodels/gl/wht.sql`: `payer_*`/`payee_*` tax_id/branch_no/name/address + `remark` + `wht_book_no`) — payer = ผู้จ่าย/ผู้หักภาษีเสมอ (ทิศทาง 1 บริษัทหักคู่ค้า: payer = บริษัท, ทิศทาง 2 คู่ค้าหักเรา: payer = คู่ค้า); หนังสือรับรอง 50 ทวิ และรายงาน ภ.ง.ด. อ่าน snapshot ก่อนทะเบียนปัจจุบัน **ทีละช่อง** (แก้ทะเบียนภายหลังต้องไม่เปลี่ยนเลขภาษีของใบเก่า); ฝั่งคู่ค้าที่ว่างทั้งชุดเติมจากทะเบียนตอนบันทึก (รอลุงจืดยืนยัน); เลขภาษีตัดขีดเหลือ 13 หลัก, สาขาเติม 0 ให้ครบ 5 หลัก; `wht_rate` บังคับส่ง (ไม่หัก = `"0"`) — `backend/internal/generalledger/subledger_withholding.go`, `backend/internal/goapi/handlers/wht_certificate.go`, `applyWithholdingPartySnapshot` ใน `backend/internal/goapi/handlers/tax_report.go`
- **ปีงวดภาษีเก็บเป็น ค.ศ. — ปี ≥ 2400 คือผู้ใช้กรอก พ.ศ.** → ปฏิเสธ `vat_period_year_buddhist` ห้ามลบ 543 ให้เอง (งวดภาษีต้องไม่เปลี่ยนเงียบ ๆ); จอแสดงเดือนเป็นชื่อเดือนไทย + พ.ศ. แต่ค่าที่ส่งเป็น ค.ศ.
- **กฎภาษีใหม่ตรวจเฉพาะแถวใหม่หรือแถวที่แก้** (ปีงวด, กรอบใช้สิทธิ, หลักตรวจสอบเลขผู้เสียภาษี, ความยาวข้อความตาม DDL) — แถวเดิมที่ค่าไม่เปลี่ยนหลัง normalize ต้องผ่าน ไม่งั้นใบร่างเก่าแก้/ลบ/กลับรายการไม่ได้ (`vatRowNeedsRules`); **ยกเว้นตอนผ่านรายการตรวจทุกแถว** เพราะแถวจะเข้า ภ.พ.30 ทันที
- **ใบกำกับภาษีเดียวกันหลายแถวในใบสำคัญเดียว** (สถานะใช้สิทธิเดียวกัน) = ซ้ำด้วย — `duplicatedocnos` มีเลขของใบนี้เอง; แยกแถวต่างสถานะ (ใช้สิทธิบางส่วน + ต้องห้ามบางส่วน) ไม่นับว่าซ้ำ
- **เลขประจำตัวผู้เสียภาษี 13 หลักต้องผ่านหลักตรวจสอบ mod 11** (`whtcert.ValidThaiTaxID` แหล่งเดียว) — ทะเบียนคู่ค้า, แถว VAT, แถวภาษีหัก, 50 ทวิ, ไฟล์ยื่นด้วยสื่อ; ว่าง = ผ่าน (เติมจากทะเบียนคู่ค้าได้โดยไม่ทับค่าที่พิมพ์); ภ.ง.ด.2 ผู้รับเงินไม่มีเลขใช้ `0000000000000` (ไฟล์ยื่นรับเฉพาะดอกเบี้ย 40(4)(ก)); **เอกสารทางการ (กรมการปกครอง/DBD/สรรพากร) บอกแค่ว่ามีหลักตรวจสอบ ไม่ได้ระบุสูตร** — ห้ามเขียนว่าสูตรมาจากกรมใด (`docs/kms/21` §12)
- **ไฟล์ยื่นภาษีหัก ณ ที่จ่ายด้วยสื่อ (Format กลาง V2.0) — กับดัก** (2026-09-24, `docs/kms/21` §11, ADR `docs/kms/decisions/2026-09-24-rd-wht-file-export.md`):
  - **ไม่ใช่ไฟล์อัปโหลด e-Filing** — e-Filing รับ .rdx/.xml เท่านั้น "ไฟล์ .txt จะไม่สามารถนำมา upload ได้"; ไฟล์นี้นำเข้าโปรแกรม SWC-UI ของกรมเพื่อตรวจ/แปลง — ห้ามเขียนใน UI/เอกสารว่าอัปโหลดตรงได้
  - **สาขา 6 หลัก** (`000000` = สำนักงานใหญ่) ทั้งหัวแบบและบรรทัด D ขณะที่แบบกระดาษ/ระบบใช้ 5 หลัก — เติม 0 หน้า; สาขาในบรรทัด D คือสาขาของ **ผู้จ่ายเงินได้** (เรา)
  - **UTF-8 มี BOM**, คั่นด้วย pipe, CRLF ระหว่างบรรทัด, **ไม่มี CRLF หลังบรรทัดสุดท้าย** (ตามไฟล์ตัวอย่างทางการ — ทดสอบทีละ byte ด้วย `BC_RDFILE_SAMPLE_ZIP`); BFF ต้องส่งผ่านทุก byte
  - **อักขระต้องห้ามข้อ 10** (ดอกจัน บวก ทับ ทับกลับ อัศเจรีย์ ดอลลาร์ เปอร์เซ็นต์ ชาร์ป แอมเปอร์แซนด์ แอต คอมมา อัญประกาศ) — บล็อกพร้อมบอกแถว/ช่อง/อักขระ ห้ามแทนที่เงียบ ๆ; ชื่อบริษัทที่มีคอมมา/`&` ต้องให้ผู้ใช้แก้ในทะเบียน
  - **TOT_NUM = จำนวนบรรทัด D** ("หากไม่มีระบุ 0"): ไม่มีใบแนบ + ยอดศูนย์ทุกช่อง = ยื่นหัวแบบอย่างเดียวได้; ไม่มีใบแนบแต่มียอด = ผิด; ยอดรวมหัวแบบคำนวณใหม่จากบรรทัด D ด้วย decimal (ภ.ง.ด.2 นับเฉพาะรายการแรกของบรรทัด)
  - ปีในชื่อไฟล์/TAX_YEAR/วันที่จ่ายเป็น **พ.ศ.**; ทศนิยมเกิน 2 ตำแหน่ง/ยอดติดลบ = ผิด ห้ามปัด; ความยาวนับเป็นตัวอักษร (rune); ตัดช่องว่างหัวท้ายทุกช่อง
  - ไฟล์สร้างจาก **ฉบับที่บันทึกแล้ว** (`tax_filings` id+version) เท่านั้น และห้าม log เนื้อไฟล์ (มีเลขบัตรประชาชน)
- **ล้างรายการภาษีของใบที่ผ่านบัญชีแล้ว = ส่ง `[]`** (reconcile + เหตุผล) — ไม่ส่งคีย์ = คงเดิม; audit `withholding_replace`/`vat_replace` เก็บ `after: []` (`backend/internal/generalledger/subledger_reconcile.go`)
