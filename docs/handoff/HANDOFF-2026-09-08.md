## 1. สิ่งที่ทำวันนี้

เทียบเมนู BC กับ FlowAccount + PEAK **2 รอบ**: รอบแรกจากหน้าเว็บทางการ (411 ฟีเจอร์) เพิ่ม 15 + 18 รายการ → 218; รอบสองตามที่ลุงจืดสั่งให้ "หาตามโซเชียลและที่อื่นๆ" กวาด 12 มุมนอกเว็บทางการ (คู่มือผู้ใช้ ศูนย์ช่วยเหลือ YouTube กลุ่ม Facebook Pantip/บล็อกรีวิว หน้าราคา release note) ได้ข้อกล่าวอ้าง 442 → ฟีเจอร์ไม่ซ้ำ 434 → ผู้เข้าชิง 59 → **ช่องว่างจริง 3 เรื่อง** เพิ่มอีก 6 รายการ → รวม **224** รายการ

ของใหม่รอบสอง: **ภ.ง.ด.2** (ยืนยันกับกรมสรรพากร efiling.rd.go.th — เป็นภาษีหัก ณ ที่จ่าย 40(3)/(4) ไม่ใช่เงินเดือน), **กำไรขาดทุนตามสาขาและแผนก**, **ดึงคำสั่งซื้อจากร้านค้าออนไลน์** และกลุ่ม **เชื่อมข้อมูลตลาดออนไลน์** ที่ต่อสายให้ 3 จอ marketplace ซึ่งเขียนเสร็จแล้วแต่เข้าไม่ถึงมาตลอด

> อย่าเขียนว่า "ครบ 100%" อีก — รอบแรกสรุปแบบนั้นจากเว็บทางการอย่างเดียว แล้วรอบสองก็ยังเจอช่องว่างเพิ่ม

- รายละเอียด + ตารางว่าอะไรครอบคลุมแล้ว: `docs/kms/19-menu-coverage-flowaccount-peak.md`
- เหตุผลเชิงตัดสินใจ: `docs/kms/decisions/2026-09-08-menu-parity-flowaccount-peak.md`
- หลักฐานฝั่งคู่แข่ง (ของเดิมที่ AI ตัวอื่นทำไว้): `docs/features-flowaccount-peak/`
- วิธีเพิ่มเมนู (4 จุดที่ต้องแก้พร้อมกัน): `docs/skills/ui-scale-polish/SKILL.md` §8 (+ §8.1 จอกำพร้า)

## 2. ขอบเขตที่ "ตัดออก" — ห้าม AI ตัวไหนเพิ่มกลับเอง

| เรื่อง | สถานะ | เหตุผล |
|---|---|---|
| ระบบเงินเดือน (payroll run, สลิปเงินเดือน, ส่งไฟล์ธนาคารเงินเดือน) | **ไม่ทำ** (ลุงจืดสั่ง 2026-09-08) | ไม่อยู่ในขอบเขตผลิตภัณฑ์ |
| แบบยื่น ภ.ง.ด.1 / ภ.ง.ด.1ก | **ไม่ทำ** | เป็นผลจากเงินเดือน ไม่มีข้อมูลต้นทาง |
| ไฟล์นำส่งเงินสมทบประกันสังคม (สปส.) / กท.20 ก | **ไม่ทำ** | เหตุผลเดียวกัน |

ของที่ยังทำอยู่และอย่าสับสน: ภาษีหัก ณ ที่จ่ายของคู่ค้า (ภ.ง.ด.3/53 + 50 ทวิ), **ภ.ง.ด.2** (เงินได้ 40(3)/(4) ต้นทางคือรายการจ่ายเงิน), "เงินทดรองจ่ายพนักงาน" (การเงิน ไม่ใช่เงินเดือน), ทะเบียนพนักงาน `/employee` ที่อยู่ทั้งในเมนูข้อมูลหลัก › บุคลากรและผู้ใช้งาน (`frontend/src/lib/menu-data.ts:376`) และใน workspace wizard (`frontend/src/app/workspace/workspace-screen.tsx:106`)

การลบครั้งนี้กวาดถึง language key `payroll`, `employee_payroll`, `payroll_run`, `payroll_slip`, `vat_pnd1`, `sso_contribution_file` ใน `backend/assets/language/languages.tsv` แล้ว

## 3. งานค้างที่ทำต่อได้ทันที

1. **จอจริงของเมนูใหม่** — เมนูที่เพิ่มรอบนี้ 39 รายการ (185 → 224) มีจอจริงแล้วเพียง 8 รายการ (`/employee`, `/user`, `/permissiongroup`, `/useraccessaudit` ผ่านหน้าตั้งค่าองค์กร และ `/line-oa`, `/marketplace/shopee|lazada|tiktok`) อีก **31 รายการยังชี้ route ที่ไม่มีจอ** จึงตกลงการ์ด "Flutter route เดิม" (`frontend/src/app/menu/main-menu-screen.tsx:2787-2815`) ถ้าจะทำจอ ให้ทำทีละใบตามกฎ UI ใน `AGENTS.md` + skill
2. **คำถามที่ต้องได้คำตอบก่อนลงรายละเอียด** (อยู่ใน `docs/kms/18-decisions-and-agreements.md` §คำถาม): taxonomy XBRL ของกรมพัฒนาธุรกิจการค้า, รูปแบบไฟล์โอนเงินของธนาคารที่จะรองรับ, ระดับการอนุมัติรายจ่าย (ผู้อนุมัติเดียว vs หลายขั้น/วงเงิน), เทมเพลตนำเข้าเอกสารจากแพลตฟอร์มไหน
3. **จอ marketplace ใช้ได้แล้ว** — `frontend/src/app/menu/marketplace-screen.tsx` เปิดผ่านเมนู "เชื่อมข้อมูลตลาดออนไลน์" ได้จริง (ตรวจแล้วเปิดจอจริงไม่ใช่การ์ด placeholder) ส่วน `/report/vatpnd2`, `/report/dimensionpnl`, `/transaction/marketplaceorder` ยังไม่มีจอ
7. **ก่อนเพิ่มเมนูรอบหน้า ให้เช็ค "จอกำพร้า" ก่อน** — วิธี comm ระหว่าง route ในจอกับ route ในเมนูอยู่ใน `docs/kms/19-menu-coverage-flowaccount-peak.md` ท้ายไฟล์
4. **คำแปล 12 ภาษาของ key ใหม่** เขียนด้วย AI ยังไม่มีเจ้าของภาษาตรวจ (th/en ตรวจแล้ว)
5. **backend image ยังไม่มี key ใหม่** จนกว่าจะ rebuild — ตอนนี้ frontend fallback เป็นป้ายไทยในโค้ดจึงแสดงถูกอยู่แล้ว
6. งานค้างฝั่ง backend (projection drift ของ debtor/creditor/erp_user, DLQ log-only, busy-poll, ClickHouse ถอดถาวรหรือไม่) ยังเหมือนเดิมใน `HANDOFF-2026-09-06.md` §4
