## 2. งานที่ต้องทำต่อ — เรียงตามความสำคัญ

### P1 — ข้อมูลที่ backend ยังให้ไม่ได้ (ทำให้จอยังไม่ครบ)

1. **ไม่มีที่เก็บภาษีหัก ณ ที่จ่าย (WHT)** — ภ.ง.ด.2/3/53 และ 50 ทวิ ยังไม่มีตารางใน PostgreSQL เลย จอจึงขึ้น "ยังไม่เปิดใช้งาน" ต้องออกแบบ schema + consumer ก่อน แล้วค่อยทำ API
2. **`branchno` ในรายงานภาษีจะว่างเสมอ** — Kafka consumer ไม่เคยเขียนคอลัมน์ `branchnumber` ลง PostgreSQL (พบโดย subagent ที่ทำ API ภาษี) ต้องแก้ที่ consumer ไม่ใช่ที่รายงาน
3. **รายงานภาษีครอบทุกบริษัทใน holding** — ตารางต้นทางไม่มีคอลัมน์ `businesscode` ให้กรอง ถ้า holding มีหลายบริษัทจะได้ยอดรวมเกินจริง **เรื่องนี้กระทบความถูกต้องของแบบยื่นภาษี ต้องแก้ก่อนใช้งานจริง**
4. **`vattype` ตีความไม่ได้** — subagent ใช้ `vatrate` + `totalvatvalue` แทน ต้องยืนยันกับข้อมูลจริงว่าแยก zero-rated/exempt ถูกหรือไม่
5. **รายงานอีก 22 ตัวไม่มี endpoint** — ที่ต้องทำก่อนคือ AR/AP aging, สรุปยอดซื้อ, ยอดขายรายวัน/รายพนักงาน (มีตารางใน PG อยู่แล้ว เขียน query ได้เลย)
6. **เครื่องมืออีก 10 ตัวไม่มี endpoint** — `processstockcalccost` มีอยู่แต่บังคับส่ง `itemcodelist` อย่างน้อย 1 รายการ ถ้าจะทำปุ่ม "คำนวณทั้งระบบ" ต้องเพิ่มโหมด all-items ที่ backend
7. **`/gl/reprocess` ถูกปฏิเสธโดยตั้งใจที่ backend** (`processes.go:46` — "เอกสารซื้อขายเดิมยังไม่มีจำนวนเงินต้นฉบับแบบทศนิยมแม่นยำ") จอจึงไม่ผูกไว้ **อย่าไปผูกกับ action `recalculate` แทนเพราะคนละความหมาย**

จอทั้ง 5 ที่แก้รอบนี้ยังใช้แพตเทิร์น `language === "th" ? ... : ...` ตามของเดิมในไฟล์ (รองรับแค่ 2 ใน 13 ภาษา) — ผิดกฎ i18n 2026-09-14 ที่ต้องใช้ `backendText()` + key

- **ยังไม่ได้ทดสอบบนเบราว์เซอร์จริง** ทั้ง 5 จอ เพราะหน้า login ไม่มีปุ่ม Demo/Dev Login แล้ว และ AI ห้ามกรอกรหัสผ่าน → ลุงจืดต้อง login เองที่ `localhost:3000` แล้วเปิดจอภาษี/รายงาน/เครื่องมือ/อนุมัติเพื่อดูของจริง

## 4. หมายเหตุจาก subagent ที่แก้ fixedasset

- ไม่ได้แตะ `languages.tsv` เพราะ `fixedasset/httpapi.fail()` ไม่เคยเรียก `language.Text()` เลย ถ้าใส่ key โดยไม่ทำ resolver ผู้ใช้จะเห็น key ดิบ → ต้องเปิดงานแยกเพื่อ thread `lang` เข้าโมดูลนี้ทั้งชุด (27 จุดข้อความไทย hardcode)
- การโพสต์ค่าเสื่อมราคาจะ **fail ถ้ากิจการยังไม่ตั้งงวดบัญชี/ผังบัญชีใน GL** — เป็นพฤติกรรมที่ถูกต้อง (เคารพด่านตรวจ) แต่เป็น dependency ใหม่ที่ฝ่ายปฏิบัติการต้องเตรียมข้อมูลก่อน
- `gl.Line` ไม่มีฟิลด์สาขาต่อบรรทัด สาขาอยู่ระดับ journal เท่านั้น ถ้าต้องการ GL แยกสาขาต่อบรรทัดต้องเป็นงานแยก
