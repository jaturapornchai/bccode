### 2.2 ลบเอกสารแล้วยังค้างใน read model ของ PostgreSQL

ลบผ่าน `DELETE /transaction/sale-invoice/<guidfixed>` เอกสารหายจาก MongoDB จริง แต่แถวใน PG (`doc`, `stock_ledger`) ยังอยู่ → รายงานยังนับยอดที่ลบไปแล้ว
เริ่มที่ consumer ฝั่ง delete ใน `backend/internal/goapi/handlers/kafka/` (ดูคู่กับ `sale_invoice.go` ที่เพิ่ง fix `CustCode`) — ต้องหา topic/handler ของ event ลบ แล้วลบแถวใน PG ให้ครบทุกตารางที่ projection เขียนไว้

### 2.3 ตาราง `debtor` ใน PostgreSQL ว่าง → ชื่อลูกค้าในรายงานเป็นค่าว่าง

`backend/internal/goapi/handlers/sales_report.go` join `debtor` ด้วย `doc.custcode` แล้วอ่านชื่อไทยจาก `d.names` (แก้จาก `d.name0` ที่ไม่มีคอลัมน์นี้แล้ว) — query ถูกแล้ว แต่ **ตาราง `debtor` ไม่มีแถวเลย** เพราะไม่มี projection ของ master ลูกหนี้
ต้องทำ projection master (MongoDB `debtor` → PG `debtor`) ตามกฎ 2-tier ใน AGENTS.md; `POST /product/resync` (หลัง select-shop) เป็นตัวอย่างที่ปลอดภัยของการสั่ง rebuild แบบไม่ลบอะไร
