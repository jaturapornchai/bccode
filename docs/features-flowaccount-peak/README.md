## ผลการนำไปใช้กับเมนู BC (2026-09-08)

โฟลเดอร์นี้คือ **หลักฐานฝั่งคู่แข่ง**; ผลการเทียบกับเมนูจริงของ BC และรายการที่เพิ่มเข้าโค้ดแล้วอยู่ที่ `docs/kms/19-menu-coverage-flowaccount-peak.md` (เมนู BC **224** รายการ: 185 → 200 → 218 → 224 ณ commit 098107e1) พร้อม ADR `docs/kms/decisions/2026-09-08-menu-parity-flowaccount-peak.md` และ `docs/kms/decisions/2026-09-08-menu-parity-social-sweep.md` — **ห้ามเขียนว่า BC ครบ 100% เทียบ FlowAccount/PEAK** เพราะความครบขึ้นกับชุดหลักฐานที่ใช้เสมอ

**ระบบเงินเดือน (payroll) ถูกตัดออกจากขอบเขตผลิตภัณฑ์ BC โดยลุงจืด 2026-09-08** — โฟลเดอร์นี้ตัดข้อมูล FlowPayroll / PEAK Payroll ออกทั้งหมดอยู่แล้ว (ดู `09-flowaccount-peak-menu-catalog.md` §1 หัวข้อ "ตัดออกทั้งหมด") ห้ามนำหลักฐานของคู่แข่งมาสร้างเมนู/จอ/สเปกเงินเดือน รวมถึง **ภ.ง.ด.1 / ภ.ง.ด.1ก** และ **ไฟล์นำส่งเงินสมทบประกันสังคม (สปส. / กท.20 ก)** — ส่วน **ภ.ง.ด.2** (หัก ณ ที่จ่ายเงินได้ 40(3)/(4) เช่น ดอกเบี้ย เงินปันผล ค่าสิทธิ) **ยังอยู่ในขอบเขต** เพราะมาจากรายการจ่ายเงิน ไม่ใช่เงินเดือน และมีเมนู `vat-pnd2` → `/report/vatpnd2` ในโค้ดแล้ว

## การใช้หลักฐาน

- เริ่มจาก 11/12 เมื่อต้องการชื่อเมนูและเส้นทางของแต่ละค่าย; ใช้ 09 ดูรายการรวม หรือ 03 เทียบสองค่าย
- ชื่อในตารางเป็นชื่อกลางสำหรับเทียบเคียง ไม่รับรองว่าตรง sidebar ทุกแพ็กเกจและบทบาท
- 311 เป็นรายการความสามารถรวมขั้นตอนและทางลัด ไม่ใช่จำนวนหน้าจอไม่ซ้ำ (268 ในเอกสาร 10 คือจำนวนรายการรอบค้นสเปกก่อนหน้า ไม่ใช่จำนวนหน้าจอ)
- จำนวนรายการใน 01 และ 02 ทับซ้อนกันได้ เพราะทั้งสองค่ายมีความสามารถร่วมกัน
- สิ่งที่ยังไม่ยืนยันแยกไว้ชัดเจน ไม่ถือว่าผลิตภัณฑ์ไม่มีความสามารถนั้น
- ข้อกำหนด API ต้องมีเอกสารนักพัฒนาทางการรองรับ ไม่ใช้คู่มือฟีเจอร์อนุมาน schema หรือสถาปัตยกรรมฐานข้อมูลภายใน
