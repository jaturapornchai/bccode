# ผังเมนู FlowAccount จากคู่มือทางการ

ตรวจข้อมูล: 2026-09-07 | ขอบเขต: FlowAccount, AutoKey, MobilePOS, BOQ by FlowAccount และ Partner Center เฉพาะงานธุรกิจ ไม่รวมระบบเงินเดือนและ HR

## วิธีอ่านและขอบเขตความครบ

วัตถุประสงค์คือเก็บชื่อที่ผู้ใช้พบในผลิตภัณฑ์และแยกเมนูออกจากปุ่ม/รูปแบบเอกสาร โดยเทียบกับ[รายการ FlowAccount](01-flowaccount-in-depth.md) และ[บัญชีเทียบเคียง](09-flowaccount-peak-menu-catalog.md) ฉบับก่อนตรวจรอบนี้

สำรวจหน้ารวมคู่มือครบ **25 หมวดในขอบเขตเมนูโปรแกรม** พบ **197 ลิงก์บทความในหมวด** ก่อนกรองหัวข้อประยุกต์และงานที่อยู่นอกขอบเขต ตัวเลขนี้เป็นจำนวนลิงก์ในดัชนี ไม่ใช่จำนวนเมนูและไม่ใช่จำนวนบทความที่เปิดอ่านละเอียดทุกหน้า ในตารางต่อไปมี **211 แถวผัง** บางแถวรวมตัวเลือกในหน้าเดียว จึงไม่ใช้จำนวนแถวแทนจำนวนหน้าจอ

หลักฐาน “ขั้นตอน” หมายถึงอ่านเนื้อหาที่อธิบายเส้นทางหรือคำสั่งนั้นโดยตรง ส่วน “หัวข้อคู่มือ” หมายถึงพบชื่อในดัชนีหรือคู่มือ แต่ยังไม่รับรองตำแหน่ง sidebar/แท็บและปุ่มทั้งหมด การจัดหมวดด้านล่างช่วยค้นหา ไม่ได้อ้างว่าลำดับเท่ากับ sidebar ของทุกแพ็กเกจ

ชนิด: **M** เมนูหรือหน้ารายการ, **D** ชนิดเอกสารที่ยังไม่ยืนยันว่าเป็นเมนูอิสระ, **A** ปุ่ม/คำสั่ง/วิธีทำงาน, **T** แท็บ ตัวกรอง ตารางหรือส่วนในหน้า, **R** รายงาน/มุมมอง, **S** ตั้งค่า/ตัวเลือก

การใช้งาน: เลือกหมวด → ดูเส้นทาง → เปิดลิงก์คู่มือ → ตรวจแพ็กเกจและสิทธิ์ของบัญชีจริงก่อนกำหนดรายการหน้าจอ ตัวอย่าง ใบส่งของอยู่ที่ตัวเลือกพิมพ์ จึงไม่สร้างเป็นข้อสรุปว่าเป็น sidebar แยก ข้อจำกัด: ยังไม่ได้เข้าบัญชีใช้งานจริง ไม่มีไฟล์ตั้งค่าที่ต้องใช้ และข้อมูลการเชื่อมต่อขึ้นกับการเปิดบริการของผู้ให้บริการ

## จุดที่ต้องแก้ความเข้าใจจากรายการเดิม

- **ใบส่งของ** เป็นตัวเลือกพิมพ์จากเอกสารขายที่รองรับ; คู่มือระบุ Preview / Print จึงยังไม่ยืนยันเมนูสร้างใบส่งของอิสระ
- **ใบมัดจำ** มีทางสร้างจากสถานะใบเสนอราคา ไม่ใช้หลักฐานนี้ยืนยันว่ามีหน้ารายการมัดจำแยก
- **ลดหนี้ฝั่งซื้อ** เป็นวิธีประยุกต์ค่าใช้จ่ายติดลบและเอกสารเตรียมจ่าย การคืนสต็อกปรับแยก ไม่ใช่หลักฐานว่ามีเมนูใบลดหนี้ซื้อโดยตรง
- **สินค้าบริการ/ไม่นับสต็อก/นับสต็อก** เป็นประเภทสินค้า; **หลายหน่วยนับ** มีปุ่มในหน้าสินค้าจริง ไม่จำเป็นต้องอ้างจาก API เท่านั้น
- **รายงาน**, **รายงานด้านบัญชี**, **โปรเจกต์** และ **ปิดงบบัญชี** ต้องเก็บตำแหน่งต่างกันตามคู่มือ ไม่รวมเป็นศูนย์รายงานที่สมมติขึ้น
- **KCC ส่งจ่ายผู้จำหน่ายอัตโนมัติ** และ **ดาวน์โหลดไฟล์ไปนำเข้าเอง** เป็นคนละวิธี โดยวิธีส่งอัตโนมัติรอผลธนาคารกลับมาอัปเดต ส่วนไฟล์ที่ผู้ใช้นำเข้าเองต้องอัปเดตสถานะเอง
- **เทมเพลตนำเข้าที่กำหนดเอง** ที่หน้า how_to_create_custom_template ใช้จับคู่คอลัมน์นำเข้าขายเงินสด ไม่ใช่เครื่องมือออกแบบหน้าตาเอกสาร

## ข้อจำกัดและรายการที่ยังต้องยืนยัน

1. ตำแหน่งและชื่อ sidebar ทุกบทบาท/แพ็กเกจ รวมรายการที่ซ่อนจากสิทธิ์ และความต่างระหว่างเว็บ แอปมือถือ และบทความรุ่นเก่า
2. รายงานเชิงธุรกิจทุกชื่อและตัวกรองย่อย โดยเฉพาะรายการที่อยู่ในภาพหน้าจอแต่ไม่มีชื่อในข้อความคู่มือ ไม่เติมรายงานตามการคาดเดา
3. หน้ากระทบยอดมีหลักฐานแก้ไข/ยกเลิก/บันทึกผลต่างแล้ว แต่ยังไม่ยืนยันตัวแก้กฎอัตโนมัติ Bank Rules แยกต่างหาก
4. การทำงาน offline, เปิดกะ/ปิดกะ, ลิ้นชักเงินและคืนเงินของ MobilePOS ยังไม่มีหลักฐานตรงครบ; ปุ่มของ FoodStory เป็นของบริการปลายทาง ไม่นับเป็นเมนู FlowAccount
5. คู่มือหลายหน่วยนับยังมีหัวข้อข้อจำกัด Beta ลงวันที่ 2023 ปะปนกับคำอธิบายใหม่ จึงไม่ยืนยันข้อจำกัดแพ็กเกจ/มือถือทั้งหมดว่าเป็นสถานะปัจจุบัน
6. หน้าสินค้าใกล้หมดระบุการส่งออก CSV ในบทนำและ XLSX ในขั้นตอน ให้เก็บว่า “ดาวน์โหลดรายงาน” จนตรวจรูปแบบไฟล์จริง
7. หน้า AI Connector ถูกตรวจในระดับดัชนี แต่ไม่ขยาย API/MCP เป็นรายการเมนูในเอกสารนี้ ดู[ผลค้นสเปก](10-product-spec-research.md) สำหรับข้อจำกัดที่ตรวจแยกไว้
