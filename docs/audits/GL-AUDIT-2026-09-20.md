### G1 — ผ่านรายการต้นฉบับที่กลับแล้วได้อีก ทำให้กลับซ้ำจนยอดผิด

ตำแหน่ง: [postgres_store.go:497](D:/bccode/backend/internal/generalledger/postgres_store.go:497)

คำสั่ง post ปฏิเสธเฉพาะ `posted` แต่ยอม `reversed → posted` จากนั้น reverse ได้อีกด้วยเลขเอกสารใหม่ ตัวพิสูจน์: เงินสดเดบิต 100 → กลับรายการ → post ต้นฉบับอีก → กลับอีกครั้ง ทุกคำสั่งสำเร็จ ยอดเงินสดสุทธิกลายเป็น **−100.00000000** ทั้งที่ต้นฉบับและรายการหักล้างควรเหลือ 0

ต้องยอม post เฉพาะ draft และกำหนด transition/ความสัมพันธ์ reversal ที่ service และทดสอบซ้ำด้วย request ID ใหม่ด้วย เพราะ idempotency เดิมไม่กันการกระทำนี้

## ช่องว่างจากสเปกที่ต้องแยกจากบั๊ก

สเปกกำหนดรายละเอียดลูกหนี้/เจ้าหนี้/Statement แบบ many-to-many และ dedup ด้วย source_system+source_record_id แต่ runtime Journal/Line ที่ `models.go:183–229` และ resource dispatcher ยังไม่มีข้อมูล/คำสั่งชุดนี้ การค้นใน backend GL/frontend GL พบชื่อเหล่านี้ในสเปกเท่านั้น

ดังนั้นไม่ควรนับว่า runtime รองรับตรวจยอดค้าง จัดสรรรับจ่าย จับคู่ Statement และป้องกันนำเข้าซ้ำตาม stable source ID ครบแล้ว `requestid` ป้องกัน retry คำขอเดิมได้ แต่ไม่แทน stable ID ของเอกสารต้นทางเมื่อ integration สร้าง requestid ใหม่
