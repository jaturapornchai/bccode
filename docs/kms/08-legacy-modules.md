## 1. ขอบเขตและวิธีอ่านสถานะ

บทความนี้ครอบคลุมโมดูลใต้ `backend/internal/**` ที่บทความ 03–07 ไม่ได้พูดถึง (ไม่รวม goapi, transaction, product, shop, organization, authentication, warehouse, stockprocess, systemadmin, migration, documentwarehouse, *import). หลักฐานหลักคือ `backend/main.go` (binary เดียวที่ Dockerfile ทุกตัว build: `backend/Dockerfile:21`, `backend/Dockerfile-consumer:20`, `backend/Dockerfile-migration:20`, `backend/Dockerfile.local:18`) ซึ่งแบ่งงานด้วย `DEV_API_MODE`:

| mode | block ใน main.go | บทบาท | ที่ตั้งค่า |
|---|---|---|---|
| `""` หรือ `"2"` | `backend/main.go:256` | HTTP modules (`httpServices` `backend/main.go:357-546`) + goapi (`backend/main.go:568-581`) | image default `backend/Dockerfile:41`; local compose `backend/docker-compose.yml:80`; prod `mainapi` ไม่ override (`deploy/account/compose.yml:234`) |
| `"3"` | `backend/main.go:585` | PG AutoMigrate แล้ว `return` (`backend/main.go:651`) | `backend/Dockerfile-migration:28`; prod service `migrate` `deploy/account/compose.yml:212` |
| `""` หรือ `"1"` | `backend/main.go:654` | legacy Kafka consumers → PostgreSQL | `backend/Dockerfile-consumer:29`; prod service `worker` `deploy/account/compose.yml:275`; **local compose ไม่มี service mode 1** (`backend/docker-compose.yml` มีแค่ redis/kafka/mainapi บรรทัด 31/42/63) |

นิยามสถานะในตาราง: **LIVE** = อยู่ใน `httpServices`/consumer ของ main.go และมีผู้เรียก (frontend หรือโมดูลอื่น import); **LIVE-NOFE** = register อยู่แต่ `rg` ใน `frontend/src` ไม่พบ route prefix เลย (ยังใช้ได้ผ่าน API ตรง/ระบบเก่า); **DEAD** = ไม่ถูก import จาก entrypoint ใดที่ถูก build; **STUBBED** = พึ่ง service ที่ปิดไป (ClickHouse). ผู้เรียกฝั่ง frontend ตรวจจาก `frontend/src/lib/system-setting-screens.ts` (`basePath`) ผ่าน proxy `frontend/src/app/api/system-settings/[[...settingPath]]/route.ts:137-143` และ map master ใน `frontend/src/app/api/product-barcode/master/[master]/route.ts:19-37`.

## 5. ข้อสังเกตเชิงสถาปัตยกรรม (สรุปสั้น)

1. **GL (vfgl) เป็น dual-write Mongo→Kafka→PG**: HTTP เขียน Mongo `journals` และ produce (`journal_http.go:35,39`); รายงานอ่าน PG (`journal_report_http.go:23-25`) — ถ้า worker ไม่รัน รายงานเงียบ ๆ ว่าง ไม่มี error path ที่บอกผู้ใช้ (ยังไม่ตรวจ handler รายงานทีละตัว)
2. **debtor/creditor เป็นชุดเดียวใน scope นี้ที่ทั้ง register, มี FE เรียก, มีข้อมูลจริง และมี topic จริงใน Kafka** — แต่ตาม lead: projection PG พังจาก schema drift (บทความ 05) จึงมีผลแค่ Mongo
3. **ซ้ำซ้อน 3 คู่**: `debtaccount/customer` vs `debtor`; `shopcoupon` vs `coupon`; `report/reportqueryc` vs `reportquerym` — ทั้งคู่หลังเป็น DEAD อยู่แล้ว
4. **external hard-code**: OCR ชี้ `manager.ztrus.com` ใน source (`ocr_service.go:28`) ไม่ผ่าน bootstrap/env
5. `member.NewMemberHttp` ถูกใส่ใน `httpServices` สองครั้ง (`backend/main.go:363,541`) — Echo จะ register route ซ้ำ (ผลจริงยังไม่ตรวจ)
