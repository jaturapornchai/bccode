# เลขที่ใบสำคัญรันอัตโนมัติแบบ Champ + หัวใบสำคัญเรียงตาม Champ

## Context
ลุงจืดสั่ง 2026-10-07 "ออกแบบใหม่ให้ Champ เป็นหลัก ให้เหมือนกันแทบทุกอย่าง" — จอบันทึกสมุดรายวันของ BC ให้ผู้ใช้พิมพ์เลขที่เองทุกใบ บังคับคำอธิบาย และมีช่องปีบัญชีให้เลือก ขณะที่ Champ (`docs/kms/champ/09-gl.md` §2.3, §2.11):
- รันเลขที่ให้ใบใหม่ด้วยรูปแบบ `YYMM-@#####` (`BRunningBttn.cpp`): YY = ปี พ.ศ. 2 หลัก, @ = รหัส, # = เลขรัน, เลขถัดไป = MAX+1 ในคำนำหน้าเดียวกัน
- หัวเอกสารเรียง สมุดรายวัน → เลขที่ → วันที่ → เลขที่อ้างอิง → วันที่อ้างอิง → หมายเหตุ (ไม่บังคับ)
- สมุดรายวันมี `TitleName` = หัวใบสำคัญที่พิมพ์ (เช่น ใบสำคัญจ่าย); ปุ่มบันทึก = F11

## Decision
- รูปแบบเลขที่ (`docformat`, ≤ 20 ตัว ต้องมี `#`) และหัวเอกสาร (`titlename`) เก็บที่ **สมุดรายวัน** — ว่าง = `@YYMM-####` (`backend/internal/generalledger/journal_docno.go`)
- ใบใหม่ที่เว้นเลขที่ไว้ backend ออกเลขใน `sql.Tx` ของคำสั่งบันทึก (ถือ `lockCompany` อยู่แล้ว จึงไม่ชนกัน); เลขที่พิมพ์เองเก็บตามที่พิมพ์; ใช้ **วันที่เอกสาร** (ไม่ใช่วันนี้แบบ Champ) เพื่อให้ใบที่คีย์ย้อนหลังได้เลขของเดือนตัวเอง; ฉบับร่างที่ลบ (soft delete) ยังกันเลขไว้ ไม่นำกลับมาใช้
- จอแสดงเลขถัดไปเป็นตัวอย่างจาก `GET /gl/v2/journal-next-docno?bookcode=&from=` (อ่านอย่างเดียว เลขจริงออกตอนบันทึก)
- หัวใบสำคัญเรียงตาม Champ, เพิ่ม `refdate` (ตรง `mydocs/datamodels/gl/gltrans.sql` `ref_date`), หมายเหตุไม่บังคับ (`description` nullable ใน gltrans.sql), ซ่อนช่องปีบัญชี (คำนวณจากวันที่), F11 = บันทึก, Enter ในหัวเอกสารเลื่อนช่อง

## Alternatives
- ผูกรูปแบบกับ "หน้าจอ + กลุ่มเอกสาร" แบบ Champ — BC ไม่มีกลุ่มเอกสารแยก สมุดรายวันทำหน้าที่นั้นอยู่แล้ว (**ต้องให้ลุงจืดยืนยัน**)
- ออกเลขที่ frontend — ชนกันเมื่อหลายคนบันทึกพร้อมกัน และผิดกฎ backend-first
- ตารางตัวนับแยก — MAX+1 จาก `gl_records` ตรงกับ Champ และไม่ต้องดูแลตัวนับ (ใบเยอะมากค่อยพิจารณา index)

## Consequences
- `journal_books` ใน `mydocs/datamodels/gl/journalbook.sql` ยังไม่มีคอลัมน์ `doc_format`/`title_name` — โค้ดเก็บใน payload JSON ไปก่อน; ถ้าลุงจืดไม่ต้องการ ให้ถอดสองช่องนี้
- เลขที่ยาวได้ 30 ตัว (ตาม `doc_no VARCHAR(30)`) ไม่ใช่ 20 แบบ Champ; รูปแบบยาวเกินจนเลขเกิน 30 ตัว → ข้อความ `journal_docno_auto_too_long`
- ทดสอบ: `journal_docno_test.go`, `journal_docno_integration_test.go`, `use-form-shortcuts.test.ts`, `general-ledger.test.ts`
