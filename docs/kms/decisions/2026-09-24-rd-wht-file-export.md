# ไฟล์ยื่นภาษีหัก ณ ที่จ่ายด้วยสื่อ = ไฟล์ .txt Format กลาง V2.0 สำหรับโปรแกรม SWC-UI (ภ.ง.ด.53/3/2 รายเดือน)

## Context

- ลุงจืดสั่งให้ทำไฟล์ยื่นภาษีหัก ณ ที่จ่ายจากแบบที่บันทึกในระบบ (หมวดภาษีอยู่ใน GL ตาม ADR `2026-09-23-tax-inside-general-ledger.md`) เพื่อไม่ต้องคีย์ใบแนบซ้ำในโปรแกรมของกรมสรรพากร
- ช่องทางของกรมสรรพากรที่ตรวจแล้ว 2026-09-24 (รหัสแหล่งตาม `docs/kms/21-thai-tax-form-references.md` §1):
  - **ไฟล์ Format กลาง V2.0** (RD-FMT-V2, ปรับปรุง 16/06/2568) + ไฟล์ตัวอย่าง (RD-SWC-SAMPLE) — นำเข้าโปรแกรม SWC-UI ของกรม ซึ่งตรวจและแปลงเป็นไฟล์สำหรับยื่น (RD-SWC-MANUAL, RD-WHT-PORTAL)
  - **e-Filing อัปโหลดไฟล์ตรง** — FAQ ของ e-Filing (RD-EFILING-FAQ): ไฟล์ .txt อัปโหลดไม่ได้ รับเฉพาะ .rdx/.xml
  - **RD Prep** (RD-PREP) — โปรแกรมของกรมที่นำเข้า .txt/.csv แล้วผู้ใช้จับคู่คอลัมน์เองก่อนแปลงเป็น .rdx
  - **.rdx** — กรมไม่ได้เผยแพร่โครงสร้างไฟล์
  - **XML บน e-Filing** — ปุ่มยังปิดใช้งาน และ FAQ ระบุว่ายังไม่ได้ประกาศ
  - **Open API ของ e-Filing** (RD-OPENAPI) — ต้องยื่นขอเชื่อมต่อและได้รับอนุมัติจากกรม
- โปรเจกต์ยึด Champ เป็นต้นแบบ แต่ไฟล์ยื่นภาษีเป็นข้อบังคับทางภาษีที่ลุงจืดสั่งเป็นคำ ๆ จึงไม่ติดกฎ Zero-Bloat; ไม่เพิ่มเมนูใหม่ — เป็นแผงในจอกรอกแบบเดิม

## Decision

1. **ทำไฟล์ .txt Format กลาง V2.0 สำหรับ SWC-UI** เฉพาะ **ภ.ง.ด.53 / ภ.ง.ด.3 / ภ.ง.ด.2 รายเดือน** — endpoint `POST /api/report/tax/form/rdfile` (`backend/internal/goapi/bootstrap.go:365`), handler `backend/internal/goapi/handlers/tax_rdfile.go`, ตัวเขียน/ตัวตรวจ `backend/internal/rdfile/` (ไม่แตะ DB ไม่มีตรรกะภาษี); ปุ่ม/แผงในจอกรอกแบบ `frontend/src/app/tax/tax-rdfile-panel.tsx` แสดงเฉพาะแบบที่ backend ติดธง `meta.rdfile`
2. **แหล่งข้อมูล = ฉบับที่บันทึกแล้ว** ใน `tax_filings` (id + version ต้องตรง) คำนวณยอดรวมใหม่ด้วย `prepareTaxDocument` และหัวแบบจากทะเบียนบริษัทแบบเดียวกับ PDF — ไฟล์จึงตรงกับกระดาษที่ผู้ใช้ตรวจแล้ว (รวมฐานภาษีที่แก้); ไม่รับเอกสารจาก browser; ห้าม log เนื้อไฟล์ (มีเลขบัตรประชาชน)
3. **ค่าเริ่มต้นที่เลือก (ลุงจืดสั่งทำ ให้ AI เลือกค่าเริ่มต้นตามเอกสารทางการ)**:
   - SENDER_ROLE = `1` (ผู้มีหน้าที่หักยื่นเอง) เท่านั้น — ไม่ทำกรณีตัวแทน/สำนักงานบัญชียื่นแทน
   - อักขระต้องห้ามตามข้อ 10 ของ Format (รวม pipe และอัญประกาศโค้ง) **บล็อกพร้อมบอกแถว/ช่อง/อักขระ ไม่แทนที่เงียบ ๆ**; ยอดติดลบและทศนิยมเกิน 2 ตำแหน่ง **บล็อก ไม่ปัด**
   - คำนำหน้าว่างใน ภ.ง.ด.3 = ข้อผิด (Format ให้ใส่ `-` — ผู้ใช้พิมพ์เอง ระบบไม่เติม)
   - ACC_NO ของ ภ.ง.ด.2 ส่งตามที่กรอก บังคับเฉพาะเงินปันผล (รหัส 3) เพราะรหัส 2 รวมดอกเบี้ยที่ไม่ใช่เงินฝาก — ไม่เดาจากชื่อรายการ
   - ใส่ BOM และไม่มี CRLF หลังบรรทัดสุดท้าย (ตรงไฟล์ตัวอย่างทางการ ทดสอบทีละ byte ด้วย `BC_RDFILE_SAMPLE_ZIP`)
   - สาขา 5 หลักบนแบบ → 6 หลักในไฟล์ (`000000` = สำนักงานใหญ่); DEPT_NAME ว่าง + สำนักงานใหญ่ → `สำนักงานใหญ่`; ครั้งที่ส่งเริ่มต้น `00`
   - ฉบับที่ไม่มีใบแนบและยอดทุกช่องเป็นศูนย์ = ยื่นหัวแบบอย่างเดียว (TOT_NUM `0` ตาม H18); ไม่มีใบแนบแต่มียอด = ข้อผิด `tax_rdfile_no_rows`
4. **ตรวจทุกข้อก่อนเขียน** (`rdfile.Check` รวบรวมทุกจุดผิด ไม่หยุดที่ข้อแรก) → 400 `tax_rdfile_invalid` + รายการ `issues` (ไม่เกิน 100) ข้อความตามภาษาผู้ใช้ผ่าน key `tax_rdfile_*` ใน `languages.tsv`; ผ่านแล้ว 200 เป็นไฟล์แนบ `text/plain; charset=utf-8`, `Cache-Control: no-store`
5. **จอบอกชัดว่าไฟล์นี้ไม่ใช่ไฟล์อัปโหลด e-Filing** — ขั้นตอนคือ นำเข้า SWC-UI → ตรวจ/แปลง → อัปโหลดผลลัพธ์ที่ e-Filing
6. ตาราง mapping ช่อง H/D ↔ ข้อมูลในระบบ และกับดักทั้งหมด: `docs/kms/21-thai-tax-form-references.md` §11

## Alternatives

- **อัปโหลด .txt เข้า e-Filing ตรง** — ทำไม่ได้: e-Filing ปฏิเสธ .txt (RD-EFILING-FAQ)
- **ทำไฟล์ .rdx เอง** — ไม่เลือก: กรมไม่เผยแพร่โครงสร้าง ต้องเดา = ขัดกฎ NO MAGIC
- **ไฟล์ XML สำหรับ e-Filing** — ไม่เลือกตอนนี้: ยังไม่ประกาศ/ปุ่มยังปิด
- **ส่งผ่าน Open API ของ e-Filing** — ไม่เลือกตอนนี้: ต้องขออนุมัติจากกรม (ผู้ให้บริการหรือนิติบุคคลส่งข้อมูลของตัวเอง) และเป็นการยื่นแบบแทนผู้ใช้ = R0 ต้องให้ลุงจืดตัดสิน
- **ไฟล์ .csv สำหรับ RD Prep** — ไม่เลือก: ผู้ใช้ต้องจับคู่คอลัมน์เองทุกครั้ง ส่วน SWC-UI อ่าน Format กลางได้โดยตรง
- **ภ.ง.ด.2ก / ภ.ง.ด.3ก / ภ.พ.30 ยื่นรวม / ภ.พ.36** — เลื่อน: 3ก ยังไม่มีในแคตตาล็อกแบบและบังคับที่อยู่; ภ.พ.30 ยื่นรวมใช้ RD Prep และเฉพาะผู้ได้อนุมัติ ภ.พ.02; ภ.พ.36 ไม่มีช่องทางไฟล์ — รอลุงจืดสั่ง
- **ภ.ง.ด.1/1ก** — ไม่ทำ: นอกขอบเขต (ไม่ทำระบบเงินเดือน)

## Consequences

- ผู้ใช้ยังต้องติดตั้งและใช้ SWC-UI ของกรม — ระบบลดงานคีย์ใบแนบ แต่ไม่ได้ยื่นแบบให้
- ถ้ากรมออก Format เวอร์ชันใหม่ ต้องตรวจเอกสารใหม่แล้วแก้ `backend/internal/rdfile/` (ลำดับช่องอยู่ที่เดียว) พร้อมเทียบไฟล์ตัวอย่างชุดใหม่
- ข้อมูลที่ Format ต้องการแต่ระบบไม่เก็บ: TIN 10 หลักแบบเดิม (ส่ง `0000000000` ตาม Format), ที่อยู่ละเอียดของผู้มีเงินได้ (ส่งเฉพาะอำเภอ/จังหวัด/รหัสไปรษณีย์ของ ภ.ง.ด.3)
- เลขประจำตัว 13 หลักทุกช่องต้องผ่านหลักตรวจสอบ mod 11 (§12 ของ kms/21 — สูตรยังไม่มีเอกสารทางการระบุ)
