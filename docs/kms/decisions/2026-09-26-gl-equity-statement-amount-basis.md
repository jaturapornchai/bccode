# งบการเปลี่ยนแปลงส่วนของผู้ถือหุ้น (แบบ 2) + ยอดที่แถวใช้ (ต้นงวด/ปลายงวด/ความเคลื่อนไหว)

ต่อจาก ADR `2026-09-26-gl-statements-backend-comparative.md` (งบคำนวณที่ backend + คอลัมน์ปีก่อน)

## Context

- **งบการเปลี่ยนแปลงส่วนของผู้ถือหุ้น** เป็นงบที่บริษัทจำกัดต้องจัดทำ: ประกาศกรมพัฒนาธุรกิจการค้า เรื่อง กำหนดรายการย่อที่ต้องมีในงบการเงิน พ.ศ. 2566 **แบบ 2** หน้า 2-21 (ทะเบียน `DBD-FS-2566` ใน `docs/kms/21-thai-tax-form-references.md`) และ TFRS for NPAEs ย่อหน้า 4.1 — ระบบยังไม่มี; Champ ก็ไม่มี (มีแค่ตัวออกแบบงบทั่วไป เมนู 5505)
  - แบบ 2 หน้า 2-21: คอลัมน์ = ทุนที่ชำระแล้ว, ส่วนเกินมูลค่าหุ้น, ส่วนเกิน (ต่ำกว่า) ทุนอื่น, กำไร (ขาดทุน) สะสม, ส่วนได้เสีย - ทุนอื่น, องค์ประกอบอื่นของส่วนของผู้ถือหุ้น, รวมส่วนของผู้ถือหุ้น (+ หมายเหตุ); แถว = ยอดต้นงวด → ผลกระทบการเปลี่ยนนโยบายบัญชี → การแก้ไขข้อผิดพลาด → ยอดที่ปรับปรุงแล้ว → การเปลี่ยนแปลงระหว่างปี 5.1–5.7 (หุ้นบุริมสิทธิ, หุ้นสามัญ, ส่วนเกินทุนอื่น, เงินปันผลจ่าย, กำไร (ขาดทุน) สุทธิ, โอนไปกำไรสะสม, องค์ประกอบอื่น) → ยอดปลายงวด; ซ้ำชุดสำหรับปีก่อนและปีปัจจุบัน
  - ระบบไม่รู้เองว่าบัญชีไหนเป็นทุนชำระแล้ว หรือรายการไหนเป็นเงินปันผล — **ห้ามเดาจากรหัส/ชื่อบัญชี** (กฎโปรเจกต์)
- **แม่แบบงบต้นทุนขาย/งบกระแสเงินสดเดิมผิดหลัก**: แถว "ต้นงวด/ปลายงวด" และ "การเปลี่ยนแปลงในลูกหนี้/สินค้า/เจ้าหนี้" ใช้ยอดคงเหลือ (งบชนิด `cash_flow` ไม่ใช่งบช่วงเวลา) หรือความเคลื่อนไหว (งบต้นทุน) เหมือนกันทุกแถว — ไม่มีทางบอกว่าแถวไหนต้องใช้ยอดต้นงวด

## Decision

1. **`amountbasis` ต่อแถวบัญชี** (`StatementRow.AmountBasis`): ว่าง = ตามประเภทงบ (งบช่วงเวลา `pnl`/`production_cost`/`cash_flow`/`equity` ใช้ความเคลื่อนไหว, ที่เหลือใช้ยอดคงเหลือ) · `opening` = ยอดต้นงวด (ยอดยกมา + รายการก่อนวันเริ่มงวด) · `closing` = ยอดปลายงวด · `movement` = ความเคลื่อนไหวในงวด (ไม่นับยอดยกมา/ปิดบัญชี) · `other` เฉพาะงบส่วนของผู้ถือหุ้น — SQL เดียวเดิมบน `gl_lines` เพิ่มคอลัมน์ยอดต้นงวด (`statements.go`)
2. **งบชนิด `equity`** (`statements_equity.go`):
   - `Master.Columns []StatementColumn{id,title,accountcodes}` = องค์ประกอบส่วนของผู้ถือหุ้น **ผู้ใช้เลือกบัญชีเอง**; คอลัมน์ที่ยังไม่เลือกบัญชีไม่แสดง (ประกาศข้อ 7 รายการที่ไม่มีไม่ต้องแสดง); ไม่มีคอลัมน์ใดเลย = error
   - คำนวณทีละคอลัมน์: แถว `opening`/`closing` = ยอดต้น/ปลายงวดของบัญชีในคอลัมน์ (ไม่ต้องเลือกบัญชีที่แถว), แถวความเคลื่อนไหว = บัญชีของแถว ∩ บัญชีของคอลัมน์, แถว `other` = ปลายงวด − ต้นงวด − ทุกแถวความเคลื่อนไหว → **ต้นงวด + ทุกบรรทัด = ปลายงวด เสมอ**; คอลัมน์ "รวม" = ผลรวมคอลัมน์
   - ปีเปรียบเทียบ (`comparisontype: previous_year`) = ชุดแถวซ้ำ ปีก่อนก่อนแล้วปีปัจจุบัน (เรียงตามแบบ 2), `{year}` ในชื่อแถวแทนด้วยรหัสปีบัญชี, แถวมี `block` (`prioramount`/`amount`)
   - กำไรที่ยังไม่ปิดบัญชี (`__current_earnings__`) ใส่ในคอลัมน์กำไรสะสม (ติ๊ก "รวมกำไร (ขาดทุน) ที่ยังไม่ปิดบัญชี") → รายการปิดบัญชีหักล้างในคอลัมน์เดียว ใช้ได้ทั้งก่อนและหลังปิดบัญชี
   - คำเตือน (ไม่เงียบ): บัญชีอยู่หลายคอลัมน์/หลายบรรทัด, บัญชีของบรรทัดไม่อยู่ในคอลัมน์ใด, ไม่มีคอลัมน์ใดรวมกำไรที่ยังไม่ปิด, มียอดที่ไม่อยู่ในบรรทัดใดแต่ไม่มีแถว `other`, รายการปิดบัญชีไม่หักล้างในคอลัมน์
3. **แม่แบบ**: `EQ-DBD` ตามแบบ 2 (6 คอลัมน์, คอลัมน์กำไรสะสมรวมกำไรที่ยังไม่ปิด, แถว 5.5 = กำไรที่ยังไม่ปิด, แถว "รายการอื่นที่ยังไม่ได้จัดประเภท", แถวปลายงวด = `closing`); `COGS-STMT` ต้นงวด/ปลายงวดใช้ `opening`/`closing`; `CASH-FLOW-IND` แถวการเปลี่ยนแปลงใช้ความเคลื่อนไหว + เพิ่มแถว 170 เงินสดต้นงวด (`opening`) และ 180 เงินสดปลายงวด = R160 + R170; ทุกแม่แบบตั้งเปรียบเทียบปีก่อน
4. **จอ** (`gl-statement-designer.tsx`): กล่อง "คอลัมน์องค์ประกอบส่วนของผู้ถือหุ้น" (ชื่อ + เลือกบัญชี + ติ๊กรวมกำไรที่ยังไม่ปิด + ลบ), ช่อง "ยอดที่ใช้" ทุกแถวบัญชี, บันทึก `columns`; หน้าพิมพ์ (`GLStatementTable`) หัวคอลัมน์ตัดบรรทัดได้ เว้นบรรทัดระหว่างชุดปี และงบที่มียอดเงินเกิน 3 คอลัมน์พิมพ์ A4 แนวนอน (`statementOrientation`)
5. ป้ายหน่วย "(หน่วย: บาท)" ให้ตรงกับที่ sanitizer ของ dictionary แสดงจริง (ตัดช่องว่างหน้า ":")

## Alternatives considered

- **จับคู่บัญชีเข้าคอลัมน์จากประเภท/รหัส/ชื่อบัญชีอัตโนมัติ** — ห้าม (ผังบัญชีแต่ละกิจการต่างกัน; กฎไม่ใช้รหัส/ชื่อบัญชีเป็นเงื่อนไข)
- **ใช้ `kind` ของรายการรายวันแยกเงินปันผล/เพิ่มทุน** — ระบบไม่มี kind เหล่านี้ และต้องให้ผู้ใช้เลือกตอนบันทึกทุกครั้ง (เพิ่มงานหน้าบ้าน ไม่ใช่งานห้องบัญชี)
- **สูตรปลายงวด = ต้นงวด + ผลรวมบรรทัด** — ตัวเลขลงตัวเสมอแม้ตั้งค่าผิด; เลือกใช้ยอดปลายงวดจริง + แถว `other` + คำเตือน แทน เพื่อให้ปลายงวดตรงกับงบแสดงฐานะการเงินเสมอ

## Consequences

- ✅ ทำงบการเปลี่ยนแปลงส่วนของผู้ถือหุ้นตามแบบ 2 ได้ ยอดปลายงวดตรงกับงบแสดงฐานะการเงิน; งบต้นทุนขาย/กระแสเงินสดใช้ยอดถูกประเภท
- ⚠️ การแยกเงินปันผล/เพิ่มทุน ขึ้นกับการมีบัญชีแยก (เช่น บัญชีเงินปันผลจ่าย) — ถ้าตัดเงินปันผลเข้ากำไรสะสมตรง ยอดจะไปอยู่แถว "รายการอื่นที่ยังไม่ได้จัดประเภท"
- ⚠️ ชุดปีปัจจุบันแสดงแถว "ยอดคงเหลือ ณ ต้นงวด" ซ้ำกับปลายงวดปีก่อน (แบบ 2 รวมเป็นบรรทัดเดียว "ปลายงวด 25X0 / ต้นงวด 25X1") — ถ้ายังไม่ยกยอดปีใหม่ ตัวเลขสองบรรทัดนี้จะต่างกันและเห็นได้ทันที
- ⚠️ งบกระแสเงินสดยังไม่มีแถวตรวจยอดเงินสดตามบัญชี — ผู้ใช้ต้องเลือกบัญชีครบเองให้ยอดปลายงวดตรง
- ⚠️ ยังไม่มีหมายเหตุประกอบงบ (ต้องมีที่เก็บข้อความ — รอลุงจืดตัดสิน)

## Verification

- `backend/internal/generalledger/statements_equity_test.go` — ยอดที่แถวใช้ทั้ง 4 แบบ, ต้นงวด + บรรทัด + รายการอื่น = ปลายงวดทุกคอลัมน์, คำเตือนครบ 6 ชนิด
- `backend/internal/generalledger/statements_equity_integration_test.go` (PostgreSQL จริง) — ปี 2026 ปิดบัญชีและยกยอดแล้ว, ปี 2027 เพิ่มทุน 500 ปันผล 20 กำไรที่ยังไม่ปิด 150 รายการอื่น 5: ปลายงวดรวม 1,704.75 = เงินสด, ชุดปี 2026 มาก่อน, คอลัมน์ที่ไม่เลือกบัญชีไม่แสดง, ไม่ได้ใส่กำไรที่ยังไม่ปิด = เตือน, ไม่มีคอลัมน์ = error
- `frontend/src/lib/general-ledger.test.ts` (แม่แบบ 5 ชุด ยอดที่แถวใช้/คอลัมน์ตามแบบ 2), `frontend/src/app/gl/gl-print.test.ts` (คอลัมน์องค์ประกอบ บรรทัดคั่นชุดปี แนวนอน)
