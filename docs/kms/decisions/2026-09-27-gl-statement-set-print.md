# พิมพ์ชุดงบการเงินในงานพิมพ์เดียว (งบทุกงบ + หมายเหตุ เรียงตามแบบ 2)

## Context
หลังทำหมายเหตุประกอบงบการเงิน (ADR `2026-09-26-gl-statement-notes-hidezero-cashcheck.md`) ผู้ใช้ยังต้องพิมพ์งบทีละงบแล้วพิมพ์หมายเหตุแยกอีกครั้ง — เลขหน้าไม่ต่อกัน ลำดับขึ้นกับผู้ใช้ และงบที่ยังมีคำเตือน (ไม่สมดุล/เงินสดไม่ตรงบัญชี/หมายเหตุที่อ้างยังไม่มี) หลุดไปถึงกระดาษได้ง่าย Champ ไม่มีฟังก์ชันนี้ — ลุงจืดอนุมัติเป็นข้อ [1] เมื่อ 2026-09-27

ลำดับตามแบบ 2 (บริษัทจำกัด) ของประกาศกรมพัฒนาธุรกิจการค้า เรื่อง กำหนดรายการย่อที่ต้องมีในงบการเงิน พ.ศ. 2566 ตรวจจากต้นฉบับ https://www.dbd.go.th/storage/law/4941272b-c21b-4d78-b1ca-3e63f83252e7.pdf (ทะเบียน `docs/kms/21` แถว DBD-FS-2566): 1. งบฐานะการเงิน (หน้า 2-1) → 2. งบกำไรขาดทุน (2-4) → 3. งบการเปลี่ยนแปลงส่วนของผู้ถือหุ้น (2-20) → 4. งบกระแสเงินสด (2-23, NPAEs ไม่บังคับ) → 5. หมายเหตุประกอบงบการเงิน (2-30)

## Decision
- ปุ่ม "พิมพ์ชุดงบการเงิน" ในแถวสลับโหมดของจอออกแบบงบ (`/gl/statement-designer`) — ไม่เพิ่มเมนู; หน้าต่าง `GLStatementSetDialog` (`frontend/src/app/gl/gl-statement-set.tsx`)
- เลือกปีบัญชี (ทั้งปี startdate–enddate) + รายการแม่แบบที่เปิดใช้งาน เรียงด้วย `statementSetTemplates` (ลำดับแบบ 2, ประเภทที่แบบ 2 ไม่มี — งบต้นทุนผลิต/กำหนดเอง — ต่อท้ายก่อนหมายเหตุ เรียงตามรหัส); ค่าเริ่มต้นติ๊กแม่แบบแรกของงบฐานะการเงิน/กำไรขาดทุน/ส่วนของผู้ถือหุ้น/กระแสเงินสด (`statementSetDefaultSelection`); หมายเหตุของปีเดียวกันติ๊กให้เมื่อมี
- ต้องกด "ตรวจและเตรียมพิมพ์" ก่อน: คำขอเดียว `GET reports/statement-set` (ปีบัญชีทั้งปี + รหัสที่ติ๊ก + ธงหมายเหตุ — `backend/internal/generalledger/statement_set.go`) ทุกงบคำนวณด้วยเส้นทางเดียวกับ `reports/statement` (ตัวเลข/คำเตือน/ผลตรวจเท่ากับพรีวิวทุกค่า) และหมายเหตุของปี ใน snapshot เดียว เรียงตามแบบ 2 มาจาก backend (จอไม่เรียงใหม่) แสดงสถานะต่องบ (พร้อม / มีข้อควรตรวจสอบ + คำเตือน + ผลตรวจยอด / คำนวณไม่ได้); งบที่ error ห้ามพิมพ์, คำเตือนไม่ห้ามแต่สรุปจำนวน; เปลี่ยนปีหรือรายการ = ล้างผลเตรียมพิมพ์ + ทิ้งคำตอบที่มาช้า
- พิมพ์ครั้งเดียว (`GLStatementSetPrint`): แต่ละงบเป็น `.gl-print-set-section` ขึ้นหน้าใหม่ + named page ตามแนวกระดาษของตัวเอง (งบส่วนของผู้ถือหุ้นที่มีคอลัมน์เงิน > 3 = แนวนอน) หมายเหตุท้ายสุดแนวตั้ง; เลขหน้า "หน้า n / N" ต่อเนื่องทั้งชุดจาก `@page` เดิม
- บรรทัดวันที่ของหัวงบใช้ `statementPeriodLine` ตัวเดียวกับพรีวิว (ย้ายออกจาก `statementView` ของจอออกแบบ ไม่เปลี่ยนพฤติกรรม)
- ใช้แม่แบบ/หมายเหตุที่บันทึกแล้วเท่านั้น — ถ้าจอมีการแก้ไขค้าง หน้าต่างเตือนว่าการแก้ไขนั้นไม่รวมในชุดพิมพ์

## Alternatives
- เรียก `reports/statement` ทีละงบพร้อมกันที่ browser + อ่านหมายเหตุแยก (ฉบับแรกของ commit `4882e0e7`) — เลิกใช้ 2026-09-27 และลบโค้ดแล้ว: แต่ละงบเป็นคนละธุรกรรม ถ้ามีการผ่านรายการระหว่างคำขอ งบในชุดเดียวกันอาจเห็นสมุดบัญชีต่างเวลา (งบฐานะการเงินกับงบกำไรขาดทุนไม่กระทบกัน), ลำดับแบบ 2 อยู่ที่ browser อย่างเดียว — แทนด้วย endpoint `reports/statement-set` (ตอนนี้เปิดให้จอเว็บผ่าน session BFF `/api/gl` เท่านั้น ทางเข้า API token `/api/integration/gl` ยังไม่เปิด — จะเปิดให้ API ภายนอกต้องให้ลุงจืดอนุมัติก่อน) (ลำดับแบบ 2 อยู่ที่ backend `statementSetOrder`; รายการให้เลือกในจอยังเรียงด้วย `statementSetRank` และ `gl-statement-set.test.ts` ตรวจว่าตรงกัน)
- ให้ `templates` ว่างหมายถึงชุดเริ่มต้น — ไม่ทำ: จอพิมพ์หมายเหตุอย่างเดียวได้ จึงต้องแยก "ไม่ส่ง" (ชุดเริ่มต้น) กับ "ส่งค่าว่าง" (ไม่มีงบ)
- จำรายการที่เลือกไว้ต่อบริษัท — ไม่ทำ: เปิดหน้าต่างใหม่ = ค่าเริ่มต้นจากแม่แบบที่บันทึกล่าสุดเสมอ
- หน้าปก / สารบัญ / ช่องลายมือชื่อกรรมการ — ไม่ทำ: แบบ 2 ไม่ได้กำหนดรูปแบบไว้ ห้ามแต่งเอง

## Consequences
- แนวตั้ง/แนวนอนปนในงานเดียวพึ่ง CSS named pages — ตรวจแล้วใน Chromium (PDF 4 ส่วน P,P,L,P = 4 หน้าแนวตรง) ยังไม่ได้ตรวจ Safari/Firefox
- ความถูกต้องของเนื้อหายังขึ้นกับการจับคู่บัญชีในแม่แบบของผู้ใช้ — ชุดพิมพ์แค่ทำให้คำเตือนเห็นก่อนพิมพ์
- รูปแบบงบที่ติ๊กไว้แต่ถูกลบ/ปิดใช้งานระหว่างเปิดหน้าต่าง = ทั้งคำขอไม่ผ่าน (400 พร้อมรหัสรูปแบบ) หน้าต่างแสดง "ตรวจชุดงบไม่สำเร็จ: …" ต้องปิดแล้วเปิดใหม่ — ส่วนงบที่คำนวณไม่ได้ (เช่น งบส่วนของผู้ถือหุ้นยังไม่ผูกบัญชี) ยังล้มเฉพาะงบนั้น
- review workflow 3 มุม (พิมพ์/CSS, UX-i18n-state, บัญชี/ข้อมูล) เจอจริง 2 ข้อ (โฟกัสหลุดเมื่อปุ่มถูกปิดระหว่างทำงาน, ข้อความท้ายหน้าต่างเมื่อไม่มีปีบัญชี) แก้ก่อน commit — SKILL `ui-scale-polish` §8.59
