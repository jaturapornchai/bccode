# แยกฟอร์มสินค้าเป็น 2 เมนู: "สินค้า" (งานบัญชี) กับ "สินค้า (ส่วนขยาย)"

## Context
ฟอร์มสินค้าเดิม (`frontend/src/app/menu/product-screen.tsx`) มี 11 tab ในจอเดียว — พนักงานบัญชี (ผู้ใช้หลัก
คนไทย 40+) ต้องเลื่อนผ่าน tab ที่ไม่เกี่ยวกับงานบัญชี (POS/ร้านอาหาร, เวลาขาย, โลจิสติกส์, รูปภาพ ฯลฯ)
ทุกครั้งที่แก้สินค้า ลุงจืดสั่ง 2026-09-04: "เพิ่ม สินค้า (ส่วนขยาย) ต่อจากสินค้า และย้ายไปเมนูใหม่
เพื่อให้งานบัญชีง่ายขึ้น" และเลือก tab เองทีละตัว

## Decision
- เมนู **สินค้า** (`/product`) เหลือ 3 tab: ข้อมูลหลัก, หน่วยนับและบาร์โค้ด, คงคลัง
- เมนูใหม่ **สินค้า (ส่วนขยาย)** (`/productextension`, id `product-extension`) วางต่อจาก "สินค้า" ใน group
  `products` มี 8 tab: หมวดหมู่, ส่วนประกอบ (BOM), ภาพและสี, การจัดส่ง/โลจิสติกส์, ร้านอาหาร/POS, เวลาขาย,
  สาขา/ธุรกิจ, อื่นๆ
- ทำด้วย prop `mode: "core" | "extension"` บน `ProductScreen` เดิม — list ซ้าย + panel ขวา + save handler
  ใช้ร่วมกัน; โหมดส่วนขยายเป็น **edit-only** (ซ่อน เพิ่ม/คัดลอก) เพราะสร้างสินค้าโดยไม่มี tab ข้อมูลหลัก
  จะได้สินค้าไร้ชื่อ/หน่วยนับ
- ทั้ง 2 เมนูอ่าน/เขียน document เดียวกันใน `appdb.products` — ไม่มี collection/field ใหม่

## Alternatives
- **ก็อป product-screen.tsx เป็นไฟล์ใหม่** — ~2,600 บรรทัดซ้ำ, bug fix ต้องแก้ 2 ที่ → ไม่เอา (Rule 15)
- **แค่ซ่อน tab ด้วยปุ่ม "ขั้นสูง" ในจอเดิม** — ลุงจืดเคยสั่งเอาปุ่มขั้นสูงออก (2026-07-19) และครั้งนี้ต้องการ
  "เมนูใหม่" ชัดเจน เพื่อกำหนดสิทธิ์แยกกันได้ในอนาคต → ไม่เอา
- **หน้าส่วนขยายไม่มี list เอง ต้องลิงก์จากหน้าสินค้า** — เสนอแล้ว ลุงจืดเลือกแบบมี list ของตัวเอง

## Consequences
- งานบัญชีเห็นแค่ 3 tab; ทีมอื่น (คลัง/ออนไลน์/POS) ใช้เมนูส่วนขยาย
- role ที่มีรายการสิทธิ์ชัดเจน (ไม่ใช่ `"*"`) จะเห็น "สินค้า (ส่วนขยาย)" เป็นล็อกจนกว่า admin จะติ๊กเพิ่ม —
  พฤติกรรมเดียวกับเมนูใหม่ทุกตัว
- เพิ่มแถว `product_extension` ใน `backend/assets/language/languages.tsv` (th/en จริง, ภาษาอื่น English
  ตาม precedent `productset`); container `mainapi` local ยังไม่มี TSV ใหม่จนกว่าจะ build image ใหม่ —
  UI ไม่พังเพราะ `menuText` fallback ไป `label.th`
- verify แล้ว: tsc 0 error, vitest menu-data 23/23, บันทึกจากจอส่วนขยาย → PUT 200 และ doc P1-001 ใน Mongo
  คง names/itemtype/vattype เดิม (`updatedat` เลื่อน) — ดู skill `ui-scale-polish` §4.37
