# เอกสาร ERP ลงบัญชี/สต็อกในธุรกรรมเดียว และแก้/ลบ = กลับรายการ

## Context
`SaveDoc` เดิมลง `gl_records`/`stock_ledger` ด้วยผังบัญชี hard-code, ปีบัญชี fallback "2569" และ `float64`; กลืน error ของ docref/สต็อก/GL; แก้ไม่กลับรายการ ลบไม่ย้อน (บั๊กค้นหา docno ด้วย args ที่ถูกตัด ทำให้ `stock_ledger` ไม่ถูกลบ — แก้แล้วใน `7b0d333d`) — ละเมิด Rule 20 และกฎ "ห้าม branch ด้วยรหัสบัญชี" และเอกสารที่ผ่านบัญชีแล้วต้องแก้ด้วยรายการกลับเท่านั้น

## Decision
- **ใช้เครื่องยนต์เดียวกับ GL:** `generalledger.ExecuteSourceTx` (สร้าง→ผ่านรายการ→กลับรายการ) ในธุรกรรม SQL เดียวกับหัว/รายการ/สต็อก/บัญชีย่อย; ล็อกบริษัทเดียวกับคำสั่งบัญชี (`LockCompanyTx`) สำหรับประเภทที่ลงบัญชีหรือเคลื่อนไหวสต็อก (`serialized`) ทั้งหมดสำเร็จหรือถอยกลับพร้อมกัน
- **บัญชีมาจากข้อมูลของบริษัท ไม่ใช่โค้ด:** รูปแบบลงบัญชี = master `mappings` ที่มี `sourcedoc` (หนึ่งประเภทเอกสารต่อหนึ่งรูปแบบ, ตรวจที่ `validateMasterMapping`; ประเภทที่ลงได้มาจาก `doctype.PostingKeys()`) แต่ละรายการอ้างยอดด้วย `total|goods|vat` ยังไม่มีรูปแบบ → บันทึกเอกสารแต่ไม่ลงบัญชี ตอบ `glstatus: no_mapping` (จอแจ้งผู้ใช้) — ไม่เดาบัญชี; บัญชีคุมลูกหนี้/เจ้าหนี้อ่านจากรายการ `total` ของรูปแบบ, บัญชีเงินสด (`IsCash`) ไม่ลงบัญชีย่อย
- **ปีบัญชี/วันกลับรายการจากฐาน:** `SourceFiscalYear` / `SourceReversalDate` (ไม่มี fallback ปีคงที่); วันที่ใบสำคัญ = วันตามเวลา Asia/Bangkok ของเอกสาร
- **ตัวเลขเงิน:** `float64` จาก JSON แปลงเป็น `decimal` 2 ตำแหน่งที่ขอบเขตแล้วคำนวณ/ส่งเป็น decimal string; ยอดรวม = สินค้า + ภาษี; ยอดติดลบหรือภาษีเกินยอดรวม = ปฏิเสธ (`gl_err_erp_amount_invalid`)
- **แก้/ลบ = กลับรายการ ไม่ใช่แก้ทับ:** ตาราง `erp_doc_journals(businesscode, transflag, docno, revision, journal_id, …, voided_at)` — ใบที่ใช้งานอยู่มีใบเดียวต่อเอกสาร; แก้ = กลับรายการใบเดิม (`<docno ใบเดิม>-R`, เหตุผล "แก้ไขเอกสาร …") แล้วลงใบ revision ถัดไป; ลบ = กลับรายการ + ถอนสต็อก + ถอนบัญชีย่อย แล้วตั้ง `doc.isdelete`; ใบเดิมคงอยู่เป็นหลักฐาน
- **ตัดหนี้แล้วแก้/ลบไม่ได้:** ถ้ามี settlement/allocation ของเอกสารอื่นผูกกับ `AR-/AP-<docno>` → `gl_err_erp_doc_settled` ต้องยกเลิกการตัดหนี้ก่อน (กันยอดค้างอีกฝั่งเพี้ยนเงียบๆ); ใบรับ/จ่ายที่อ้าง `docref` เป็นใบหนี้เดิมจะตัดหนี้ให้ตอนลงบัญชี
- **สต็อกทุกประเภทที่ทะเบียนบอกว่าเคลื่อนไหว** (`Stock = StockIn|StockOut`, 12 ประเภทที่ลงบัญชีหรือเคลื่อนไหว รวม `goodsreceive`, `stock-*`) — เปลี่ยนจากเดิมที่เคลื่อนเฉพาะ 5 ประเภทที่ hard-code; ทุกครั้งที่บันทึก/แก้/ลบ คำนวณสายยอดคงเหลือ/ต้นทุนถัวเฉลี่ยของ (สินค้า, คลัง) ใหม่ตั้งแต่แถวแรกที่เปลี่ยน (`rebuildStockChain`) รองรับเอกสารย้อนหลัง; `behindindex` = ลำดับที่บันทึกในเวลาเดียวกัน (หน้าจอส่ง `T09:00:00Z` ทั้งวัน — เรียงด้วยเลขที่เอกสารจะทำให้ `INV` มาก่อน `PUR` ของวันเดียวกันแล้วยอดติดลบ) และการแก้เอกสารคงตำแหน่งเดิม
- เลขที่เอกสารที่เคยใช้แล้ว (รวมที่ลบ) ใช้ซ้ำไม่ได้ (`gl_err_erp_doc_duplicate`); ลบซ้ำ = 404; error ของ docref/สต็อก/GL ไม่ถูกกลืนอีก
- Error ผู้ใช้ผ่าน `gl.UserError` + แถว `gl_err_<code>` ใน `languages.tsv` (13 คอลัมน์) แสดงตาม `Accept-Language`; BFF `userErrorStatusOk` ส่งต่อ 4xx ที่มี `code` เป็น HTTP 200 + `success:false` → `saveErpTransaction`/`deleteErpTransaction` ต้องเช็ค `success===false` (ไม่ใช่แค่ `res.ok`) และส่งภาษาที่เลือกบนจอเป็น `Accept-Language`
- Frontend: `ERP_AUTO_POSTING_MODULES` = `postingFlags` + Stock In/Out ของทะเบียน (เทสต์ parse `doctype.go`); แบนเนอร์ผลลงบัญชี `erp_gl_notice_posted|no_mapping|no_amount`

## Consequences
- **เป็นการเขียนใหม่ (R1):** ชุดทดสอบ `httpapi` ปรับตามทั้งชุด + เทสต์ integration จริงกับ PostgreSQL (`save_integration_test.go`, tag `integration`, `BC_GL_TEST_POSTGRES_DSN`)
- **prod ยังไม่มีรูปแบบลงบัญชี** → เอกสารทั้ง 7 ประเภทที่ลงบัญชีบันทึกได้แต่ `no_mapping` จนกว่าจะตั้งที่เมนูการจับคู่บัญชี
- ใบที่ลงโดยโค้ดเก่า (journal id `SAL-…` ไม่มีแถวใน `erp_doc_journals`) ไม่ถูกกลับรายการเมื่อแก้/ลบเอกสารนั้น — แก้เอกสารเก่าจึงลงซ้ำ (ข้อมูลทิ้งได้ช่วงก่อน go-live; ก่อน go-live จริงต้องไล่ปิด)
- สต็อกขายเกินคงเหลือ: ยังไม่มีนโยบาย (ยอดติดลบได้) — รอลุงจืดตัดสิน
- ยังไม่ทำ: ลงบัญชีย่อยจาก `Details` ของเครื่องยนต์เดิม, รายการต้นทุนขาย/สินค้าคงเหลือของใบขาย, ประเภท ByLine (`stock-transfer`, `stock-adjustment`), เปิดใบอ้างอิงต้นทางคืนเมื่อลบใบปลายทาง, คลังเริ่มต้น `WH01` ยัง hard-code, `docdetail` ของใบที่ลบยังอยู่ในตาราง
