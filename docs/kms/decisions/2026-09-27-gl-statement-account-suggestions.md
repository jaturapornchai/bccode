# แนะนำบัญชีให้บรรทัดของแม่แบบงบการเงินจากข้อมูลที่บันทึกไว้ + แทนบัญชีหัวข้อด้วยบัญชีย่อย + เตือนบัญชีที่มียอดแต่ไม่อยู่ในงบ + ยอดปกติ/บัญชีเงินสดในผังบัญชี (D0–D4)

## Context

- แม่แบบงบมาตรฐาน (`frontend/src/lib/general-ledger.ts` `generateStarterTemplates`) ไม่ใส่รหัสบัญชีเลย เพราะผังบัญชีแต่ละกิจการไม่เหมือนกัน (ADR `2026-09-26-gl-statements-backend-comparative.md`) — ผู้ใช้ต้องเลือกบัญชีเองทุกบรรทัด และไม่มีอะไรบอกว่าบัญชีไหนควรอยู่บรรทัดไหน
- **ยอดศูนย์เงียบ:** เครื่องคำนวณงบรวมยอดจาก `gl_lines` ตามรหัสบัญชีตรง ๆ (`statements.go` `statementBalances`) บัญชีหัวข้อไม่มีรายการจึงได้ 0 เสมอ; รหัสที่ถูกลบออกจากผังก็ได้ 0 โดยไม่มีคำเตือน
- **บัญชีหลุดงบ:** บัญชีที่มียอดแต่ไม่อยู่ในบรรทัดใดของงบ ทำให้งบฐานะการเงินไม่สมดุลหรือกำไรไม่ตรงกับบัญชี โดยผู้ใช้ไม่รู้ว่าบัญชีไหนหาย
- **ผังบัญชี:** จอผังบัญชีแสดงยอดปกติ (เดบิต/เครดิต) ตามหมวดอย่างเดียวและตั้งค่าใหม่ทุกครั้งที่เปลี่ยนหมวดหรือบัญชีแม่ → บันทึกบัญชีปรับลด (เช่น ค่าเสื่อมราคาสะสม ยอดปกติเครดิตในหมวดสินทรัพย์) ทับเป็นเดบิตได้; และไม่มีช่องให้ตั้ง "บัญชีเงินสด" (`iscash`) ทั้งที่ backend เก็บและตรวจอยู่แล้ว (`backend/internal/generalledger/models.go:48,52,348,354`) และรายงานเงินสดใช้ค่านี้

## Decision

**D1 — แนะนำบัญชี (backend คำนวณ ผู้ใช้เลือกเอง):** บรรทัด/คอลัมน์ของแม่แบบมี `suggestkey` (ชนิดบรรทัด ไม่มีผลต่อการคำนวณงบ — `models.go:146-147,176-177`). คำสั่ง `POST /gl/v2/command` `{resource:"statement-templates", action:"suggest", master}` คำนวณอย่างเดียว ไม่บันทึก ไม่ใช้ requestid/idempotency (`postgres_store.go:75-76`, `statement_suggestions.go:198`) สิทธิ์อ่านจอ `financial-statement-designer` พอ (`httpapi/http.go:378` `calculationOnly`) — ผลคือ `{targets, fixes}`; เหตุผลมาจาก **ข้อมูลที่บันทึกไว้เท่านั้น** ไม่ดูรหัส ช่วงรหัส หรือชื่อบัญชี:

| suggestkey | บรรทัดในแม่แบบมาตรฐาน | หมวดบัญชี | หลักฐาน (reason source) |
|---|---|---|---|
| `cash_and_equivalents` | `bs-30`, `cf-17` | สินทรัพย์ | `iscash` (ผังบัญชี), `bank_accounts` (บัญชีธนาคารที่ผูกบัญชี GL) |
| `trade_receivables` | `bs-50`, `cf-4` | สินทรัพย์ | `ar_documents` (บัญชีคุมเอกสารลูกหนี้) |
| `inventories` | `bs-80`, `cf-5` | สินทรัพย์ | `product_item` (กลุ่มบัญชีสินค้า) |
| `property_plant_equipment` | `bs-230` | สินทรัพย์ | `fa_asset`, `fa_accum` (สินทรัพย์ถาวร) |
| `purchase_of_ppe` | `cf-10` | สินทรัพย์ | `fa_asset` |
| `trade_payables` | `bs-350`, `cf-6` | หนี้สิน | `ap_documents` (บัญชีคุมเอกสารเจ้าหนี้) |
| `retained_earnings` | `bs-650`, คอลัมน์ `eq-c4` | ส่วนของเจ้าของ | `fiscal_retained` (บัญชีกำไรสะสมของปีบัญชี) |
| `sales_revenue` | `pnl-10` | รายได้ | `product_revenue` |
| `cost_of_sales` | `pnl-20` | ค่าใช้จ่าย | `product_cost` |
| `depreciation_expense` | `cf-3` | ค่าใช้จ่าย | `fa_expense` |

ทุกชนิดได้ `other_templates` ด้วย (บัญชีที่ผูกในบรรทัดชนิดเดียวกันของแม่แบบอื่น แสดงรหัสแม่แบบไม่เกิน 5 รหัส). แนะนำเฉพาะบัญชีลงรายการได้ที่หมวดตรง; บัญชีที่อยู่ในบรรทัดอื่นที่เครื่องคำนวณอ่านด้วยฐานยอดเดียวกันแล้วแสดงแยก (`inuse`) ไม่แนะนำซ้ำ (ยกเว้นงบกระแสเงินสดที่วิธีทางอ้อมใช้บัญชีซ้ำได้). รายการคีย์ต้องตรงกันสองฝั่ง: `statement_suggestions.go:22` ↔ `STATEMENT_SUGGEST_KEYS` (`general-ledger.ts:550`, มี test เทียบ)

- **จอ (`gl-statement-designer.tsx`):** ปุ่ม "แนะนำ N บัญชี" ข้างปุ่มเลือกบัญชีของบรรทัด/คอลัมน์ที่มีคำแนะนำ → หน้าต่างตรวจ (`gl-statement-suggestions.tsx`) **ไม่ติ๊กให้**, บอกเหตุผลทุกบัญชี, บัญชีปิดใช้งานมีป้าย, บัญชีที่อยู่บรรทัดอื่นแสดงแยกไม่มีช่องติ๊ก → "เพิ่มบัญชีที่เลือก (N)" ต่อท้ายรหัสเดิม (ยังไม่บันทึกจนกด "บันทึก"). ขอคำแนะนำใหม่เมื่อ `statementSuggestSignature` เปลี่ยน (หน่วง 400ms, ยกเลิกคำขอเก่า, ผลเก่าที่ไม่ตรงลายเซ็นทิ้ง) ไม่ผูกกับปุ่มบันทึก
- ชนิดบรรทัดตั้งจากแม่แบบมาตรฐานเท่านั้น ยังไม่มีตัวเลือกให้ผู้ใช้เปลี่ยน (ข้อ 6 ด้านล่าง); ค่าที่ไม่รู้จักถูกตัดก่อนส่ง (`withKnownSuggestKeys`)

**D2 — แทนบัญชีหัวข้อด้วยบัญชีย่อย:** `fixes` บอกต่อบรรทัดว่ามีบัญชีหัวข้อ (→ บัญชีย่อยที่ลงรายการได้ทุกชั้น `descendants`, บัญชีย่อยที่อยู่บรรทัดอื่นแล้ว `skipped`) และรหัสที่ไม่มีในผัง (`removed`). จอแทนให้ **เฉพาะบรรทัดที่ผู้ใช้เพิ่งเลือกบัญชีจากหน้าต่างเลือกบัญชี** (แทนในตำแหน่งเดิม ตัดรหัสซ้ำ — `applyStatementAccountFix`) + บรรทัดที่ backend ให้รับบัญชีย่อยของบัญชีหัวข้อเดียวกันไปก่อน (ตำแหน่งก่อนหน้ารับก่อน; `statementFixesToApply` แทนพร้อมกัน ไม่งั้นบรรทัดที่ผู้ใช้เลือกได้ 0 บัญชีและข้อความ "อยู่ในบรรทัดอื่นแล้ว" ไม่จริง) แล้วบอกเป็นข้อความว่าแทนอะไรด้วยกี่บัญชี ข้ามบัญชีไหน; แม่แบบเดิมที่มีปัญหาอยู่แล้วแสดงกล่องเตือน "มี N บรรทัดที่ใช้บัญชีหัวข้อ…" พร้อมปุ่ม "แทนบัญชีหัวข้อด้วยบัญชีย่อย (N บรรทัด)" ให้ผู้ใช้กดเอง. ตอนบันทึก backend ปฏิเสธบัญชีหัวข้อ/รหัสที่ไม่มีในผังในตำแหน่งที่เครื่องคำนวณอ่าน (`validateMasterStatement`, `statement_suggestions.go:541`; 400 `statement_template_row_accounts_invalid` / `statement_template_column_accounts_invalid`)

**D3 — กันเปลี่ยนบัญชีเป็นหัวข้อ + ลบบัญชี:** เงื่อนไข SQL เดียว `statementTemplateReadsAccount` (`statement_suggestions.go:568`) = "แม่แบบงบอ่านรหัสนี้จริง" (แถวชนิดยอดบัญชี; งบส่วนของผู้ถือหุ้น = แถวความเคลื่อนไหว + ทุกคอลัมน์) ใช้ทั้งกันลบบัญชี (`deletePGAccountGuard`) และกันปิด "บันทึกบัญชีได้" ของบัญชีที่ผูกงบอยู่ (409 `account_in_statement_template` field `allowposting`, `postgres_guards.go:182`) — รหัสที่ค้างในแถวชนิดอื่นไม่ถูกนับ

**D0 — บัญชีที่มียอดแต่ไม่อยู่ในบรรทัดใด:** `reports/statement` และทุก section ของ `reports/statement-set` มี `unassigned` (`statements_unassigned.go`, เรียกที่ `statements.go:73,91` ทั้งปีนี้และปีเปรียบเทียบ): งบฐานะการเงิน = บัญชีสินทรัพย์/หนี้สิน/ส่วนของเจ้าของที่ยอดคงเหลือปลายงวดไม่เป็นศูนย์ + กำไร (ขาดทุน) ที่ยังไม่ปิดบัญชีหนึ่งรายการถ้าไม่มีบรรทัดใดรวม `__current_earnings__`; งบกำไรขาดทุน = บัญชีรายได้/ค่าใช้จ่ายที่ยอดเคลื่อนไหวไม่เป็นศูนย์; งบอื่นไม่ตรวจ. ตัวกรองสาขา/แผนก/โครงการ/ทั้งบริษัทเหมือนงบ (งบไม่กรองสมุดรายวันอยู่แล้ว; ทดสอบใน `TestStatementUnassignedIntegration`). จอแสดงเป็นกล่องเตือน `role="status"` บนจอ (ตัวอย่างงบในจอออกแบบ และหน้าต่างตรวจก่อนพิมพ์ชุดงบ — `reportNeedsReview` นับด้วย) **ไม่อยู่ในงบที่พิมพ์**

**D4 — ผังบัญชี (`gl-masters.tsx`):** ยอดปกติเป็นช่องเลือก เดบิต/เครดิต (ค่าเริ่มต้นตามหมวด, เปลี่ยนกลับตามหมวดเฉพาะเมื่อหมวดเปลี่ยนจริง, ขึ้นข้อความ "บัญชีปรับลด" เมื่อด้านตรงข้ามกับหมวด) + ช่องติ๊ก "เป็นบัญชีเงินสดหรือรายการเทียบเท่าเงินสด" ใช้ได้เฉพาะบัญชีสินทรัพย์ที่ลงรายการได้และไม่มีบัญชีย่อย (`accountCashAllowed`/`accountSavePayload` ไม่ส่งค่าที่ backend จะปฏิเสธ). ทั้งสองค่ายังล็อกเมื่อบัญชีมีรายการแล้ว (guard เดิม `validatePGAccount`) — hint ของทั้งสองช่องบอกเงื่อนไขนี้ และข้อความ `account_posted_immutable` ระบุยอดปกติ/บัญชีเงินสด; จอยังไม่รู้ล่วงหน้าว่าบัญชีมีรายการ (ช่องจึงยังกดได้แล้ว backend ปฏิเสธตอนบันทึก — ถ้าจะปิดช่องล่วงหน้าต้องเพิ่มธงใน API รายการผังบัญชี)

## Alternatives

- **จับคู่บัญชีจากรหัส/ช่วงรหัส/ชื่อบัญชี** — ห้าม (ผังบัญชีแต่ละกิจการต่างกัน; กฎไม่ใช้รหัส/ชื่อเป็นเงื่อนไข)
- **รวมยอดบัญชีย่อยขึ้นหัวข้อตอนออกรายงาน** — ไม่เลือก: บัญชีเดียวถูกนับสองครั้งได้ถ้าหัวข้อกับบัญชีย่อยอยู่คนละบรรทัด; เลือก D2 (แทนตอนออกแบบ ผู้ใช้เห็น) + D0 (เตือนที่เหลือ) แทน
- **ใส่บัญชีที่แนะนำให้อัตโนมัติ** — ไม่เลือก: คำแนะนำเป็นหลักฐานประกอบ ผู้ใช้ต้องตรวจเอง (บัญชีที่ปิดใช้งาน/บัญชีหลายบทบาท)
- **ตรวจรหัสที่ไม่มีในผังตอนออกรายงาน** — เลื่อนไปก่อน (กล่องเตือนในจอออกแบบครอบคลุมแม่แบบที่เปิด)

## Consequences

- แม่แบบที่บันทึกก่อนมีคีย์ไม่ได้คำแนะนำ (เดินหน้าอย่างเดียว ไม่มี shim) — แต่ยังได้กล่องเตือนแทนบัญชีหัวข้อ และ D0; ใช้แม่แบบมาตรฐานทับเพื่อได้คีย์
- **ช่องว่างที่ยังเหลือ:** แม่แบบต้นทุนขาย/ส่วนของผู้ถือหุ้น/กำหนดเองที่ยังมีบัญชีหัวข้อได้ยอดศูนย์เงียบจนกว่าจะเปิดจอออกแบบแล้วบันทึก; บัญชีย่อยที่เพิ่มภายหลังใต้หัวข้อที่แทนไปแล้วไม่ถูกเติมให้ (ใน COGS/ส่วนของผู้ถือหุ้น/กำหนดเอง ไม่มีคำเตือน; BS/P&L มี D0); งบกระแสเงินสดมีแค่การตรวจเงินสดปลายงวดเดิม
- โมดูล GL อ่านตาราง `fa_records` ของระบบสินทรัพย์ถาวรตรง ๆ (ตรวจ `to_regclass` ก่อน ไม่มีตาราง = ไม่มีหลักฐาน — `statement_suggestions.go:688-694`)
- ผู้มีสิทธิ์อ่านจอออกแบบงบเห็นจำนวนเอกสารลูกหนี้/เจ้าหนี้ บัญชีธนาคาร และสินทรัพย์ถาวรต่อบัญชี ทั้งบริษัท (ไม่กรองสาขา) — ความอ่อนไหวต่ำ
- ขีดจำกัดคำสั่งแนะนำ: 500 บรรทัดรวมคอลัมน์, 2,000 รหัสต่อบรรทัดที่เครื่องคำนวณอ่าน, 20,000 รหัสในผลแทนบัญชี (400 `statement_template_suggest_too_large`); ไม่จำกัดตอนบันทึก
- MCP `gl_command` ส่งคำสั่งผ่านตรง จึงเรียก suggest ได้ (อ่านอย่างเดียว) — ไม่แก้ MCP (งาน MCP พักไว้)
- **ต้อง deploy mainapi กับ frontend พร้อมกัน (`fast-deploy --all`)**: `decodeCommand` ใช้ `DisallowUnknownFields` → frontend ใหม่ที่ส่ง `suggestkey` กับ backend เก่า = บันทึกแม่แบบไม่ได้ (400)
- **D4 และการแนะนำบัญชีเกินจาก Champ** (`BCChartOfAccount` ไม่มียอดปกติ/บัญชีเงินสด; ตัวออกแบบงบ 5505 ไม่มีคำแนะนำ) — เหตุผล: backend เก็บและตรวจทั้งสองค่าอยู่แล้ว, รายงานเงินสดใช้ `is_cash` แต่ไม่มีจอให้ตั้ง, และบันทึกบัญชีปรับลดทับยอดปกติได้ (บั๊กข้อมูล). **การอนุมัติ:** ลุงจืดสั่ง "ทำให้เสร็จ" (2026-09-27) ต่อแผน D0–D4 — ยังไม่ได้ยืนยันแยกเฉพาะ D4; ถ้าไม่อนุมัติ ให้เอาเฉพาะช่องเลือกยอดปกติและช่องติ๊กบัญชีเงินสดออก ส่วนอื่นคงไว้

## ข้อตัดสินใจที่ต้องรับรู้ (จากสเปก)

1. ตรวจ "อยู่บรรทัดอื่นแล้ว" และข้ามบัญชีย่อยตามฐานยอด (ต้นงวด/ปลายงวด/เคลื่อนไหว) และปิดสำหรับงบกระแสเงินสด
2. คอลัมน์ `eq-c4` ของงบส่วนของผู้ถือหุ้นมีคีย์ (ขยาย D1 จากบรรทัดไปคอลัมน์)
3. ไม่ใช้ `profitlossaccount` ของปีบัญชีเป็นหลักฐาน (ปิดบัญชีแล้วยอดเป็นศูนย์เสมอ)
4. GL อ่าน `fa_records` ตรง (ทางเลือก: provider interface ฉีดจาก `httpapi`)
5. แม่แบบเก่าไม่มีคีย์ = ไม่มีคำแนะนำ
6. แก้ชื่อบรรทัดแล้วคีย์ยังอยู่; ยังไม่มีตัวเลือกคีย์รายบรรทัด (ต้องขออนุมัติก่อนทำ)
7. บัญชีเงินสด/ยอดปกติล็อกหลังมีรายการ (snapshot ใน `gl_lines`)
