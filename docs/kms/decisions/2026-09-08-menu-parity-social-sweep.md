# เพิ่มเมนูอีก 6 รายการจากการกวาดหาแหล่งนอกเว็บทางการ (โซเชียล/รีวิว/คู่มือผู้ใช้)

ต่อจาก [2026-09-08-menu-parity-flowaccount-peak.md](2026-09-08-menu-parity-flowaccount-peak.md)

## Context

รอบก่อนเทียบจาก **หน้าเว็บทางการ** ของ FlowAccount + PEAK อย่างเดียว (411 ฟีเจอร์) แล้วสรุปว่า "ครบ 100%" — ลุงจืดสั่งเพิ่มว่า **"หาตามโซเชียล และที่อื่นๆ ด้วย"** เพราะหน้าทางการมักไม่ลงรายละเอียดฟีเจอร์ย่อย

รอบนี้กวาด 12 มุมพร้อมกัน (คู่มือผู้ใช้ · ศูนย์ช่วยเหลือ · YouTube/ช่องสอนใช้งาน · กลุ่ม Facebook ผู้ใช้งาน · Pantip/บล็อกรีวิว · หน้าราคา/แพ็กเกจ · release note · เว็บบอร์ดบัญชี ฯลฯ) ได้ข้อกล่าวอ้าง 442 รายการ → ฟีเจอร์ไม่ซ้ำ 434 → คัดเหลือผู้เข้าชิง 59 → ผ่านการตรวจซ้ำแบบหักล้าง **16 รายการ ซึ่งยุบเหลือฟีเจอร์จริง 3 เรื่อง**

## Decision

เพิ่มเมนู **6 รายการ + กลุ่มใหม่ 1 กลุ่ม** → รวม **218 → 224 รายการ**

| เมนู | route | ที่อยู่ | ที่มา |
|---|---|---|---|
| แบบยื่น ภ.ง.ด.2 | `/report/vatpnd2` | รายงาน › รายงานภาษี | คู่มือ PEAK Tax + ยืนยันกับ **กรมสรรพากร** `https://efiling.rd.go.th` |
| กำไรขาดทุนตามสาขาและแผนก | `/report/dimensionpnl` | รายงาน › รายงานการเงิน | PEAK Board (มิติสาขา/แผนก) |
| ดึงคำสั่งซื้อจากร้านค้าออนไลน์ | `/transaction/marketplaceorder` | งานประจำ › ขาย | FlowAccount e-commerce + PEAK ระบบจัดการร้านค้าออนไลน์ |
| เชื่อม Shopee / Lazada / TikTok | `/marketplace/shopee` · `/marketplace/lazada` · `/marketplace/tiktok` | ข้อมูลหลัก › เชื่อมข้อมูลตลาดออนไลน์ | เดียวกัน |

**ภ.ง.ด.2 ไม่ขัดกับกฎ "ไม่ทำเงินเดือน"** — เป็นภาษีหัก ณ ที่จ่ายของเงินได้ 40(3)/(4) คือ ดอกเบี้ย เงินปันผล ค่าสิทธิ ที่จ่ายให้บุคคลธรรมดา ต้นทางคือรายการจ่ายเงินในระบบ ไม่ใช่เงินเดือน (ต่างจาก **ภ.ง.ด.1** ที่ยังตัดออกตามเดิม)

**สามจอ marketplace มีอยู่จริงแล้วแต่ผู้ใช้เข้าไม่ถึง** — `frontend/src/app/menu/marketplace-screen.tsx` ทำงานได้ครบ (สถานะเชื่อมต่อ ตารางจับคู่ SKU นำเข้าเป็นชุด) และ `main-menu-screen.tsx` ก็ dispatch ไว้แล้ว แต่ `onOpenRoute` เปิดแท็บได้เฉพาะ route ที่มีในเมนู (`main-menu-screen.tsx:1453-1455`) จึงเป็น **จอกำพร้า** มาตลอด รอบนี้แค่ต่อสายเมนูก็ใช้ได้ทันที — ไม่ใช่การสร้างของใหม่

## Alternatives

- คงคำว่า "ครบ 100%" ตามรอบก่อน — ปฏิเสธ: การกวาดนอกเว็บทางการเจอช่องว่างจริงเพิ่ม 3 เรื่อง แปลว่าคำสรุปเดิมเกินจริง
- ตั้งชื่อเมนู marketplace แบบกลาง ๆ ไม่เอ่ยชื่อแพลตฟอร์ม — ปฏิเสธ: กฎชื่อกลางบังคับที่ **โมเดลข้อมูล/ฟิลด์/API** ไม่ใช่ป้ายเมนูที่ผู้ใช้ต้องรู้ว่ากำลังเชื่อมร้านไหน; language key `shopee_mappings`/`lazada_mappings`/`tiktok_mappings` และไอคอนมีอยู่ในระบบก่อนแล้ว รอบนี้ใช้ของเดิมไม่ตั้งชื่อใหม่
- รอทำจอ ภ.ง.ด.2 / dimension P&L ก่อนค่อยเพิ่มเมนู — ปฏิเสธ: BC ใช้เมนูเป็นแผนผังงาน เมนูที่ยังไม่มีจอแสดงการ์ด "Flutter route เดิม" ตามแพทเทิร์นเดิม

## Consequences

- ✅ 3 จอ marketplace ที่เขียนเสร็จแล้วกลับมาใช้งานได้ โดยไม่ต้องเขียนโค้ดจอเพิ่ม
- ✅ ครบชุดแบบยื่นหัก ณ ที่จ่ายฝั่งนิติบุคคล (ภ.ง.ด.2 / 3 / 53) — เดิมข้าม 2 ไป
- ⚠️ คำว่า "ครบ 100%" ในเอกสารรอบก่อนเกินจริง แก้ถ้อยคำแล้วใน `19-menu-coverage-flowaccount-peak.md` — รอบหน้าให้เขียนว่า "ครบเท่าที่หลักฐานชุดนี้ครอบคลุม"
- ⚠️ `/report/vatpnd2`, `/report/dimensionpnl`, `/transaction/marketplaceorder` ยังไม่มีจอจริง
- ⚠️ กฎ ภ.ง.ด.2 (อัตราหัก เงินได้ 40(3)/(4) กำหนดยื่นภายในวันที่ 7 ของเดือนถัดไป) ยังไม่ได้ลงรายละเอียดในระบบ — ตอนทำจอต้องตรวจกับกรมสรรพากรอีกครั้งตาม Rule 17
- ⚠️ dimension P&L ต้องใช้ master `/dimension` + `/department` + สาขา ที่มีอยู่แล้ว แต่ยังไม่มีการตัดสินว่ามิติใดบังคับกรอกบนเอกสาร
