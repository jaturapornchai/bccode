# แบบยื่นภาษีกรมสรรพากรทุกแบบใน `mydocs/sample`: backend ดึงยอดจาก GL → แก้ได้ทุกช่อง → บันทึกฉบับ → พิมพ์ลงแบบ PDF ทางการ

## Context

- ลุงจืดสั่ง (2026-09-23): "เพิ่มแบบฟอร์มสำหรับราชการมาให้แล้ว ไล่ดูให้หมด ทำระบบ frontend backend ให้สัมพันธ์กับฟอร์มด้วย เอาให้ครบ `mydocs/sample`" และย้ำ "ฐานภาษีต้องเปลี่ยนแปลงได้เสมอ" + ตรวจ PostgreSQL ทุกครั้ง
- `mydocs/sample` มี 23 ไฟล์ PDF ทางการ (AcroForm): ภ.ง.ด.1/1ก/2/2ก/3/53 (แบบ+ใบแนบ), ภ.ง.ด.50/51/93/94, ภ.ธ.40 (แบบ+ใบแนบ), ภ.พ.30 (แบบ+ใบแนบ), ภ.พ.36, 50 ทวิ (`50 ทวิ_master.pdf` กับ `หนังสือรับรองหัก ณ ที่จ่าย.pdf` เป็นไฟล์เดียวกัน md5 ตรงกัน)
- ของเดิม: ภ.พ.30 และ ภ.ง.ด.3/53 เป็น HTML จำลอง + `window.print()` (ตำแหน่งเพี้ยนตามเครื่องพิมพ์ ขัด skill §8.30), ภ.พ.36/ภ.ง.ด.2 ไม่มีแบบ, ที่เหลือไม่มีเลย
- ภ.ง.ด.1/1ก เป็นผลจากระบบเงินเดือน — อยู่นอกขอบเขต (AGENTS.md "ไม่ทำระบบเงินเดือน") จึงไม่ทำ

## Decision

1. **ตัวสร้างแบบกลาง `backend/internal/rdform`** — ทุกแบบเป็นข้อมูล ไม่ใช่โค้ดต่อแบบ
   - สเปกคนเขียนที่ `tools/rdform/specs/<code>.json` (ช่อง AcroForm หมายเลขไหน = key อะไร) → `tools/rdform/rdform_build.py` ตรวจเส้นแบ่งช่องบนแบบจริง (ช่องหลักเลข, บาท|สตางค์) แล้วเขียน `backend/internal/rdform/{assets,specs}` ที่ Go ฝังด้วย `go:embed` — วิธีเขียนสเปกอยู่ที่ `tools/rdform/README.md`
   - `rdform.Render` ถอดช่อง AcroForm แล้วประทับข้อความไทยด้วย `backend/internal/pdftext` (ย้ายมาจาก `whtcert/textpdf.go` ให้ใช้ร่วมกับ 50 ทวิ) → แก้ในโปรแกรมอ่าน PDF ไม่ได้ ตัวเลขอยู่ตำแหน่งตามแบบ
   - ใบแนบ 2 แบบ: `rows` (ตารางรายผู้มีเงินได้ — ระบบแบ่งแผ่นละ N แถว ใส่ลำดับ/แผ่นที่/ยอดรวมท้ายแผ่นเอง) และ `sheets` (หนึ่งแผ่นต่อหนึ่งรายการ — ภ.ธ.40)
   - `rdform.SchemaFor` คืนสเปกจอ (ไม่มีพิกัด): รวมคู่ `X_baht/X_satang` เป็นยอดเดียว `X`, รวม `X_d1..X_dN` เป็นช่องเดียว, ตัดช่องที่ระบบเติมเอง
   - `rdform.Validate` ตรวจทุกค่าก่อนบันทึก/พิมพ์ (เงินเป็น decimal ≤ 2 ตำแหน่ง, เลข 13 หลัก, ตัวเลือกต้องอยู่ในแบบ, ความยาว) → error เป็น key `tax_form_value_invalid` + `field` + `row`
2. **API `POST /api/report/tax/form/{catalog,schema,prefill,compute,pdf,save,list,load,delete}`** (`handlers/tax_form*.go`, สิทธิ์ตามบริษัทที่ login)
   - `prefill` เติมจากข้อมูลจริงเท่านั้น: หัวผู้ยื่นจากทะเบียนบริษัท + ที่อยู่/ผู้ลงนามจากฉบับล่าสุด; ภ.ง.ด.2/2ก/3/53 จาก `buildWithholdingReport` (ฐานที่บันทึกใน `details.withholdings` ก่อน ค่าประมาณจากบรรทัดบัญชี — มีหมายเหตุ `tax_form_note_inferred_base`); ภ.พ.30 จาก `generalledger.VatRecordsForPeriod` + `sumPP30` (ยอดเดียวกับรายงานภาษีซื้อ/ขาย); ภ.ง.ด.50/51 จากงบกำไรขาดทุน/งบดุลของปีบัญชี (ยอดรวมหลัก); ภ.พ.36/ภ.ธ.40/ภ.ง.ด.93/94 ผู้ใช้กรอก (`tax_form_note_manual`)
   - `compute` คำนวณเฉพาะบรรทัดรวมตามสูตรที่พิมพ์บนแบบ (ภ.พ.30 ข้อ 4, 8, 9, 11, 12, 15, 16 + ใบแนบรายสาขา, ภ.พ.36 ข้อ 5, ภ.ธ.40 ข้อ 12/15/17 + ยอดรายแผ่น, ยอดรวมหน้าแบบ ภ.ง.ด.2/2ก/3/53) ด้วย `shopspring/decimal` — ค่าที่ผู้ใช้แก้ (รวมฐานภาษี) ไม่ถูกทับ
   - `save/list/load/delete` เก็บฉบับที่ `tax_filings` (บริษัท+แบบ+งวด+ครั้งที่ยื่นเพิ่มเติม ไม่ซ้ำ, optimistic `version`) + `tax_filing_history` (ทุกรุ่นที่บันทึก) ในฐานข้อมูล holding; เงินในเอกสารเป็น string เสมอ
   - `pdf` ตรวจ → ยึดชื่อ/เลขผู้เสียภาษีจากทะเบียนบริษัท (แบบนิติบุคคล) → คืน `application/pdf`
3. **Frontend `TaxFormEditor`** (`frontend/src/app/tax/tax-form-editor.tsx`) — จอเดียวทุกแบบ สร้างจาก schema
   - เมนูเดิม ภ.พ.30/ภ.พ.36/ภ.ง.ด.2/3/53 เปิดแบบนั้นทันที (route/สิทธิ์เดิม) + เมนูใหม่ 1 รายการ "แบบยื่นภาษีทั้งหมด" `/report/taxforms` สำหรับ ภ.ง.ด.2ก/50/51/93/94, ภ.ธ.40 (เพิ่มเมนูเดียวแทน 6 เมนู ตามกฎ Zero-Bloat)
   - ป้ายช่องเป็นถ้อยคำบนแบบทางการ (ภาษาไทยตามกรมสรรพากร) — ส่วนอื่นของจอผ่าน `languages.tsv`
   - ลบของเดิม: แท็บแบบยื่น HTML ใน `tax-filing-workbench.tsx`, config แบบยื่นใน `thai-tax.ts`, `PP30SummaryHandler`/`computeVatSettlement`/`parseMoneyInput` และ route `/api/report/tax/pp30-summary` (ตามกฎเดินหน้าอย่างเดียว)

## Alternatives

- **HTML จำลองแบบ + `window.print()` ต่อแบบ** — ตัด: ตำแหน่งเพี้ยนตามเบราว์เซอร์/เครื่องพิมพ์, ต้องเขียน HTML ใหม่ทุกแบบ (≈ 20 หน้า), ขัด skill §8.30
- **กรอกค่าลงช่อง AcroForm ตรง ๆ (fill form)** — ตัด: ฟอนต์ไทยในช่องฟอร์มขึ้นกับโปรแกรมอ่าน (สระลอย/ตัวหาย), ผู้รับแก้ค่าในไฟล์ได้, ช่องหลักเลขบางแบบเป็นช่องเดียวต้องเว้นวรรคเอง
- **โค้ด Go ต่อแบบ (พิกัดในโค้ด)** แบบ `whtcert` — ตัดสำหรับแบบที่เหลือ: 17 ไฟล์ × หลายร้อยช่อง; สเปก JSON + ตัว build ที่วัดเส้นจากแบบจริงเร็วกว่าและตรวจซ้ำได้ (`--check`); 50 ทวิ คงใช้ `whtcert` เดิมเพราะต้องออก 2 ฉบับ + สำเนาคู่ฉบับ/ใบแทน
- **ให้ frontend คำนวณยอดรวม** — ตัด: กฎ backend-first และเงินห้ามเป็น JS number

## Consequences

- ✅ แบบทุกไฟล์ใน `mydocs/sample` (ยกเว้น ภ.ง.ด.1/1ก) ดึงยอด/แก้/บันทึก/พิมพ์ได้จากจอเดียว; PDF ตรงตำแหน่งแบบทางการเพราะใช้ไฟล์ของกรมเองเป็นพื้น
- ✅ ฐานภาษีและทุกช่องแก้ได้ก่อนบันทึก/พิมพ์; ฉบับที่บันทึกมีประวัติทุกรุ่น; บันทึกซ้อนกันได้ `tax_form_version_conflict`
- ⚠️ ภ.ง.ด.50 เติมเฉพาะยอดรวมจากงบ — รายการปรับปรุงทางภาษี/ค่าใช้จ่ายต้องห้ามผู้ใช้กรอกเอง; ภ.ง.ด.51 แสดงกำไรสุทธิครึ่งปีแรกจาก GL เป็นหมายเหตุ (`tax_form_note_cit_half_profit`) ให้ผู้ใช้ประมาณการกำไรทั้งปีเอง
- ⚠️ ภ.พ.36 ยังไม่มีแหล่งข้อมูลใน GL (ผู้ใช้กรอก); ภ.ธ.40 ภาษีท้องถิ่นผู้ใช้กรอก; ภ.ง.ด.93/94 เป็นแบบบุคคลธรรมดา ยกชื่อ/ที่อยู่จากฉบับล่าสุดเท่านั้น
- ⚠️ ป้ายช่องเป็นภาษาไทยตามแบบทางการแม้เลือกภาษาอังกฤษ (แบบของกรมมีภาษาเดียว)
- ⚠️ แบบใหม่ของกรมสรรพากร (เปลี่ยนฉบับ) ต้องวาง PDF ใหม่ใน `mydocs/sample` (ลุงจืด) แล้วรัน `rdform_build.py` — ตัว build เตือนช่องที่ไม่ได้ใช้/ช่องหาย

## Evidence

- `go test ./internal/rdform/ ./internal/pdftext/ ./internal/whtcert/ ./internal/goapi/handlers/` ผ่าน (`TestRenderEveryForm`, `TestSchemaEveryForm`, `TestComputePP30` 6 กรณี ฯลฯ); integration `TestTaxFilingStorage` + `TestTaxFormFillFromLedger` (ภ.พ.30 จาก `details.vats`: ขาย 119,000 ภาษีขาย 6,930 ซื้อ 50,000 ภาษีซื้อ 3,500 ยกมา 400 → ชำระ 3,030) ผ่านบน PostgreSQL 18
