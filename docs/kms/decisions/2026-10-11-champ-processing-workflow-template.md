# งานประมวลผลและ workflow ยึด Champ เป็นต้นแบบเสมอ (2026-10-11)

## ที่มา
ลุงจืดสั่ง 2026-10-11: *"ตั้ง กฏ ให้ดูการประมวลผล work flow จาก bc (champ) เป็นต้นแบบเสมอ"*

กฎเดิม ([`2026-09-19-champ-parity-menu-cut.md`](2026-09-19-champ-parity-menu-cut.md), [`2026-10-09-champ-parity-purpose-additive-extras.md`](2026-10-09-champ-parity-purpose-additive-extras.md)) บังคับให้ตรวจ Champ ก่อนออกแบบเมนู จอ ฟิลด์ และ API แต่ไม่ได้บังคับเรื่องลำดับการประมวลผลไว้ชัด ผลคือหลายงานในรอบ 2026-10-11 ใช้ตรรกะที่คิดขึ้นเอง ตัวอย่างเช่น การตัดหนี้เกินยอด การยกเลิกเอกสาร การล็อกงวด และอายุหนี้ ซึ่งต้องย้อนไปเทียบกับ Champ ทีหลัง

## Decision
1. **ขอบเขต:** ครอบคลุมงานประมวลผลทุกชนิด ไม่ใช่แค่หน้าจอ ได้แก่
   - บันทึก ตรวจ อนุมัติ
   - ผ่านรายการลงบัญชีแยกประเภท
   - ตัดหนี้และจัดสรร
   - ตัดสต็อกและคำนวณต้นทุน
   - ยกเลิกและกลับรายการ
   - ล็อกงวด ปิดงวด และประมวลผลสิ้นปี
   - รายงาน
2. **ก่อนออกแบบหรือแก้ไข ต้องไล่โค้ดประมวลผลจริงของ Champ** จากแหล่งต่อไปนี้
   - `D:\project-champ\champ-lib\BC5PROCESS` เช่น `gltlsprocess.cpp`, `glautoprocess.cpp`
   - `.cpp` ของจอที่เกี่ยวข้อง (เข้ารหัส CP874)
   - `champ/champ/Script/SQLSERVER_Script.sql`
   - ภาพจอและคู่มือใน `bcspec/`

   แล้วสรุปให้ได้ 5 อย่าง:
   1. ลำดับขั้น
   2. สถานะหรือ flag ของเอกสาร
   3. เงื่อนไขตรวจและข้อความเตือน
   4. ตารางและยอดที่ถูกกระทบ
   5. วิธีย้อนกลับเมื่อแก้ ลบ หรือยกเลิก
3. **ทำตามผลที่สรุปได้ และอ้างอิง Champ แบบ `file:line`** ไว้ในเอกสารออกแบบ ADR หรือ commit body
4. **ต่างจาก Champ ได้เฉพาะ 3 กรณี** และต้องรายงานส่วนที่ต่างไว้ในสรุปท้ายงาน
   - (ก) กลไกทางเทคนิคที่ให้ผลลัพธ์ทางบัญชีเท่ากัน เช่น บันทึกและลงบัญชีใน `BEGIN … COMMIT` เดียวกันแทนการประมวลผล GL แบบ batch ตามกฎ PostgreSQL อย่างเดียว
   - (ข) ข้อบังคับกฎหมายบัญชีหรือภาษีไทย
   - (ค) คำสั่งของลุงจืด
5. **หาใน Champ ไม่เจอหรืออ่านไม่ออก** ให้ถามลุงจืด ห้ามคิด workflow ขึ้นเอง

## Consequences
- งานประมวลผลแต่ละชิ้นใช้เวลาเพิ่มในขั้นอ่าน Champ แต่ลดการแก้ย้อนหลัง และผู้ใช้เดิมเจอขั้นตอนที่คุ้นเคย
- Champ ประมวลผล GL แบบ batch ส่วน BC ลงบัญชีทันทีแบบ synchronous ดังนั้นสิ่งที่ต้องเท่ากันคือ **ผลลัพธ์ ลำดับขั้น และเงื่อนไข** ไม่ใช่กลไก
- design doc, ADR และ commit body ของงานประมวลผลต้องมีส่วนอ้างอิง Champ ผู้ตรวจ (opus) ใช้เป็นเกณฑ์ตรวจรับได้
- กฎอยู่ที่ `AGENTS.md` หมวด "ยึด `D:\project-champ` เป็นต้นแบบ" และฉบับเต็มอยู่ที่ `docs/kms/rules/agents-full.md` ข้อ 3.1
