# ใบ 50 ทวิ: backend สร้าง PDF บนแบบฟอร์มจริงของกรมสรรพากร — frontend แค่แสดง

## Context

- ลุงจืดสั่ง (2026-09-23): ต้องการแบบฟอร์มตาม `mydocs/sample/50 ทวิ_master.pdf`, "ตัวเลขลงตามแบบฟอร์ม ตำแหน่งตามแบบ 100%", "backend เป็นคนสร้างฟอร์ม frontend แค่เอามาแสดง สร้างเป็น pdf", ลงทุกช่อง ทุกตัวเลือก ทดสอบหลายแบบ
- ไฟล์ตัวอย่างเป็นไฟล์เดียวกับ `https://www.rd.go.th/fileadmin/tax_pdf/withhold/approve_wh3_081156.pdf` (byte ตรงกัน) — A4 595×842 pt มีช่อง AcroForm 83 ช่อง
- ข้อกำหนดทางการ (คำแนะนำกรมสรรพากร `guide100248.pdf`): ออกให้ผู้ถูกหัก **2 ฉบับข้อความตรงกัน** — ฉบับที่ 1 "ใช้แนบพร้อมกับแบบแสดงรายการ", ฉบับที่ 2 "เก็บไว้เป็นหลักฐาน"; ผู้ออกต้องทำ **สำเนาคู่ฉบับ** เก็บไว้ออก **ใบแทน** เมื่อชำรุดสูญหาย (มีคำว่า "ใบแทน" ด้านบน); ทำเครื่องหมาย ✓ ในช่อง; ลายมือชื่อพิมพ์จากภาพที่ scan ได้; เนื้อความต้องครบตามแบบ (ประกาศอธิบดีฯ ฉบับที่ 131)
- ค้นตัวอย่าง "ใบที่กรอกแล้ว" บนเว็บ (rd.go.th คู่มือโปรแกรม 50 Tawi Generator, บทความภาษีทั่วไป) — ไม่พบตัวอย่างทางการที่กรอกครบ มีแต่ฟอร์มเปล่า จึงยึดกฎจาก guide ข้างบน + ตำแหน่งช่อง AcroForm ของกรมเอง

## Decision

1. **Package ใหม่ `backend/internal/whtcert`** (ไม่ผูก DB): `Render(Certificate) ([]byte, error)`
   - ฝังฟอร์มทางการ `assets/50tawi-rd.pdf` + ฟอนต์ `assets/Sarabun-Regular.ttf` (OFL) ด้วย `go:embed`
   - ถอดช่อง AcroForm ทั้งหมดครั้งเดียว (pdfcpu `RemoveFormFields`) → ข้อความของเราเป็นตัวจริงตัวเดียว แก้ในโปรแกรมอ่าน PDF ไม่ได้
   - ชั้นข้อความ: จัดรูปอักษรไทย (สระบน/ล่าง วรรณยุกต์ซ้อน) ด้วย `go-text/typesetting` (HarfBuzz, BSD/Unlicense) แล้วเขียน PDF เองแบบ CIDFontType2 Identity-H + ToUnicode (ค้นหา/คัดลอกข้อความได้) — `textpdf.go` (ย้ายเป็น package `backend/internal/pdftext` 2026-09-23 ให้แบบยื่นกรมสรรพากรใช้ร่วม — ADR `2026-09-23-rd-tax-forms-engine.md`)
   - ประทับชั้นข้อความหน้า i ลงแบบฟอร์มหน้า i (pdfcpu multistamp) → หน้า 1 = ฉบับที่ 1 (✓ หน้าข้อความ "ฉบับที่ 1"), หน้า 2 = ฉบับที่ 2, หน้า 3 = "สำเนาคู่ฉบับ" (ถ้า `archivecopy`), `replacement` พิมพ์ "ใบแทน" มุมขวาบน
   - พิกัดทุกช่องอยู่ที่ `layout.go` วัดจากฟอร์มจริง (เส้นกรอบจาก raster 8×, baseline จาก text layer, ตำแหน่ง AcroForm เดิม) — จำนวนเงินแยก **บาท | สตางค์** ตามเส้นแบ่งบนฟอร์ม, เลข 13 หลักลงช่องละหลัก, ✓ เป็นเส้นวาด (Sarabun ไม่มี glyph ✓)
   - ตรวจก่อนสร้าง: เลข 13 หลัก + หลักตรวจสอบ mod 11, ยอดเงินเป็น decimal string ≤ 2 ตำแหน่ง ห้ามติดลบ, ภาษี ≤ ยอดจ่าย, ประเภทเงินได้ห้ามซ้ำ, ช่อง "ระบุ" ต้องมีเมื่อเป็นบรรทัด (1.4)/(2.5)/6 และห้ามมีในบรรทัดอื่น, ข้อความยาวเกินช่องย่อฟอนต์ถึง 7pt แล้วค่อย error — error เป็น language key (`wht_cert_*` ใน `languages.tsv`)
   - **ยอดรวมและตัวอักษรไทยคำนวณที่ backend เสมอ** (`BahtText` ย้ายจาก `handlers/tax_money.go` มาอยู่ที่นี่ ใช้ร่วมกับรายงาน WHT)
2. **Endpoint `POST /api/report/tax/wht/certificate`** (`handlers/wht_certificate.go`) → `application/pdf`
   - สิทธิ์ตามบริษัทที่ login (`authenticatedCompanyContext`); ชื่อ + เลขผู้เสียภาษีผู้หักยึด **ทะเบียนบริษัท** เมื่อทะเบียนมีค่า (กันออกในนามบริษัทอื่น); ที่อยู่ผู้หักยังรับจากหน้าจอเพราะทะเบียนบริษัทยังไม่มีคอลัมน์ที่อยู่
3. **Frontend แค่แสดง** — ส่งข้อมูลที่เตรียมจากรายงาน WHT ไปให้ backend แล้วแสดง PDF ที่ได้ (ลบใบ HTML จำลองในแท็บ 50 ทวิ)

## ตัวเลือกบนฟอร์มที่รองรับ (ครบทุกช่องของแบบ)

- แบบยื่น: ภ.ง.ด.1ก, 1ก พิเศษ, 2, 3, 2ก, 3ก, 53 (`form` = `1a`, `1a_special`, `2`, `3`, `2a`, `3a`, `53`)
- ประเภทเงินได้ 15 บรรทัด: 40(1), 40(2), 40(3), 40(4)(ก), 40(4)(ข)(1.1)–(1.4), (2.1)–(2.5), 5. มาตรา 3 เตรส, 6. อื่น ๆ
- ผู้จ่ายเงิน: (1) หัก ณ ที่จ่าย (2) ออกให้ตลอดไป (3) ออกให้ครั้งเดียว (4) อื่น ๆ (ระบุ)
- กองทุน กบข./กสจ./ครูเอกชน, ประกันสังคม, สำรองเลี้ยงชีพ; เลขประจำตัวแบบเดิม 10 หลัก; เล่มที่/เลขที่/ลำดับที่ในแบบ; วันที่ออก (วัน / เดือนไทย / พ.ศ.)
- หมายเหตุขอบเขต: บรรทัด 40(1), ภ.ง.ด.1ก และช่องกองทุนเป็นเรื่องเงินเดือน — renderer รองรับเพื่อให้ตรงแบบทางการ แต่ BC ไม่ทำระบบเงินเดือน (AGENTS.md) ข้อมูลจากระบบจึงไม่เติมช่องเหล่านี้

## Alternatives

- **กรอก AcroForm เดิมของกรม** — ตำแหน่งตรงแต่ค่าแก้ได้ในโปรแกรมอ่าน PDF, ไทยซ้อนสระขึ้นกับ viewer, ช่องเงินไม่แยกบาท/สตางค์ → ไม่เลือก
- **`tdewolff/canvas` วาดชั้นข้อความ** — ใช้ได้ (spike ผ่าน) แต่ดึง dependency ที่ไม่ใช้จำนวนมาก (tex, goldmark, go-chart, xgb …) ขัดหลัก "เล็ก" → เขียนตัวเขียน PDF ~250 บรรทัดเองแทน
- **HTML + window.print() (ของเดิม)** — ตำแหน่งขึ้นกับเบราว์เซอร์/เครื่องพิมพ์ และคำนวณที่ browser → ขัดกฎ backend-first

## Consequences

- เพิ่ม dependency: `github.com/pdfcpu/pdfcpu` (Apache-2.0), `github.com/go-text/typesetting` (BSD-3/Unlicense); binary ใหญ่ขึ้นเล็กน้อย + ฟอร์ม 475 KB และฟอนต์ 82 KB ฝังใน binary
- PDF หนึ่งใบ (2 หน้า) ~186 KB, มีสำเนาคู่ฉบับ ~206 KB — สร้างใน ~10 ms (วัด 2026-09-23, benchmark 20 รอบ)
- ทดสอบ: `go test ./internal/whtcert/` (8 ตัวอย่างครอบคลุมทุกตัวเลือก + 17 กรณีปฏิเสธ + ตรวจว่าไม่มี AcroForm เหลือ), `go test ./internal/goapi/handlers/ -run WhtCertificate`; ดูไฟล์ตัวอย่าง: `WHT_CERT_SAMPLE_DIR=<dir> go test ./internal/whtcert/ -run TestRenderSamples`
- ถ้ากรมสรรพากรเปลี่ยนแบบฟอร์ม: เปลี่ยน `assets/50tawi-rd.pdf` แล้ววัด `layout.go` ใหม่ทั้งชุด
