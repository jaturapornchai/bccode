# Symptom

ผ่านรายการค่าเสื่อมราคาหรือจำหน่ายสินทรัพย์ถาวรเข้า GL แล้ว:

- สินทรัพย์ที่ไม่ได้กรอกรหัสบัญชี ถูกลงบัญชี `520103` / `129101` / `120101` / `110101` / `530101` / `420101` / `210301` ซึ่งไม่มีในผังบัญชีของบริษัทส่วนใหญ่ — ถ้ารหัสนั้นบังเอิญมีอยู่ก็ลงผิดบัญชีเงียบ ๆ
- จอสินทรัพย์เติมรหัสเหล่านี้ไว้ในฟอร์มล่วงหน้า (ช่องบัญชี 3 ช่องล้างไม่ได้ เพราะ `value={x || "120101"}`)
- ใบจำหน่าย `JV-DISP-<รหัสสินทรัพย์>` ยาวเกิน 30 ตัวอักษรเมื่อรหัสสินทรัพย์ยาว (เช่นรหัสไทยมีสระ/วรรณยุกต์) → GL ตอบ `code_too_long` ที่ผู้ใช้แก้ไม่ได้ เพราะไม่ได้พิมพ์เลขนั้นเอง; ทั้งค่าเสื่อม (`JV-FA-…`) และจำหน่ายขึ้นต้น "JV" ทั้งที่สมุดรายวันเป็นข้อมูลที่ผู้ใช้กำหนดเอง
- ใบสำคัญจากสินทรัพย์ไม่ผ่านการตรวจสาขาหัวเอกสาร — session ระดับบริษัทบันทึกสาขาว่างได้, session สาขาจำหน่ายสินทรัพย์ของสาขาอื่นได้
- ข้อความยอดไม่สมดุลแปลงเงินเป็น float (`InexactFloat64`)

## Root Cause

`backend/internal/fixedasset/gl_poster.go` ใส่รหัสบัญชีสำรองตายตัวเมื่อช่องว่าง (ละเมิดกฎ "ห้ามใช้รหัสบัญชีเป็นเงื่อนไข/ค่าเดา — ผังบัญชีแต่ละบริษัทต่างกัน"), สร้างเลขใบสำคัญด้วย prefix `"JV"` โดยไม่ตรวจความยาว, และเรียก GL engine ตรง ๆ โดยไม่ผ่าน `checkJournalBranch` ที่หน้าบันทึกรายวันใช้ (`generalledger/httpapi/branch.go`) ส่วนจอ `frontend/src/app/asset/fixed-assets-screen.tsx` คัดลอกรหัสชุดเดียวกันมาเป็นค่าเริ่มต้น

## Fix

- **บัญชี:** สินทรัพย์ → ประเภทสินทรัพย์ (`resolveAssetAccounts`) → ถ้าไม่มีทั้งคู่ตอบ `fa_account_required` ภาษาไทยพร้อม `field` (`deprecexpenseaccountcode`, `accumdeprecaccountcode`, `assetaccountcode`) และรายชื่อสินทรัพย์ที่ขาด (ไม่เกิน 10 รหัส + "และอีก N รายการ") — ไม่เดารหัส; บัญชีรับชำระ / กำไรขาดทุน / ภาษีขาย ของการจำหน่ายต้องมาจากผู้ใช้เมื่อมียอด (`settlementaccountcode`, `gainlossaccountcode`, `vataccountcode` ช่องใหม่)
- **เลขใบสำคัญ:** ขึ้นต้นด้วยรหัสสมุดประเภททั่วไปที่เลือก (`<book>-FA-<ปี>-<งวด>`, `<book>-DISP-<รหัสสินทรัพย์>`), ตรวจด้วย `gl.CheckDocNo` (นับ rune, 30 ตัว) ก่อนแตะข้อมูล — ถ้าเลขที่ระบบสร้างยาวเกินบอกเลขที่สร้าง จำนวนตัวอักษร และให้ระบุเอง; การจำหน่ายรับ `journaldocno` จากผู้ใช้ได้ (จอมีช่อง "เลขที่ใบสำคัญ (เว้นว่าง = ระบบสร้างให้)" `maxLength=30`)
- **สาขา:** `GLPoster` รับ `BranchChecker` ที่ต่อกับ `glhttp.CheckJournalBranch` (กฎเดียวกับหน้าบันทึกรายวัน) ครอบคลุมทั้ง HTTP และ MCP; ค่าเสื่อมรับ `branchcode` (เว้นว่าง = สาขาที่เข้าระบบ), การจำหน่ายใช้สาขาของสินทรัพย์พร้อมข้อความที่ชี้สินทรัพย์; ไม่มีตัวตรวจ = ปฏิเสธ (fail closed)
- **เงิน:** ข้อความยอดไม่สมดุลใช้ `decimal.String()` (เต็มความละเอียด), ข้อความขาดบัญชีแสดงยอด `StringFixed(2)` เช่น "14000.00 บาท"; ลำดับบรรทัดค่าเสื่อมเรียงตามรหัสบัญชี (เดิมวน map ทำให้ลำดับสุ่ม — retry เลขเดิมอาจถูก GL ปฏิเสธว่าเป็นใบคนละใบ)
- รายการค่าเสื่อมที่หาสินทรัพย์ไม่พบ → ปฏิเสธ (เดิมข้ามบรรทัดแต่ยังทำเครื่องหมายว่าผ่านรายการแล้ว)
- HTTP ส่ง `code` + `field` ของ `gl.UserError` ต่อให้จอ (`failure()` ใน `fixedasset/httpapi/http.go`)

## ยังไม่ได้แก้ (นอกขอบเขตงานนี้)

- จอ "ผ่านรายการค่าเสื่อม" ยังไม่มีช่องเลือกสาขา — ผู้ใช้ที่เข้าระบบระดับบริษัทจะได้ข้อความให้เลือกสาขา ต้องเข้าระบบในสาขาก่อน (API/MCP ส่ง `branchcode` ได้แล้ว)
- ช่องราคาขายในหน้าต่างจำหน่ายคำนวณ VAT 7% ด้วย `Number()` (float) ฝั่ง browser
- MCP `fa_create_asset` / `fa_dispose_asset` รับยอดเงินเป็น JSON number (`AmountFromFloat`)
- ปีบัญชีของใบจำหน่ายตัดจาก 4 ตัวแรกของวันที่ (ปีปฏิทิน) ไม่ได้หาจากปีบัญชีของบริษัท
- สินทรัพย์ที่จำหน่ายแล้วยังมีรายการค่าเสื่อมงวดหลังวันจำหน่ายค้างอยู่ และจะถูกผ่านรายการในงวดถัดไป
- การผ่านค่าเสื่อมจาก session สาขาดึงสินทรัพย์ทุกสาขาของบริษัทมาลงใบของสาขาที่เข้าระบบ
- หน้าต่างจำหน่ายและปุ่มบันทึกแจ้งผิดพลาดด้วย `alert()` ของ browser (ไม่ใช่ dialog/ข้อความในจอตามมาตรฐาน UI) — ข้อความจาก backend ถึงผู้ใช้ครบ แต่ไม่ชี้ช่องที่ต้องแก้ (`field`)
- เปิดจอสินทรัพย์ครั้งแรกของ holding ใหม่: `GET /api/fa/assets` ตอบ 500 `duplicate key … pg_type_typname_nsp_index` เพราะ request ประเภทกับสินทรัพย์สร้างตาราง `fa_records` พร้อมกัน (`CREATE TABLE IF NOT EXISTS` ชนกัน) — โหลดซ้ำแล้วหาย (พบตอนทดสอบบนจอ 2026-09-24)
