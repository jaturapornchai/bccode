# Symptom

บริษัทที่ตั้งรหัสปีบัญชีเป็น พ.ศ. กด **ผ่านรายการค่าเสื่อมราคาเข้า GL** แล้วได้ข้อความ "ไม่สามารถบันทึกสมุดรายวัน GL: กรุณาตั้งค่าปีบัญชีก่อนบันทึกรายการ" แม้บริษัทจะตั้งปีบัญชีไว้แล้ว ตัวอย่างคือ prod `rungrueng/01` ที่ใช้รหัส `2569` = 2026-01-01..2026-12-31

พบตอน UAT บน prod r20260925-5 จึงยังตรวจการปฏิเสธ `fa_schedule_posted` (409) และ `reverse-gl` บน prod ไม่ได้ การจำหน่ายสินทรัพย์ก็เจอปัญหาเดียวกัน

# Root Cause

- ตารางค่าเสื่อม (`calculator.go`) เก็บปีเป็นปีปฏิทิน ค.ศ. (`fiscalyear` = "2026") กับเดือน 1–12
- `GLPoster.PostDepreciation` (`backend/internal/fixedasset/gl_poster.go`) ส่งปีนี้ไปเป็น `gl.Journal.FiscalYear` ตรง ๆ
- `DisposeAsset` ใช้ `DisposalDate[:4]` เป็นรหัสปีบัญชี
- GL หาปีบัญชีด้วย **รหัส** แบบตรงตัว (`generalledger/postgres_guards.go` `pgYear`) แล้ว `Journal.Validate` (`models.go`) บังคับ `j.FiscalYear == f.Code`
- รหัสปีบัญชีเป็นข้อความที่ผู้ใช้ตั้งเอง จะเป็น พ.ศ. หรืออย่างอื่นก็ได้ และปีบัญชีเริ่มเดือนไหนก็ได้ ค.ศ. จึงไม่ใช่รหัสปีบัญชี
- test เดิมสร้างปีบัญชีรหัส "2026" ตรงกับ ค.ศ. จึงไม่เคยจับได้ (`gl_poster_integration_test.go`)

Champ ไม่มีรหัสปีบัญชีเลย ใบสำคัญหางวดจากวันที่ (`DocDate BETWEEN StartDate AND StopDate`: `FSTransferToGLDlg.cpp:356-365`, `mytools.cpp:834-866`, `glautoprocess.cpp:60-79`) ส่วนช่องปีบนจอโอนเข้า GL รับ พ.ศ. แล้วลบ 543 เมื่อเกิน 2400 (`FSTransferToGLDlg.cpp:197-202`) — ระบบใหม่ไม่ทำตามข้อนี้ เพราะจอสินทรัพย์ทุกจอใช้ ค.ศ.

# Fix

`backend/internal/fixedasset/gl_fiscal_year.go`:

- **`fiscalYearCodeAt` + `pickFiscalYear`** อ่าน `fiscal-years` ผ่าน `ledger.List` (แบบเดียวกับ `generalBookCode`) แล้วคืน **รหัสของปีบัญชีที่ครอบคลุมวันที่ของใบสำคัญ** (ขอบวันแรกและวันสุดท้ายนับรวม)
  - ไม่พบปีบัญชี → `fa_fiscal_year_not_found`
  - ปีบัญชีปิดแล้วหรือไม่ได้เปิดใช้ → `fa_fiscal_year_closed`
  - พบมากกว่าหนึ่งปี → `fa_fiscal_year_ambiguous` (ไม่เลือกแถวแรกเอง)
  - ทุกกรณีเป็น field error ภาษาไทย (400) ที่ชี้ช่องที่ต้องแก้ (`fiscalyear` / `date` / `disposaldate`)
  - ระบบไม่ถอยไปใช้ ค.ศ. และไม่สร้างปีบัญชีให้เอง
- **`depreciationVoucherDate`** ตรวจปีของงวด (ค.ศ. 4 หลัก ช่วงเดียวกับรายงานภาษี 1900–2400) → ผิด = `fa_post_year_invalid` ที่ช่อง `fiscalyear`
  - ตารางค่าเสื่อมเก็บ ค.ศ. ทุกจอของสินทรัพย์ใช้ ค.ศ. เหมือนกัน จึงไม่แปลง พ.ศ. ให้เอง (ป้อน "2569" จะถูกปฏิเสธพร้อมบอกให้ลบ 543)
  - **ไม่ระบุวันที่ = วันสิ้นงวด** (เกณฑ์คงค้าง: ค่าเสื่อมเป็นของงวดที่มันครอบคลุม) — เดิมใช้วันนี้ ทำให้ค่าเสื่อม ธ.ค. ที่ผ่านในเดือน ม.ค. ถูกลงปีบัญชีถัดไปเงียบ ๆ
- **`depreciationFiscalYear`** ปีบัญชีของใบ = ปีที่ครอบคลุมวันสิ้นงวด และวันที่ใบสำคัญต้องอยู่ปีเดียวกัน ไม่งั้น `fa_date_outside_period_year` (ข้อความบอกทั้งสองปีและวันสิ้นงวด) — ปีที่ปิดแล้วจึงยังปิดอยู่
- **`checkVoucherDate`** ตรวจรูปแบบวันที่ก่อนหาปี → `fa_date_invalid`
  - เดิมวันที่ค่าเสื่อมไม่ถูกตรวจ ส่วนวันที่จำหน่ายเป็น error ข้อความเปล่าที่ไม่ชี้ช่อง

ใน `gl_poster.go`:
- `PostDepreciation` และ `DisposeAsset` ใส่รหัสที่หาได้ลง `Journal.FiscalYear` และ `GLJournalDoc.FiscalYear`
- ปี ค.ศ. ของตารางยังใช้เป็นกุญแจแถว เลขที่ใบ และคำอธิบายเหมือนเดิม
- `ReverseDepreciation` ตรวจปีบัญชีของวันที่กลับรายการก่อนเรียก GL เพื่อให้ผู้ใช้เห็นข้อความไทยแทน `…: sql: no rows in result set`

อื่น ๆ:
- `languages.tsv` เพิ่ม `gl_err_fa_date_invalid`, `gl_err_fa_post_year_invalid`, `gl_err_fa_fiscal_year_not_found`, `gl_err_fa_fiscal_year_closed`, `gl_err_fa_fiscal_year_ambiguous`, `gl_err_fa_date_outside_period_year`
- GL ไม่ถูกแก้ ยังตรวจปีซ้ำใน transaction ของตัวเอง กรณีปีถูกปิดระหว่างทาง
- MCP เรียกฟังก์ชันเดียวกันจึงได้ผลตามไปด้วยโดยไม่แตะโค้ด MCP

# Regression Test

- `gl_fiscal_year_test.go` (unit):
  - `pickFiscalYear`: ปีเริ่มเมษายนรหัส พ.ศ., วันขอบปี, ปีปิด, ปีไม่เปิดใช้, ปีถูกลบ, ไม่พบ, ปีทับซ้อน
  - `depreciationVoucherDate`: ว่าง = วันสิ้นงวด (รวม ก.พ. ปีอธิกสุรทิน), ปี พ.ศ./ผิดรูป → `fa_post_year_invalid`
  - `depreciationFiscalYear`: ธ.ค. 2026 ผ่านวันที่ 2027-01-10 → ปีปิด หรือ `fa_date_outside_period_year`
  - ledger จำลองที่ fail ทันทีถ้ามีการเขียน GL: วันที่/ปีผิดต้องถูกปฏิเสธก่อนอ่านปีบัญชี และวันที่นอกปีต้องไม่ถึง GL
- `gl_fiscal_year_integration_test.go` (PostgreSQL จริง, `-tags integration`, ปีบัญชี 2568 ไม่เปิดใช้ / 2569 / 2570 เริ่ม 1 เม.ย.):
  - การปฏิเสธทุกแบบเกิดก่อนเขียน: ไม่มีใบใน `gl_records` และแถวตารางยังไม่ผ่าน
  - งวด 4/2026 ไม่ระบุวันที่ → ใบวันที่ 2026-04-30 `fiscalyear` = 2569, ยอดสมดุลเท่าตาราง, แถวตารางชี้เลขที่ใบ
  - มี.ค. 2027 ผ่านในเดือน พ.ค. (วันนี้อยู่ปี 2570) → ใบวันที่ 2027-03-31 ปี 2569; ม.ค. 2027 → 2569; เม.ย. 2027 → 2570
  - กลับรายการได้ `REV-…` ปี 2569 และแถวกลับเป็นยังไม่ผ่าน
  - วันที่กลับรายการนอกทุกปีบัญชี → `fa_fiscal_year_not_found` และไม่มีอะไรถูกเขียน
  - จำหน่ายในปี 2568 → `fa_fiscal_year_closed`; ในปี 2570 → ใบปี 2570
- `fixedasset_test.go`: ledger จำลองมีปีบัญชีรหัส พ.ศ. และตรวจ `FiscalYear` ของใบแบบเดียวกับ GL จริง
- **Mutation:** ใส่ `FiscalYear: fiscalYear` กลับ แล้ว test fail รวมตัว integration ที่ขึ้นข้อความเดียวกับ prod

# Open (ต้องให้ลุงจืดตัดสิน)

- **ผ่านซ้ำหลังกลับรายการ** (พบระหว่างรีวิว ไม่ได้แก้ในงานนี้): เลขที่ใบเดิมให้ requestID เดิม GL จึงคืนผลเก่าแทนสร้างใบใหม่ ขณะที่ตารางค่าเสื่อมถูกทำเครื่องหมายว่าผ่านแล้ว — ห้ามผ่านงวดเดิมซ้ำหลังกลับรายการจนกว่าจะแก้
- วันที่กลับรายการใช้ "วันนี้" แบบ UTC ไม่ใช่เวลาไทย
- ข้อความ error ของสินทรัพย์ยังเป็นไทยเสมอ (ชั้น HTTP ของ FA ยังไม่ใช้แถว `gl_err_fa_*` แปลตามภาษา)
- จอผ่านรายการ (`frontend/src/app/asset/fixed-assets-screen.tsx`) ไม่มีช่องวันที่ใบสำคัญ (Champ ให้แก้วันที่ได้) และค่าเริ่มต้นของช่องปีเป็น "2026" แบบ hard-code
- ตารางค่าเสื่อมคิดตามเดือนปฏิทิน ขณะที่ Champ คิดตามงวดบัญชี (`Depreciation.cpp:358-398`) บริษัทที่ปีบัญชีไม่เริ่มมกราคมจะเห็นความต่าง
- Champ ไม่ลงบัญชี GL ตอนขาย/จำหน่ายสินทรัพย์ (เก็บแค่ฟิลด์ขายใน `BCAssetsMaster`) ต้องยืนยันว่ายังต้องการใบจำหน่ายใน GL หรือไม่
- เลขที่ใบ / คำอธิบายยังแสดงปี ค.ศ. ของตาราง (`GJ-FA-2026-04`, "งวด 4/2026") แม้ใบอยู่ปีบัญชี 2569
