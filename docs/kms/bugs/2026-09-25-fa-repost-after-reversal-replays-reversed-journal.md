# Symptom

- กลับรายการใบค่าเสื่อมราคา (`reverse-gl`) แล้วผ่านงวดเดิมอีกครั้ง จอสินทรัพย์ตอบ "ผ่านรายการสำเร็จ" พร้อมเลขที่ใบเดิม (`GJ-FA-2026-07`) และทำเครื่องหมายตารางค่าเสื่อมว่าผ่านแล้ว แต่ **GL ไม่มีใบใหม่** ใบที่ได้กลับมาคือใบที่ถูกกลับรายการไปแล้ว ผลคือยอดค่าเสื่อมของงวดใน GL เป็น 0 ขณะที่ทะเบียนสินทรัพย์บอกว่าผ่านแล้ว ตัวเลขสองฝั่งไม่ตรงกันโดยไม่มีอะไรเตือน
- วันที่ของใบกลับรายการใช้ "วันนี้" แบบ UTC ถ้ากลับรายการช่วง 00:00–07:00 เวลาไทยจะได้วันที่ของเมื่อวาน
- จอผ่านรายการไม่มีช่องวันที่ใบสำคัญและเลขที่ใบ ส่วนช่องปีฝังค่า `"2026"` ไว้ ปีหน้าจะผ่านรายการผิดปี

**พบระหว่างรีวิวของงานนี้ (แก้ในงานเดียวกัน):**

- ใบกลับรายการลงวันที่ "วันนี้" แต่ใบใหม่ลงวันสิ้นงวดเดิม งวดเดิมจึงมีค่าเสื่อม 2 เท่า และเดือนที่กลับรายการติดลบ ถ้าข้ามปีบัญชี งบรายปีจะผิดด้วย
- ช่องเลขที่ใบบนจอทำให้คนสองคนผ่านงวดเดียวกันพร้อมกันด้วยเลขต่างกันได้ ทั้งสองคนอ่านแถวชุดเดียวกัน ค่าเสื่อมจึงลงซ้ำ
- เลขที่ใบที่พิมพ์เองแล้วซ้ำกับงวดอื่นได้ข้อความเทคนิค "รหัสคำขอนี้ถูกใช้แล้วด้วยข้อมูลที่ต่างกัน" ซึ่งไม่ชี้ไปที่ช่องเลขที่ใบ

# Root Cause

1. `postJournal` สร้าง requestID จากเลขที่ใบ (`backend/internal/fixedasset/gl_poster.go:211`, `:221`) และเลขที่ใบที่ระบบสร้างคงที่ต่อปี/งวด (`GJ-FA-<ปี>-<งวด>`) ผ่านงวดเดิมซ้ำจึงได้ requestID เดิม
2. GL เก็บ idempotency ใน `gl_events` และ **คืนผลเก่าก่อนตรวจสถานะ** คำขอซ้ำจึงได้ใบที่ตอนนี้เป็น `reversed` โดยไม่มี error
3. FA ทำเครื่องหมายตารางโดยไม่ตรวจว่าใบใน GL อยู่สถานะ `posted` จริง และเขียนทีละแถวแบบ autocommit ถ้าล้มกลางทาง งวดจะผ่านไปแค่ครึ่งเดียว
4. วันที่กลับรายการใช้ "วันนี้" แบบ UTC และไม่คำนึงว่าใบใหม่จะกลับไปลงงวดเดิม
5. ไม่มีอะไรกันการผ่านงวดเดียวกันพร้อมกัน การอ่านแถว→GL→ทำเครื่องหมายไม่อยู่ใน transaction เดียว (คำสั่ง GL แยก tx)

# Fix

`backend/internal/fixedasset/gl_repost.go` (ใหม่) + `gl_poster.go`:

- **`depreciationDocNo`** (`gl_poster.go:409`) เลือกเลขที่ใบก่อนส่ง GL จากใบใน GL ทั้งบริษัท (ไม่จำกัดสาขา อ่านทุกหน้า):

  | สถานะของเลขที่ใบใน GL | เลขที่ระบบสร้าง | เลขที่พิมพ์เอง |
  |---|---|---|
  | ยังไม่มีใบนี้ | ใช้เลขนี้ | ใช้เลขนี้ |
  | ใบของงวดนี้ (reference `FA-<ปี>-<งวด>`) เป็น draft/posted แต่**ยังไม่มีแถวตารางที่ทำเครื่องหมายด้วยเลขนี้** (ล้มกลางทาง) | ใช้เลขเดิม (retry = replay ไม่ลงซ้ำ) | ใช้เลขเดิม |
  | ถูกกลับรายการแล้ว | ใช้เลขถัดไป `-2`, `-3`, … | ปฏิเสธ `fa_docno_reversed` |
  | ผ่านเสร็จแล้ว หรือเป็นเอกสารอื่น | ใช้เลขถัดไป | ปฏิเสธ `fa_docno_in_use` |
  | ยาวเกิน 26 ตัว (`REV-` + เลขต้องไม่เกิน 30) | ปฏิเสธ `fa_docno_too_long_to_reverse` | ปฏิเสธ `fa_docno_too_long_to_reverse` |

- **`lockDepreciationPeriod`** (`gl_poster.go:278`) ใช้ `pg_try_advisory_lock` ระดับ session ต่อบริษัท+ปี+งวด บน connection ของตัวเอง ถ้าอีกคนกำลังผ่านงวดนั้นอยู่ จะได้ `fa_period_post_in_progress` (409) ทันที ไม่รอ เพื่อไม่ให้ถือ connection ใน pool ค้างไว้
- **`checkJournalPosted`** (`:430`) ตรวจซ้ำหลังผ่านรายการว่าใบเป็น `posted` ถ้าไม่ใช่จะได้ `fa_journal_not_posted` และไม่แตะตาราง
- **`setDepreciationPosted`** (`:459`, `:492`) ทำเครื่องหมายหรือล้างเครื่องหมายทุกแถวของใบใน `sql.Tx` เดียว
- **`ReverseDepreciation`** (`:474`): ถ้าใบถูกกลับรายการไปแล้ว (รอบก่อนล้มกลางทาง หรือกลับจากหน้าสมุดรายวัน) จะไม่เขียน GL ซ้ำ แค่ปลดแถวตาราง
- **`reversalDate`** (`:504`):
  - ถ้าวันที่ของใบเดิมยังเปิดอยู่ (ปีบัญชีเปิดและงวดไม่ถูกล็อก) ใบกลับรายการจะใช้**วันที่ของใบเดิม** งวดเดิมจึงรวมเป็น 0 และใบใหม่ลงงวดเดิมด้วยตัวเลขที่ถูก ผลเท่ากับ Champ ที่ลบใบแล้วสร้างใหม่ในงวดเดิม
  - ถ้าปีปิดหรืองวดล็อกแล้ว จะใช้**วันที่ไทยของวันนี้** (`businessDate`, `Asia/Bangkok`) และการผ่านงวดนั้นซ้ำจะถูกปฏิเสธด้วยปีปิดหรืองวดล็อกเดียวกัน จึงไม่นับซ้ำ
- วันที่จำหน่ายตั้งต้นใช้ `businessDate` (`:567`)
- จอ `frontend/src/app/asset/fixed-assets-screen.tsx`:
  - ปีและงวดตั้งต้นจากวันนี้ (`:52`)
  - เพิ่มช่องวันที่ใบสำคัญ (เว้นว่าง = วันสิ้นงวด) และช่องเลขที่ใบ แล้วส่ง `date`/`docno` ไป backend (`:258`)
  - dialog ยืนยันแสดงวันที่และเลขที่ใบที่จะใช้จริง (`:235`)
  - ข้อผิดพลาดแสดงเป็นกล่องเดียว `role="alert"` (`:1030`) แล้วโฟกัสช่องตาม `field` (`:230`) เลิกใช้ `alert()` ซ้อนกับแถบสถานะ
- แถวภาษา:
  - error: `gl_err_fa_docno_reversed`, `gl_err_fa_docno_in_use`, `gl_err_fa_docno_too_long_to_reverse`, `gl_err_fa_journal_not_posted`, `gl_err_fa_period_post_in_progress`
  - ป้ายบนจอ: `fa_period_year_ce`, `fa_voucher_date`, `fa_voucher_date_blank_period_end`, `fa_post_voucher_summary`, `fa_voucher_date_period_end`, `fa_docno_generated`
  - ลบ `fa_failed_reason` ที่ไม่มีใครใช้แล้ว

**ต่างจาก Champ โดยตั้งใจ:** Champ โอนซ้ำโดยลบใบเดิมแล้วสร้างใหม่ใต้เลขเดิม (`FSTransferToGLDlg.cpp:548-554`, `:1090-1094`) ระบบใหม่เป็น append-only ใบที่กลับรายการต้องอยู่ครบเพื่อ audit จึงใช้เลขต่อท้าย `-2`, `-3` แต่ผลต่องวดเหมือนกัน เพราะใบกลับรายการลงวันที่ของใบเดิม

  - ถอด `checkJournalPosted` จับได้เฉพาะ unit (เป็นชั้นป้องกันซ้อน)

- **ใบร่างที่ถูกลบหรือผ่านจากหน้าสมุดรายวันระหว่าง retry** (มีอยู่ก่อนงานนี้):
