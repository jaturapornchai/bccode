## 6. Retry / DLQ
- `myretry.WithRetry` exponential backoff (MaxRetries 3, BaseDelay 1 s → MaxDelay 30 s, ×2) — retry เฉพาะ error ที่ข้อความมี connection/timeout/temporary/unavailable/deadlock (`backend/internal/goapi/myretry/retry.go:22-49`, เงื่อนไข `:37-43`; ใช้ที่ `backend/internal/goapi/handlers/kafka/utils.go:65-92`)
- `SafeConsumerWrapper` = recover panic + retry + DLQ; หลัง retry หมดจะ `return finalErr` แต่ตาม §5 offset ถูก commit ไปแล้ว (`utils.go:37-118`, `finalErr` `:91-112`)
- **DLQ log-only**: `globalDLQHandler = NewLogDLQHandler()` (`dlq.go:131`) `LogDLQHandler.Send` เขียน `logger.Error` เท่านั้น (`:91-104`); `FileDLQHandler.Send` มี `// TODO: เขียนลงไฟล์จริง` (`:57`); `Get/List/Delete/Retry` ทั้ง File และ Log handler คืน `not implemented` (`backend/internal/goapi/mydlq/dlq.go:64-80,107-119`)
- ตาราง PG `deadletterqueue` มี INSERT ในชั้น queue worker (ไม่ใช่ Kafka DLQ) (`backend/internal/goapi/mypostgres/queue.go:169`)
- consumer-level reconnect: `ConsumeMessage` วน `consumeWithRetry` ไม่รู้จบ, backoff+jitter สูงสุด 30 s, กรอง transient error ด้วย string match (`kafka_consumer.go:95-136,243-271`)

## 7. ทำไมมี kafka-go กับ librdkafka สองตัว และต้องแยก group
- ความเห็นในโค้ด: kafka-go กับ librdkafka เข้ารหัส JoinGroup member metadata ต่างกัน — ถ้าใช้ group เดียวกันจะ rebalance ไม่จบหรือ reader ไม่ได้ partition → barcode reader ใช้ `group+"-projection"` (`backend/pkg/microservice/barcode_projection_consumer.go:13-18`)
- goapi ใช้ kafka-go ล้วน (`kafka_consumer.go:16`); legacy ใช้ librdkafka สำหรับ producer/admin/consumer (`backend/pkg/microservice/mq.go:10`, `producer.go:9`, `microservice_consumer.go:7`) — เป็นเหตุให้ build native Windows ไม่ได้ ต้อง Docker + librdkafka-dev (`docs/handoff/HANDOFF-2026-09-06.md:32-34`)
- outbox README ยืนยันสถานะ: 9 goapi topic + legacy barcode ใช้ acknowledged loop ร่วมกัน, topic legacy อื่นยัง transport เดิม (`backend/internal/product/product/outbox/README.md:13`)
