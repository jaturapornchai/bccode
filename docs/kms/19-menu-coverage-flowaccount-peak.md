# ความครบของเมนู BC เทียบ FlowAccount + PEAK
> ตรวจล่าสุด: 2026-09-08 (รอบที่ 2 — กวาดแหล่งนอกเว็บทางการ) — เทียบเมนูจริงใน `frontend/src/lib/menu-data.ts` กับฟีเจอร์ของ FlowAccount และ PEAK จาก 2 ชุดหลักฐาน: (1) หน้าทางการ flowaccount.com / peakaccount.com → 411 รายการ จับคู่ครอบคลุมแล้ว 230 คู่ ช่องว่างที่ยืนยันแบบหักล้าง 20 ข้อ · (2) แหล่งนอกทางการ 12 มุม (คู่มือผู้ใช้ ศูนย์ช่วยเหลือ YouTube กลุ่ม Facebook ผู้ใช้งาน Pantip/บล็อกรีวิว หน้าราคา release note เว็บบอร์ดบัญชี) → ข้อกล่าวอ้าง 442 รายการ ฟีเจอร์ไม่ซ้ำ 434 ผู้เข้าชิง 59 ยืนยันเป็นช่องว่างจริง 3 เรื่อง

## สรุปผล

หลังเพิ่มเมนูรอบนี้ BC ครอบคลุมงานของ FlowAccount และ PEAK Account **ครบทุกข้อเท่าที่หลักฐาน 2 ชุดข้างบนครอบคลุม** ในระดับ "มีเมนู" — รวม **224** รายการเมนู (จากเดิม 185 → 200 → 218 → 224)

> ⚠️ **อย่าเขียนว่า "ครบ 100%" อีก** — รอบแรกสรุปแบบนั้นจากหน้าเว็บทางการอย่างเดียว พอกวาดโซเชียล/คู่มือผู้ใช้เพิ่มก็ยังเจอช่องว่างจริงอีก 3 เรื่อง ความครบขึ้นกับชุดหลักฐานที่ใช้เสมอ โดยปิดช่องว่างที่เหลือทั้งหมด (ล็อต/วันหมดอายุ, ใบรวมจ่าย/ใบเสร็จรวม, บัตรเครดิตกิจการ, เงินทดรองจ่ายกรรมการ, ซื้อสินทรัพย์/งานระหว่างก่อสร้าง/ตารางสินทรัพย์, ภาษีเงินได้รอการตัดบัญชี, บุคลากรและผู้ใช้งาน, เชื่อมต่อ LINE, สำรองข้อมูล, ส่งรายงานอัตโนมัติ) และมีสิ่งที่ทั้งสองเจ้าไม่มีอยู่แล้วหลายกลุ่ม (POS/ร้านอาหาร, BOQ, marketplace, ชั้นต้นทุน FIFO, สินค้าชุด/BOM, เลขเครื่อง/serial, ทางลัดผู้ใช้)

**ข้อยกเว้นที่ตั้งใจไม่ทำ: ระบบเงินเดือน (payroll)** — ลุงจืดตัดสินใจ 2026-09-08 ว่า **ไม่เอาระบบเงินเดือน** ดังนั้น BC จะไม่มีโมดูลเทียบ FlowPayroll / PEAK Payroll และไม่มีแบบยื่นที่เกิดจากเงินเดือน (ภ.ง.ด.1 / ภ.ง.ด.1ก, ไฟล์นำส่งเงินสมทบประกันสังคม สปส. / กท.20 ก) — ถือเป็นความต่างที่ยอมรับแล้ว ไม่ใช่ช่องว่างที่ต้องปิด **ห้าม AI ตัวใดเพิ่มเมนูเงินเดือนกลับเข้ามาเองอีก**

**"มีเมนู" ≠ "ทำงานได้"** — เมนูส่วนใหญ่ของ BC ยังชี้ไป route ที่ยังไม่มีจอจริงใน Next (แสดงการ์ด "Flutter route เดิม" ที่ `frontend/src/app/menu/main-menu-screen.tsx:2786-2800`) เอกสารนี้พูดถึงความครบของ **แผนผังเมนู** เท่านั้น

## บทเรียน: จอกำพร้า (screen ที่ไม่มีเมนูชี้)

`onOpenRoute` (`frontend/src/app/menu/main-menu-screen.tsx:1453-1455`) เปิดแท็บได้เฉพาะ route ที่มีรายการในเมนูเท่านั้น — จอที่เขียนเสร็จแล้วแต่ไม่มีเมนู = ผู้ใช้เข้าไม่ถึง และ test ไม่จับให้ ตรวจซ้ำได้ด้วย:

```bash
# route ของจอจริง = ที่ main-menu-screen dispatch (activeTab.route === "...") + route ของ system-setting slug
grep -ohE 'activeTab\.route === "[^"]+"' frontend/src/app/menu/main-menu-screen.tsx | grep -oE '"/[^"]+"' | tr -d '"' > /tmp/screens.txt
grep -ohE '^\s*route: "[^"]+"' frontend/src/lib/system-setting-screens.ts | grep -oE '"/[^"]+"' | tr -d '"' >> /tmp/screens.txt
sort -u /tmp/screens.txt -o /tmp/screens.txt
grep -oE '"/[^"]+"' frontend/src/lib/menu-data.ts | tr -d '"' | sort -u > /tmp/menu.txt
comm -23 /tmp/screens.txt /tmp/menu.txt
```

ห้ามใช้ `grep -ohE '"/[a-z0-9/-]+"'` กวาดทั้งไฟล์ เพราะจะติด backend `basePath`/`listPath` และ `/api/*` ปนมาเป็น 63 บรรทัด ไม่ตรงกับข้อสรุปด้านล่าง

ผลตรวจ 2026-09-08 หลังต่อสาย marketplace (รันซ้ำ 2026-09-09 ได้ 17 บรรทัด): เหลือ `/currency`, `/datamodelgraph`, `/shortcuts` ที่อยู่นอกเมนูโดยตั้งใจ (workspace wizard / เครื่องมือ dev / แท็บทางลัดเต็มจอ) และ route ตั้งค่าองค์กรที่ห้ามอยู่ในเมนูหลักตามเทสต์ `has no settings section in the main menu` — ไม่มีจอกำพร้าที่ผิดพลาดเหลืออยู่
