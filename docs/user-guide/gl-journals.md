> อ้างอิงหน้าจอจริง ฉบับ 2569-09-21 · แนวคิดของระบบคือ "ห้องบัญชี" ที่ให้คนทำงานคนเดียว บันทึก ตรวจเอกสาร กระทบยอด และผ่านรายการได้ครบในที่เดียว ทุกรายการเก็บผู้ทำ+เวลา+เหตุผล ตรวจย้อนหลังได้ 100% และไม่มีการลบทับข้อมูลบัญชีเด็ดขาด

## 1. แนวคิดพื้นฐานที่ต้องรู้ก่อนใช้

| หัวข้อ | รายละเอียด |
|---|---|

| **สมุดรายวัน (เล่ม)** | UV ขายเชื่อ · SV ซื้อเชื่อ · RV รับเงิน · PV จ่ายเงิน · JV ทั่วไป · GJ · AR · AP — เพิ่ม/แก้ได้ที่จอ "กำหนดสมุดรายวัน" |

| **หลังผ่านรายการ** | แก้ไข/ลบโดยตรงไม่ได้อีก — การแก้ไขทำได้ทางเดียวคือ "สร้างรายการกลับบัญชี" พร้อมเหตุผล |
| **สิทธิ์** | ข้อมูลผูกกับสาขา — แต่ละผู้ใช้เห็นเฉพาะใบของสาขาที่ตนมีสิทธิ์ (ตรวจฝั่ง server ทุกคำขอ) |

## 2. โครงหน้าจอ

```
┌─────────────────────────────────────────────────────────┐
│ ค้นหา: [เลขที่หรือคำอธิบาย]  [ค้นหา] [โหลดใหม่] [+ เพิ่มรายการ Alt+N] │
├─────────────────────────────────────────────────────────┤
│ ตารางรายการ: สมุดรายวัน | วันที่/เลขที่ | คำอธิบาย | สถานะ | จัดการ │
│   — คลิกแถว = เปิดดูข้อมูล (โหมด Read-only สำหรับใบที่ผ่านแล้ว)     │
├─────────────────────────────────────────────────────────┤
│ ฟอร์มใบสำคัญ: หัวใบ + บรรทัดเดบิต-เครดิต + รวมเดบิต/รวมเครดิต/ผลต่าง │
│ แท็บ [ผ่านรายการและยกเลิก] ← รวม Post + Reversal ตามแบบ Champ    │
│ แผง [หลักฐาน ลูกหนี้–เจ้าหนี้ และธนาคาร] + [ผลตรวจเอกสาร]            │
└─────────────────────────────────────────────────────────┘
```

- **ช่องค้นหา** รองรับทั้งเลขที่เอกสารและคำในคำอธิบาย · ปุ่ม **โหลดใหม่** ดึงข้อมูลล่าสุดเสมอ
- **คลิกแถวในตาราง** เพื่อแสดงข้อมูล — ถ้าเป็นใบที่ผ่านรายการแล้วจะขึ้น **โหมดแสดงข้อมูล (Read-only)** พร้อมข้อความ "เอกสารนี้ผ่านรายการแล้ว ไม่สามารถแก้ไขได้โดยตรง"
- **ตรวจสอบสถานะ** — ดูสถานะปัจจุบันและ version ของใบก่อนทำงานต่อ

## 3. บันทึกรายวันใหม่ (ขั้นตอนละเอียด)

กด **+ เพิ่มรายการ** (คีย์ลัด `Alt+N`) — ปุ่มนี้มองเห็นเมื่ออยู่โหมดแก้ไข

### 3.1 หัวใบสำคัญ

| ฟิลด์ | คำอธิบาย | ตัวอย่าง |
|---|---|---|
| เลขที่เอกสาร | รหัสเรียกใบของร้านคุณ เช่น `UV6901-0001` — ต้องไม่ซ้ำ | `SV6901-0005` |
| วันที่เอกสาร | วันที่บัญชีของรายการ (YYYY-MM-DD) — ต้องอยู่ในปีบัญชีที่ยังไม่ล็อก/ปิด | `2026-01-16` |
| ปีบัญชี | ปีงบของรายการ (เช่น 2569 = 2026) | `2569` |
| สมุดรายวัน | เล่มที่ใบนี้ลง (UV/SV/RV/PV/JV…) | `UV` |
| คำอธิบายรายการ | คำอธิบายหัวใบ — ใช้ค้นหาภายหลัง | `ขายปูน+สี โครงการ A เงินเชื่อ` |
| เอกสารอ้างอิง | เลขที่เอกสารต้นทางถ้ามี | `INV-2569-0201` |
| รหัสสาขา | สาขาที่เกิดรายการ เช่น `00000` สำนักงานใหญ่ | `00000` |

### 3.2 บรรทัดรายการ (สูงสุด 500 บรรทัดต่อใบ)

แต่ละบรรทัดประกอบด้วย: **บัญชี** (เลือกจากผังบัญชี) · **คำอธิบายบรรทัด** · **เดบิต** · **เครดิต** (ใส่ด้านเดียวต่อบรรทัด) · **แผนก** · **โครงการ**

ปุ่มช่วยบนตารางบรรทัด:

| ปุ่ม | ทำอะไร |
|---|---|
| **เพิ่มบรรทัด** | เพิ่มแถวรายการ |
| **Excel Paste** (`Ctrl+V`) | วางหลายแถวจาก Excel / Google Sheets พร้อมกัน |
| **ปรับยอดให้ดุล (Auto-Balance)** | คำนวณผลต่างแล้วเติมบรรทัดปิดยอดให้เดบิต=เครดิตอัตโนมัติ |
| **+ ภาษี 7% ({ฐาน})** | คำนวณและเพิ่มบรรทัดภาษีมูลค่าเพิ่ม 7% จากฐานที่กรอกอัตโนมัติ |

แถบ **ตรวจจำนวนเงิน** ด้านล่างแสดงสด ๆ: รวมเดบิต · รวมเครดิต · ผลต่าง — สถานะจะเป็น `สมดุล 100%`, `ขาดเดบิต`, `ขาดเครดิต`, `เดบิตมากกว่าเครดิต {ยอด}` หรือ `เครดิตมากกว่าเดบิต {ยอด}`

**การตรวจภาษีมูลค่าเพิ่มอัตโนมัติ:** ระบบเทียบภาษีในเอกสารกับ 7% ของฐาน
- ตรงเป๊ะ → แจ้ง "ตรวจสอบภาษีมูลค่าเพิ่ม 7%: ยอด {0} ตรงตามฐานคำนวณเป๊ะ" พร้อมปุ่ม **ปรับเป็น 7% พอดี** ถ้าเอนไปเสี้ยว
- ต่างเป็นสตางค์ → แจ้งว่า "ต่างจาก 7% คำนวณปกติ {1} อยู่ {2} สตางค์ — สรรพากรยอมรับได้ตามใบกำกับภาษีจริง"
- ต่างมาก → เตือน "ภาษีมูลค่าเพิ่มในเอกสาร {0} ต่างจาก 7% ของฐานภาษี ({1}) โปรดตรวจสอบ"

## 5. ผ่านรายการ (Post)

1. เปิดใบร่าง → แท็บ **ผ่านรายการและยกเลิก** → **ผ่านรายการ**
2. กรอก **เหตุผล** (บังคับ) → ยืนยัน
3. ระบบแจ้ง "ผ่านรายการแล้ว" และเตือนชัดเจน: **"หลังผ่านรายการจะไม่สามารถแก้ไขหรือลบได้ การแก้ไขต้องสร้างรายการกลับบัญชีพร้อมเหตุผล"**

ระบบจะ**ปฏิเสธอัตโนมัติ**เมื่อ: วันที่ร่วงงวดที่ถูกล็อก · ปีบัญชีปิดแล้ว · บัญชีถูกปิดใช้งาน · สาขาไม่ตรงสิทธิ์ · version ไม่ตรง (มีคนแก้ก่อนหน้า — ให้กดโหลดใหม่แล้วทำซ้ำ)

## 6. สร้างรายการกลับบัญชี (Reversal) — ยกเลิกใบที่ผ่านแล้ว

ใช้เมื่อคีย์ผิด / จ่ายซ้ำ / ลูกค้าคืนสินค้า หลังใบผ่านรายการแล้ว:

1. เปิดใบที่ผ่านแล้ว → แท็บ **ผ่านรายการและยกเลิก** → **สร้างรายการกลับบัญชี**
2. กรอกให้ครบทั้งสามช่อง (บังคับ): **เลขที่ใบกลับรายการ** · **วันที่กลับรายการ** · **เหตุผล**
3. ระบบสร้างใบใหม่ "กลับเดบิตและเครดิตของใบเดิม" โดย **เก็บรายการเดิมไว้ครบ** — ใบเดิมสถานะเปลี่ยนเป็น "ผ่านรายการแล้ว (ขอยกเลิก)" ใบกลับเป็นร่างให้ตรวจและผ่านรายการต่อ

> สาเหตุยอดไม่ลดทันทีหลังกลับบัญชี: ใบกลับยังเป็นฉบับร่าง — ต้องผ่านรายการใบกลับด้วยจึงมีผลในรายงาน (กติกา "ทุกอย่างผ่านการตรวจก่อนเสมอ")

## 7. หลักฐานลูกหนี้–เจ้าหนี้–ธนาคาร (แผงรายละเอียดใบสำคัญ)

แผง **"หลักฐาน ลูกหนี้–เจ้าหนี้ และธนาคาร"** อยู่ในฟอร์มใบสำคัญ มี **9 หมวด** — ขณะเป็นร่างบันทึกได้พร้อมใบในครั้งเดียว ส่วนใบที่ผ่านรายการแล้วเพิ่มได้เฉพาะหมวดยอดกระทบยอด (จัดสรร / Statement / ตัดยอด / จับคู่ / ถอน) ผ่านโหมด "เพิ่มผลกระทบยอด"

### 7.1 ลูกหนี้–เจ้าหนี้ / เอกสารค้าง (documents)

| ฟิลด์ | ค่าที่ใส่ |
|---|---|
| ประเภทบัญชี | `ลูกหนี้ (ar)` หรือ `เจ้าหนี้ (ap)` |
| คู่ค้า | เลือกจากรายการ (กรองตามประเภทบัญชีอัตโนมัติ) |
| เลขเอกสาร · วันที่เอกสาร · วันครบกำหนด | ของใบกำกับ/ใบเจ้าหนี้จริง |
| ประเภทเอกสาร | `1 ตั้งหนี้` · `2 ผลชำระที่เกิดแล้ว` · `3 เพิ่มหนี้` · `4 ลดหนี้` · `5 ยอดยกมา` |
| ด้านหนี้ | `1 เพิ่มหนี้` / `2 ลดหนี้` (ผูกกับประเภทเอกสารอัตโนมัติ) |
| ยอดจัดสรร/จำนวนเงิน · บัญชีคุม · สาขา | ยอดเอกสาร + บัญชีคุม (เช่น 1131 ลูกหนี้/2111 เจ้าหนี้) |

### 7.2 จัดสรรบรรทัดบัญชีกับเอกสาร (allocations)

โยงยอดเอกสารเข้า **บรรทัดบัญชีคุม** ของใบ: เลือก **เอกสารที่จัดสรร** → เลือก **บรรทัดบัญชี** (ระบบแสดงเลขบรรทัด+บัญชี+ยอดให้เลือก) → ใส่ **ยอดจัดสรร** จัดสรรบางส่วน/หลายเอกสาร/หลายบรรทัดได้

### 7.3 ตัดยอดหลายบิล / ชำระบางส่วน (settlements)

บันทึก "ผลการชำระที่เกิดแล้ว": เลือก **บิลเพิ่มหนี้** (ฝั่งเพิ่มหนี้) → เลือก **เอกสารลดหนี้ / ผลชำระ** (ฝั่งลดหนี้ — กรองคู่ค้าให้ตรงกันอัตโนมัติ) → **วันที่ตัดยอด** → **ยอด** — หนึ่งบิลตัดหลายครั้งบางส่วนได้ ระบบตรวจยอดทั้งสองฝั่งในคำสั่งเดียว กันตัดเกินยอด

### 7.4 บัญชีธนาคารของบรรทัด GL (bank_lines)

ระบุว่าบรรทัดไหนเป็นเงินฝากธนาคาร: เลือก **บรรทัดบัญชี** → **บัญชีธนาคาร** → **ทิศทาง** (`เงินเข้า` / `เงินออก`) — ใช้เป็นคู่จับคู่กับ Statement ภายหลัง

### 7.5 หลักฐาน Statement ธนาคาร (statement_lines)

หลักฐานจากสมุดบัญชีธนาคารจริง: **เลือกบัญชีสำหรับนำเข้า** → นำเข้า CSV หรือกรอกทีละแถว (รหัสรายการจากธนาคาร, วันที่ธนาคาร, วันที่มีผล, เลขอ้างอิงธนาคาร, รายละเอียด, ทิศทาง, ยอด)

- รูปแบบ CSV: `transaction_date,direction,amount,bank_reference,description` — วันที่ `YYYY-MM-DD`, direction `1 เข้า / 2 ออก`
- มีปุ่ม **ดาวน์โหลดหัวตาราง CSV** ให้ใช้เป็นแม่แบบ
- ไฟล์ไม่เกิน **2 MB / 1,000 แถว** · นำเข้าไฟล์เดิมซ้ำ **ไม่เพิ่มรายการซ้ำ** (ระบบใช้รหัสรายการจากธนาคาร dedup ให้)

### 7.6 จับคู่บัญชีกับ Statement (matches)

เลือก **รายการ Statement** → เลือก **รายการบัญชีธนาคารที่จะจับคู่** → **ยอด** — จับคู่ยอดหลายต่อหลายได้ ระบบตรวจยอดคงเหลือทั้งสองฝั่ง

ปุ่มดูยอดรอจัดการด้านบนแผง: **ดูเอกสารและยอดค้าง** · **ดู Statement คงเหลือ** · **ดูบัญชีธนาคารรอจับคู่** — หน้าต่างเลือกมีช่อง **"ยอดคงเหลือ ณ วันที่"** ให้ดูยอดย้อนตามวันที่ + ค้นหา + แบ่งหน้า 30 แถว

### 7.7 ถอนรายการที่ยืนยันแล้ว (withdrawals)

หลังผ่านรายการแล้วต้องการเปลี่ยนคู่จัดสรร/ตัดยอด/จับคู่: เลือก **ประเภทการถอน** (`จัดสรรเอกสาร` / `ตัดชำระ` / `จับคู่ธนาคาร`) → เลือก **รายการเดิมที่จะถอน** → **เหตุผลการถอน** — ระบบบังคับ "ถอนและจัดสรรใหม่ในครั้งเดียว ยอด GL เดิมไม่เปลี่ยน" และจะเพิ่ม revision ให้ทุกใบที่กระทบ พร้อมให้ตรวจผลตรวจเอกสารใหม่

### 7.8 เพิ่มคู่ค้า / เพิ่มบัญชีธนาคาร (partners, bank_accounts)

สร้างข้อมูลหลักใหม่ได้จากในจอเดียวกัน ไม่ต้องออกไปหน้าอื่น:

- **คู่ค้า:** รหัสคู่ค้า, ชื่อคู่ค้า, เลขผู้เสียภาษี, สาขาภาษี, ที่อยู่, ติ๊ก `ลูกหนี้` และ/หรือ `เจ้าหนี้`
- **บัญชีธนาคาร:** รหัสบัญชีธนาคาร, ธนาคาร, เลขบัญชี, ชื่อบัญชี, **บัญชี GL ธนาคาร** (บัญชีเงินฝากที่โยงกับผังบัญชี)

---

## 8. กระทบยอดใบที่ผ่านรายการแล้ว (Reconcile)

เมื่อใบสถานะ "ผ่านรายการแล้ว" ปุ่ม **เพิ่มผลกระทบยอด** จะเปิดโหมดบันทึกหลักฐานเพิ่ม:

1. กด **เพิ่มผลกระทบยอด** → เพิ่ม จัดสรร / Statement / ตัดยอด / จับคู่ / ถอน ได้ตาม §7
2. กด **บันทึกผลกระทบยอด** (`Ctrl+S`) — ระบบแจ้ง "บันทึกผลกระทบยอดแล้ว กรุณาตรวจผลตรวจเอกสารอีกครั้ง"
3. **ยอดเดบิต-เครดิตของ GL เดิมจะไม่เปลี่ยน** — งานนี้คือการบันทึกผลรับจ่ายที่เกิดจริงเท่านั้น ไม่ใช่คำสั่งโอนเงิน

## 9. ผลตรวจเอกสาร (Review)

ทุกครั้งที่บันทึกผลกระทบยอด ระบบสร้าง "ผลตรวจ" ผูกกับ version ของใบ — แผงผลตรวจด้านล่างฟอร์มแสดงประวัติใครตรวจเมื่อไหร่ ผลเป็นอย่างไร ใช้เป็นหลักฐานความเรียบร้อยของเอกสารก่อนนำยอดไปใช้

## 11. ข้อความที่พบบ่อย และวิธีจัดการ

| ข้อความ | หมายความ / วิธีทำ |
|---|---|
| "ขาดเดบิต / ขาดเครดิต / ผลต่าง" | ใบยังไม่สมดุล — ใช้ปุ่ม **ปรับยอดให้ดุล (Auto-Balance)** หรือแก้ยอดเอง |
| "ภาษีมูลค่าเพิ่มในเอกสาร … ต่างจาก 7% ของฐานภาษี โปรดตรวจสอบ" | ยอดภาษีเบี่ยงจาก 7% มาก — ตรวจใบกำกับจริงก่อนบันทึก (ต่างเป็นสตางค์สรรพากรยอมรับได้) |
| "เอกสารนี้ผ่านรายการแล้ว ไม่สามารถแก้ไขได้โดยตรง" | ใช้ **สร้างรายการกลับบัญชี** แทนการแก้ |
| "กรุณาระบุเหตุผลก่อนทำรายการ" | ผ่านรายการ/กลับรายการ/ลบร่าง/ถอนรายการ ต้องใส่เหตุผลเสมอ |
| "บันทึกฉบับร่างแล้ว กำลังปรับปรุงข้อมูลสำหรับรายงาน" | projection กำลังเดิน — รายงานจะอัปเดตตามในอีกไม่กี่วินาที |
| "รายการนี้เปลี่ยนไปแล้ว กรุณาโหลดข้อมูลล่าสุดก่อนบันทึก" | มีคน/เซสชันอื่นแก้ก่อน — กด **โหลดใหม่** แล้วทำซ้ำ (ระบบกันเหยียบกันด้วย version) |
| "ใบสำคัญที่นำเข้า Statement แล้วไม่สามารถเปลี่ยนสาขา" | ใบที่ผูกหลักฐานธนาคารห้ามย้ายสาขา — ให้กลับรายการแล้วทำใบใหม่ที่สาขาถูกต้อง |
| กลับบัญชีแล้วยอดในรายงานยังไม่ลด | ใบกลับยังเป็นร่าง — ผ่านรายการใบกลับด้วย |

## 13. เงื่อนไขที่ระบบบังคับ (สรุปสำหรับตรวจสอบ)

- สกุลเงิน **THB** เท่านั้น · ทศนิยมตามปีบัญชี (ค่าเริ่มต้น 2 ตำแหน่ง) · ตัวเลขเป็น exact decimal ห้าม float
- ใบสำคัญสูงสุด **500 บรรทัด** · หลักฐานรวมไม่เกิน **2,000 รายการ/คำขอ** · ไฟล์ Statement ไม่เกิน **2 MB / 1,000 แถว**
- ข้อมูลผูก **สาขา** — อ่าน/แก้จำกัดตามสาขาที่มีสิทธิ์, งานประมวลผลระดับบริษัท (ปิดงวด/คำนวณใหม่) ต้องสิทธิ์ครอบทุกสาขา
- บัญชีคุมของเอกสารต้องเป็นบัญชี **ลงรายการได้ + active** (ลูกหนี้=asset, เจ้าหนี้=liability)
- ทุกคำขอมี requestid กันบันทึกซ้ำจากการกดเบิ้ล — กดสองครั้งระบบคืนใบเดิมให้เสมอ
