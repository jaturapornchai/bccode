# ร่างโครงสร้างภาษีประกอบ GL

ลุงจืดอนุมัติให้ AI เพิ่มร่างในโฟลเดอร์นี้เฉพาะงานวันที่ 2026-09-20 เพื่อแก้ต่อ ยังไม่ใช่ migration หรือการรับรองว่ารองรับทุกแบบภาษี

## ขอบเขตและลำดับ

ไฟล์ SQL ที่กล่าวถึงอยู่ใน `../../datamodels/gl/` ส่วนเอกสาร Markdown อยู่ใน `mydocs/specs/gl/`

คงไฟล์ GL เดิมทั้ง 4 ไฟล์ เพิ่ม `vat.sql` และ `wht.sql` หลัง `gltrans.sql` เท่านั้น ไม่รวม RD Prep/XBRL และไม่เปลี่ยนฐานข้อมูลจริง

VAT ผูกหัวใบสำคัญ มีเลขลำดับของตัวเอง ไม่บังคับหนึ่งต่อหนึ่งกับบรรทัดบัญชี ส่วน WHT แยกหัวหนังสือรับรองกับรายการเงินได้ เพื่อไม่ซ้ำข้อมูลชื่อ/ที่อยู่ทุกบรรทัด ชื่อและที่อยู่เป็น snapshot ณ วันออกเอกสาร

ต้นแบบที่ตรวจ: `D:/project-champ/champ-report/BC5REP_GLFS/GLRepInputTaxView.cpp` มี BeforeTaxAmount, ZeroTaxAmount, ExceptTaxAmount จึงแยกฐานปกติ/0%/ยกเว้น ไม่ใช้ float ตามต้นแบบ

## ข้อเสนอที่ลุงจืดแก้ต่อได้

- ร่างเงินภาษีเป็น THB, NUMERIC(16,2), อัตรา NUMERIC(5,2) ต่างจาก GL เดิมที่เป็น NUMERIC ไม่กำหนด scale ต้องยืนยันนโยบายทศนิยมก่อนพัฒนา
- นโยบายเสนอสำหรับค่าคำนวณ: decimal ROUND_HALF_UP ที่ 2 ตำแหน่งเมื่อจบรายการ เก็บยอดตามเอกสารต้นฉบับและตรวจส่วนต่างก่อนผ่านรายการ ไม่ปัดซ้ำจากยอดที่จัดรูปแบบ ห้ามปล่อยให้ SQL ปัด input เกิน scale โดยไม่ตรวจใน Backend
- ไม่กำหนดค่าเริ่มต้น 7%/3% อัตราต้องตรวจตามประเภทรายการและวันที่มีผล
- ภาษีซื้อแยกใช้สิทธิ/ต้องห้าม/รอ/ไม่ใช้สิทธิ; เหตุผลและเงื่อนไขทางกฎหมายต้องตรวจใน Backend ไม่ใช้เพียงช่วงจำนวนเดือนใน CHECK
- ใบลดหนี้ VAT เก็บยอดบวกและให้ประเภทรายการกำหนดการหักยอดในรายงาน แยกจากการกลับรายการ GL; ต้องทดสอบไม่ให้กลับเครื่องหมายสองครั้ง
- WHT เก็บ payer และ payee ชัดเจนทั้งสองทิศทาง รหัส condition_type เป็นรหัสภายในตาม handoff ต้อง mapping กับแบบพิมพ์จริงก่อนใช้งาน
- เลขผู้เสียภาษีตรวจรูปแบบใน SQL เท่านั้น ยังไม่ตรวจ checksum/ข้อยกเว้นบุคคลต่างประเทศ ร่าง WHT นี้ยังไม่ครอบคลุมผู้รับที่ไม่มีเลขไทย

## ข้อกำหนด Backend ที่ DDL นี้ยังไม่ได้บังคับ

- ยึดสถานะหัว journal_entries ไม่ทำสำเนา status/posted ในตารางภาษี; รายงานใช้เฉพาะเอกสารที่ผ่านรายการและจัดการเอกสารกลับรายการให้ถูกต้อง
- RESTRICT ป้องกันลบหัวแล้วข้อมูลภาษีหายตาม แต่ไม่ได้ป้องกัน UPDATE/DELETE โดยตรง ต้องมีสิทธิ์และกฎห้ามแก้/ลบหลังผ่านรายการ พร้อม reversal และ audit trail
- การลบร่างต้องลบลูกก่อนหัวภายใน transaction; การบันทึกทุกส่วนต้องใช้ PostgreSQL transaction เดียวผ่าน Go sql.Tx ไม่ใช้ MongoDB, ClickHouse, Kafka หรือ Redis
- ตรวจบริษัท/สาขา สิทธิ์ผู้ใช้ งวดเปิด ความสัมพันธ์ยอดภาษีกับ GL และเดบิต=เครดิตก่อนผ่านรายการ
- WHT ต้องมีรายละเอียดอย่างน้อยหนึ่งแถว ตรวจวันจ่ายกับงวดนำส่ง และตัวตนบริษัทตามทิศทางก่อนออกหนังสือรับรอง
- idempotency, การตรวจใบกำกับ/หนังสือรับรองซ้ำ และการแก้รายการพร้อมกัน ต้องทำใน service; index ที่เพิ่มไม่ใช่ UNIQUE ทางธุรกิจ
- updated_at ต้องอัปเดตโดย service; เก็บ timestamp ด้วย CURRENT_TIMESTAMP ให้ TIMESTAMPTZ เก็บ instant ถูกต้อง
- ทดสอบ decimal 0.1+0.2, ขอบเขตปัดเศษ, API/DB round-trip, ส่งซ้ำ และยอดรายงานตรงต้นทางก่อนใช้งาน

## แหล่งตรวจต่อ

- ภาษีซื้อเลื่อนงวด: https://www.rd.go.th/3417.html (ประกาศ VAT ฉบับที่ 4 อ้างมาตรา 82/3)
- ร่างนี้ไม่อ้างว่าตาราง/constraint อย่างเดียวทำให้รายงานถูกต้องตามกฎหมายครบถ้วน


## บทบาทในห้องบัญชี

VAT/WHT เป็นรายละเอียดประกอบใบสำคัญสำหรับตรวจหลักฐานและกระทบยอดภาษี ไม่ใช่ workflow ขาย ซื้อ หรือจ่ายเงิน ไม่คำนวณเงินเดือน แม้รับข้อมูลภาษีจากระบบภายนอกได้ ผลตรวจใช้ journal_review_events ของ revision ปัจจุบันตาม [spec.md](spec.md) และแก้รายละเอียดภาษีแล้วต้องตรวจใหม่
