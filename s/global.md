### BC Ai Account

## ภาพรวม

# กฏ
- สามารถเพิ่มลบแก้ไข DataModel ของ MongoDB,PgSql,ClickHouse ได้ ทั้งหมด เพราะกำลัง DEV
- ใน MongoDB จะต้องมี guidfixed ทุก collection guidfixed จะถูกสร้างขึ้นครั้งเดียว (ครั้งแรกตอนเพิ่ม) ตอนสร้างข้อมูล แล้วใช้ทั้งระบบ แต่ guidfixed ห้ามเอาไปอ้างอิงแบบ releation ให้ใช้ รหัส (code) หรืออื่นๆ ในการอ้างอิง เพราะมีการย้ายข้อมูล หรือ sync ข้อมูลจะได้ไม่มีปัญหา
- holding เป็นกลุ่มกิจการ ภายในมีหลายบริษัท แต่ master สินค้า,ลูกหนี้,ลูกค้า,เจ้าหนี้ รวมกันได้ โดยมีให้เลือกว่า บริษัทไหนใช้ได้บ้าง เพื่อให้ข้อมูลวิเคราะห์ภาพรวมได้ และลดการจัดการข้อมูล ไม่ต้องทำงานซ้ำซ้อน
- master สินค้า code ห้ามซ้ำ
- barcode ซ้ำได้ แต่ห้ามซ้ำ (code+barcode) เพราะใช้ code + barcode เป็นสินค้า แต่มีหลาย barcode ได้
- สามารถสร้าง barcode เพื่อขายสินค้าก่อนได้ แล้วค่อยมาสร้าง master สินค้าเชื่อมกับ barcode อีกครั้ง เพราะธุรกิจค้าปลีกในไทย มั่ว

# กฏ การทำงาน ของระบบ
- BackEnd (golang) ให้ Backend เป็นตัวทำงานทั้งหมด เพราะอนาคตจะได้ใช้ MCP ได้
- FrontEnd (Next.js) มีไว้เพื่อทำงานทั่วไป การคำนวณทั้งหมด ให้ Backend เป็นคนจัดการ
- MongoDB (NoSQL) เก็บข้อมูลทั้งหมด ซึ่งเป็นข้อมูลดิบ 
- PgSql เป็น Releation Database สามารถลบทิ้งและ Build ใหม่ได้ โดยเอาข้อมูลจาก Mongodb ซึ่งเป็นข้อมูลดิบ 
- ClickHouse เป็น Dimention Database สามารถลบทิ้งและ Build ใหม่ได้ โดยเอาข้อมูลจาก Mongodb ซึ่งเป็นข้อมูลดิบ
- Kafka เป็นตัวเชื่อมระหว่าง Mongodb -> PgSql -> ClickHouse หลังจาก Mongodb บันทึก, แก้ไข, ลบ สำเร็จ Kafka จะส่งต่อให้กับ Api เพื่อ Update PgSql, ClickHouse ให้ข้อมูลตรงกันเสมอ
